## 2 记录原则

1. **只记真实发生的事。** 每一项都要能指到仓库里的文件、命令或输出。没有执行过的测试、覆盖率、压测一律写「未执行」。
2. **修正案例必须写出「怎么发现的」。** 只写「AI 写错了、人改对了」没有价值；要写出发现它的那条断言、那次运行、那个数字。
3. **包含对 AI 不利的记录。** 能力边界与失效模式只写优点等于没写。[审查记录](审查记录-AI审查与人工审查对比.md) 里「9 个真实缺陷中 AI 审查独立发现 0 个」就是这条原则的产物。
4. **不写无法核对的数量。** 「使用 N 次」这类没有埋点的数字不写；有提交与文件可核对的产出才登记。
5. **未达项与已达项分开写。** 覆盖率 8 个受门禁包全部 ≥80% 是事实；`query/discovery` 未纳入门禁、实测 13.50% 也是事实，两者必须同时出现。
6. 时间以报告日期为准，均来自本仓库现有提交与运行记录。
