## 3. 三项「先失败后修复」的真红证据

本批次按「先写能在当前缺陷下失败的测试，再修实现」执行。三处均保留了失败原文与修复后的通过结果。

### 3.1 T25 同 DOI 证据矛盾被无条件采信

- 测试：`SourceEvidenceConflictIT.sameDoiWithContradictingEvidenceGoesToGovernance`
- 输入：来源 A 入库 DOI `10.5555/IT.EVIDENCE.CONFLICT`（题名「基于图神经网络的学术合作发现方法」，2021，作者张三/李四，引用量 12）；来源 B 同 DOI，题名「城市轨道交通信号系统可靠性分析」，2019，作者王五/赵六，引用量 999。
- 修复前实测：`[同 DOI 但题名／年份／作者矛盾时必须登记治理冲突] Expected size: 1 but was: 0 in: []`，同时日志显示 `已按来源新版本刷新指标 … citationCount=999`——即 B 的引用量被写到 A 上。
- 修复内容：`SourceIntakeService` 在「稳定标识命中既有实体」分支新增 `reportEvidenceConflicts`，按类型、年份、作者完全不相交、题名相似度低于既有候选阈值四项取证，登记 `METADATA_CONFLICT` 异常，并且**不采用**矛盾字段、**不刷新**指标。
- 修复后实测：4 项全通过；异常证据里逐项写明 `conflictingFields`，成果题名与年份仍是首次入库原值，`citation_count` 仍为 12。

### 3.2 T28 来源新值静默消失

- 测试：`SourceEvidenceConflictIT.reviewedTitleSurvivesLaterSourceUpdate`
- 输入：题名 A 入库 → 模拟人工审核改为 B（`core_achievement.title` + `core_field_provenance` 置 `REVIEWED`）→ 同 DOI 再导入题名 C。
- 修复前实测：`[来源新值与人工值冲突必须登记] Expected size: 1 but was: 0`。人工值没被覆盖（既有 SQL 保护生效），但来源新值 C 除了落在原始报文里，**没有任何可裁决记录**。
- 修复后实测：题名仍是 B；溯源等级仍是 `REVIEWED`；异常证据含 `canonicalTitle=B`、`incomingTitle=C`、`manualProtected=true`、`titleValueLevel=REVIEWED`、`sourceRecordRef`。

### 3.3 T27 并发首次导入撞唯一约束

- 测试：`SourceEvidenceConflictIT.concurrentFirstImportDoesNotDuplicateEntity`
- 做法：一个事务按服务协议持事务级咨询锁并保持未提交，另一线程同时导入同一 DOI 的另一来源。
- 修复前实测：竞争者未返回接收结果（在 `insertIfAbsent` 之后撞 `uk_core_paper_doi_norm`，整批回滚），断言失败。
- 修复内容：`AchievementMapper.lockStableIdentifier`（`pg_advisory_xact_lock(hashtextextended(标识种类:归一值, 0))`）在「查标识 → 建实体」之间加互斥，键含标识种类，锁随事务结束释放。
- 修复后实测：竞争回执 `ATTACHED`，实体 1 条、论文扩展 1 行、标识注册 1 行、来源归属 2 条。

## 6. 本轮发现但未修的缺口

1. **许可与公开未联动**：`license_scope` 只登记与展示，公开资格由 `AutoPublishPolicy` 单独判定，两者之间没有约束。补齐需先定许可策略。详见《来源许可与字段白名单说明》§1。
2. **人工修订成果字段的接口不存在**：审核侧改题名只能落到库表与溯源，没有对外 API。T28 的测试因此直接用溯源写入＋改标题来模拟审核结果。这是功能缺口，不是测试取巧。
3. **参与角色恒为 AUTHOR**：贡献挂接统一写 `AUTHOR`，项目负责人（`LEADER`）、获奖者（`AWARDEE`）、发明人（`INVENTOR`）虽在库约束里允许，但来源映射未定义。T28 的「参与角色正确」因此无法通过。
4. **网络逐跳证据**：`AC-IMPL-IN01-01` 要求每跳给出论文 ID 与标题，当前路径 DTO 的逐跳证据未在本批次核对。
5. **前端无测试基础设施**：`frontend/package.json` 没有 test 脚本，本批次用 `puppeteer-core` 直接跑脚本，未引入组件测试框架。若要长期维护，需先评审是否引入。
