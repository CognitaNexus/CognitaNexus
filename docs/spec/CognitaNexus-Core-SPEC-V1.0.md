## 4. 数据清洗规范（FR09）

### 4.1 目标、输入、前置条件和输出

输入为符合来源接入许可的 SourceRecord、来源字段映射及当前机构/领域分类表；前置条件为来源声明、类型可识别和本次批次具备可定位的到达标识。输出为 CleanRecord、字段级原值与规范值、状态/原因清单及事件；清洗成功不等于去重成功或公开授权。

### 4.3 算法步骤与伪代码

```text
CLEAN(record, maps):
  if source identity missing or type unsupported or normalized_name empty:
      return Exception(reason, raw=record)
  out = new CleanRecord(rawRef=record, dataOrigin=record.origin)
  for field in record.fields: out.add(rawValue, normalizationRule, mappedValue, evidence)
  for identifier: validate using its OWN type and jurisdiction; never convert guessed IDs
  for date: parse only unambiguous format; attach event type and precision
  if invalid date/identifier: return Exception(with unchanged raw evidence)
  if ambiguous date, future suspicious date, multiple incompatible identifiers:
      return PendingVerification(out, reasons)
  return Valid(out)
```

## 5. 成果去重算法（FR09）

### 5.1 目标、输入、输出与前置条件

输入是已完成 CL 清洗的规范来源记录、成果实体索引、版本映射及归并历史；输出为 `命中实体/新建实体/疑似重复待核验/确定不同`、候选及证据、版本关系、出处映射和审计事件。先验证来源记录身份、类型和标识合法性，再判定是否自动连接；异常记录不得绕开清洗产生公共实体。

### 5.2 判定顺序及规则

| 编号 | 判定依据、顺序及可见结果 | 性质 |
| --- | --- | --- |
| DD-01 | 先按 `source_id + source_record_key` 做幂等事件定位；完全重复无新实体、无重复出处 | 继承 S10 |
| DD-02 | 类型优先隔离：跨成果类型不自动合并；同记录同体系标识非法/冲突先待核验 | 继承 S03/S06 |
| DD-03 | 对 `(标识体系,辖区/命名空间,规范键)` 精确查找；只命中一个一致类型实体且无矛盾证据可自动映射 | 继承 S06；冲突优先级待评审 |
| DD-04 | 同一稳定标识命中两个历史实体，禁止任选；列两个候选待核验 | 继承 S06 |
| DD-05 | 无有效稳定键或无命中时，以同类型、标题比对键及合理年份窗口召回，再核对作者/发明人/机构等 | 继承 S07；召回窗口待评审 |
| DD-06 | 无标识且类型、标题规范键、发生年份、参与者集合均一致，且没有强冲突时可按 FR09-S07-02 自动合并，四项证据留痕 | 继承 S07 |
| DD-07 | 只有标题近似、年份冲突或主要参与人矛盾时不可自动合并；疑似者入人工核验，明确无候选时可新建 | 继承 S07 |
| DD-08 | 预印本/正式发表存在来源明确版本指向时归入一成果的版本清单；无明示关系保持独立并标疑似 | 继承 S08 |
| DD-09 | 合并保留所有唯一出处和版本、旧 ID 可溯源重定向；禁止循环合并和部分成功 | 继承 S09 |

| DD-11 | 成果数量 `distinct(生效WorkEntity canonical_id)`，出处数量 `distinct(source_id, source_record_key)`；重复到达事件单独计数 | 继承 S06/S10 与 BR-511／BR-516 |

### 5.3 无稳定标识的推荐证据模型（待联合评审，不生效）

推荐采用两级判定：第一层高召回（同类型+规范标题/标题 n-gram+时间范围）；第二层规则证据（标题 T、参与人 P、发生年份 Y、机构 O、载体 V），但保留强冲突否决（成果类型冲突、可靠稳定标识指向互斥实体、证据确认的不同人员）。可以在标注集合上探索 `score = 0.35T + 0.30P + 0.20Y + 0.10O + 0.05V`、候选阈值 `0.75`、自动阈值 `0.95`；**这些数字仅用于离线参数敏感性试验，绝非既定合并条件，也不能覆盖 DD-06 的四证据要求**。项目/获奖的姓名和编号质量不同，应分类型验证而非直接复用权重。评估 precision、false merge rate、recall、人工负担；优先约束误合并，不用标题近似越过硬条件。

### 5.4 伪代码

```text
DEDUP(c):
  require c.status == Valid
  if sameSourceLogicalRecordSeen(c): return UpdateArrivalAndChangesWithoutDuplicate()
  if incompatibleTypeOrIdentifierConflict(c): return Pending(c, "type/id conflict")
  hits = exactStableIdentifierLookup(c)
  if count(hits)>1: return Pending(c, "multiple canonical targets")
  if count(hits)==1 and noConfirmedContradiction(c,hits[0]):
      return LinkSourceAndRetainAllEvidence(hits[0])
  candidates = retrieveSameTypeByTitleAndTime(c)
  for e in candidates:
      if verifiedExplicitVersionLink(c,e): return AddVersionToEntity(e)
      if noStableIdentifier(c) and exactTitleKey(c,e) and sameYear(c,e)
         and sameParticipantSet(c,e) and sameType(c,e) and noConflict(c,e):
           return MergeOrLinkWithEvidence(e)
  if candidates contain plausibleMatches: return Pending(c,candidates,reasons)
  return CreateNewCanonicalEntity(c, basis="no matched candidate")
```

### 5.5 并发、错误、版本与复算边界

在相同来源记录重复导入、两个重叠增量窗口或处理重试时，唯一逻辑出处保持一条，重复到达事件可多条；归并与来源映射应表现为全有或全无的生效结果；待审核未决时不猜测归并。版本关联既不能使有效作品被双计，也不能在无明示证据时静默压缩实体数。来源撤稿只影响相应版本/证据，不自动删除未撤回的正式版；误归并纠正需保留原决议链、重新计算受影响统计/检索/作者关系，不得按新结论修改历史原始证据。

### 7.3 推荐排序算法与候选参数（待联合评审）

建议分阶段：合法性校验 → 数据快照 → 可公开对象过滤 → 关键词召回 → 组合筛选 → 相关度分层 → 全序比较 → 分页。匹配层级为 exact title / exact other allowed field / fuzzy；候选分数 `0.6*title_match + 0.2*person_match + 0.1*field_match + 0.1*freshness`（每分量 0～1），全部权重 **待评审**；只用于制定可复算测试集合，不得声称 V1.9 既定。空摘要不填 0 分等价于“内容不相关”，而是仅不贡献该字段项；是否重归一权重须评审。时间排序建议 `time known first → time desc/asc → normalized title → canonical_id`；相关度同分建议 `match tier → total score desc → canonical time desc when comparable → normalized title asc → canonical_id asc`。当时间的事件语义不同或不可信时只用确定的后续键打破平局。

### 7.4 排序伪代码与一致性论证

```text
SEARCH(q, filter, sort, scope, permission, snapshot, rulesVersion):
  validateScopeAndFiltersOrReturnInvalid()
  candidates = getEntitiesAt(snapshot,scope)
  candidates = filterPublic(candidates,permission)
  matches = applyApprovedKeywordRules(candidates,q)
  matches = applyConjunctiveFilters(matches,filter)
  if queryFailed: return QueryFailed(not EmptyResult)
  keys = approvedSortKeys(matches,sort,rulesVersion)
  sortByTotalOrder(keys + [canonical_id ASC])
  return pageByStableCursorOrFrozenSnapshot(matches, snapshot, rulesVersion)
```

**可复核性原因：** 固定数据快照、权限、过滤词法、规则版本和分数算法的情况下，每个实体有确定匹配级别与排序键；最后用唯一 canonical_id 形成全序，所以并列记录的顺序不取决于输入扫描顺序。分页使用同一快照/游标才不会被中途新增记录插队。不同快照不能承诺完全相同结果；更新生效期限与 NF05 的 `60 秒` 均属待评审目标。NF02 的 `P95≤2 秒` 也是待评审目标，本文没有压测证据。
