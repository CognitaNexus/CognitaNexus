# CognitaNexus × OvO 软件工程可行性与需求收敛评审（2026-10-12）

**状态：工程实施口径建议 / Review Candidate（非两组签认、非 Frozen）。** 评审对象：CognitaNexus 2026-10-12 合并 V1.0 版与 OvO V0.3；上位依据为 [V1.9](../../requirements/学术成果分享平台需求分析与可行性报告.md)。**“精简”不得删除 V1.9 的 FR01～FR16、NF01～NF08 或至少一项创新。**

## 1. 评审结论

- CognitaNexus 第一组六人 SRS 优点：四类成果治理、学者证据、状态、来源完整，SPEC 与 PlantUML 相对完善；缺点：179 个子需求、445 个 AC 已明显超出普通课程小组的可管理粒度，较多规则仍在等参数冻结。
- OvO V0.3 优点：124 条较集中的子需求、287 个 AC、15 个用例和横切状态矩阵，较适合写执行链路；缺点：FR12 强制仅论文，与组一方案 A 不同，部分数值直接被细化为指标、附件与演示功能要求增加实现压力；自身 UML 和核心 SPEC 不是完整交付。
- 前一版把大量 OvO AC 追加进 514 页共同 Word，**是信息汇编不是充分的工程范围收敛**。本轮依据“课程优先—风险最小—测试可复核”建立统一实施版，不再把原 445 + 260 个候选 AC 当作必须实现 705 个独立功能。

## 3. 时间与人员可行性

项目基线原有**六人、约十五周、每周6–8小时**的资源假设，对应总投入约 **540–720 人时**，不是已经确认的真实工时。另一组为 SRS 协作输入，不应默认为额外可投入同等开发工时。以下为**工程规划估算，非已实施记录**：

| 工作包 | 估计人时 | 可复核交付 |
|---|---:|---|
| 需求/SPEC收敛、图源同步与评审 | 35–50 | 统一需求主稿、样例、追踪 |
| 四类数据字段与2个来源的采集、增量、异常 | 85–110 | 固定样例/日志/重试与增量 |
| 清洗去重、身份/关系核验、治理审计 | 110–150 | 同名不同人、同一成果多源、可回溯 |
| 检索、门户、账号、认领与纠错 | 105–140 | 用户主链路、状态与权限 |
| 统计、合作图、最短路径、后台 | 90–120 | 固定夹具、证据、角色守卫 |
| 自动化测试、联调、数据规模、部署、CodeArts | 115–150 | 3模块覆盖、1万条、演示、复核 |
| **合计** | **540–720** | 与六人资源假设处于同一数量级，但余量非常有限 |

**判断：有条件可行（中高风险）。** 不加入 O01/O02、全站全文、非论文跨类图边和复杂证明附件后，仍需在相同周期内完成 540–720 人时的高强度工作；数据获取和联调是关键路径。按周规划：第1–2周冻结范围/数据样例/设计；第3–5周采集+治理；第6–8周检索/门户/认领；第9–10周统计/图/后台；第11–13周测试和万条核验；第14–15周联调/CodeArts/答辩缓冲。任务可并行，不应误解为可无缝串行完成。

**近期课程节点：** 2026-10-13/14 是课前上传与课堂汇报；因此这两天只能宣称需求与 SPEC/UML 阶段完成的文档，不得宣称已实现上述系统或已验证性能。2026-10-20 是此前建议的终稿日，需以教师最新通知为准。

## 5. 正式范围控制与变更流程

1. **P0 / 必做**：FR01–FR16、NF01–NF08 的课程承诺和 IN01 创新；先有可观察的主成功/异常/权限验收，再考虑细节。
2. **P1 / Must 内的限制实现**：必须保留成果类型区分、来源溯源、可审核纠错和计数合法性，但可限定数据来源和算法技术复杂度；禁止把“延期做某一种高级算法”写成“撤销课程要求”。
3. **P2 / 选做**：O01/O02、跨类型合作自动推断、复杂文件材料、穷举全部等长路径、高阶主题模型。前两项属于基线 Optional，后几项是非必要实现增强，并非 V1.9 Must 缺失。
4. 每条改动必须记录**来源 old ID、单一目标 IMPL-ID、原 AC 处理方式、延期理由或冲突决定**。不能按同号覆盖，不能把不能复用的 AC 宣称等价。
5. 未经两组签认，文档状态始终为 **RC / 建议实施口径**，不得写 Frozen；未经运行测试，任何测试状态不得标 PASS。

## 6. 最高风险与验收红线

- **数据来源与规模**：先核对独立来源许可、四类字段覆盖、万条可复核来源与去重结果；模拟/混合必须单列，不能充作真实世界排名，也不能未获教师允许就伪称通过万条要求。
- **身份与审核安全**：拒绝同名自动合并、标题相似自动去重、认领自动覆盖原授权；待审核信息不得写入公开版本。
- **合作网络**：论文原始记录的每条无向边必须可定位去重论文证据；不得仅因同机构、同领域或同获奖项目名称就连边。
- **性能与工程证据**：NF02 2秒、NF05 60秒及NF08覆盖率未被本轮执行验证；保持待测目标、明确装置和数据集，不把构建 Word 的 GitHub Actions 成功等同于代码验收成功。
