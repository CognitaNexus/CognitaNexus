# 2. 系统总体说明

## 2.1 产品、数据与界面边界

学者为中心，以公开获准的四类成果元数据和生效关系提供检索与门户。功能联调≥100万条去重成果；最终容量基线≥500万条去重后可检索成果实体，查询负载≥100活跃并发用户；真实与模拟分组核对，不用模拟容量数据冒充已采集的真实成果。数据来源许可另行核验。

明确不建设论文投稿/发表、托管付费全文、第三方订阅代理、专利交易、支付、个人综合学术排名、实时全网搜索、通用科研问答或完整社交系统。

## 2.2 用户与业务角色

访客访问公开检索、门户、统计、网络；登录用户提交本人的认领申请；门户管理者仅可操作被授予的具体门户；管理员按具体权限管理来源、核验和审核；系统采集任务不具有人的门户授权；外部来源只提供获准的数据和原站地址。账号User、个人主页UserProfile、学者档案Scholar、学者成果关系Authorship、学者档案授权是五种独立对象。注册自动生成UserProfile；学者身份与Authorship不能由注册/昵称推导。

## 2.3 有条件可行性

团队六人/15周/每人每周6–8小时的基线资源对应540–720人时的规划假设，不是进度承诺。百万条数据合法可获得性、协作联调与 CodeArts 工程验收是最大风险。

# 4. 功能需求规格（必须实现）

### FR01 公开检索、组合筛选与稳定分页（Must）

**参与者：** 访客。**执行前提：** 对应对象、来源或账号满足已生效的公开/授权要求；权限失败不得修改任何业务实体。**规范性要求：** 可检索当前公开有效的成果与学者；成果支持类型、年份（两端含）、领域、发生时机构筛选；多维条件取交集。排序按选定字段后接稳定实体ID打破并列；切页保留查询上下文。不承诺实时全网检索。

**验收条件（需求层面的 Given/When/Then；未执行）：**

- **AC-IMPL-FR01-01**：Given 同词匹配一成果一学者，When 仅在成果范围查询，Then 只返回公开成果，不返回学者或待审成果。

- **AC-IMPL-FR01-02**：Given 同时选论文、2025年、机构甲，When 返回结果及下一页，Then 所有行符合全部条件、页间不重不漏、返回后筛选保留。

- **AC-IMPL-FR01-03**：Given 无匹配或依赖超时，When 查询，Then 分别返回无结果与执行失败，不混淆。

### FR03 公开个人主页与学者档案浏览（Must）

**参与者： 访客。规范性要求： 任何注册用户均有可公开访问的唯一UserProfile个人主页（稳定可分享地址），零学术成果时仍显示非错误的空状态；公开字段只包含用户允许展示的信息。平台来源Scholar档案独立存在，未认领时仍可公开展示符合许可与生效要求的研究者身份和成果，不得按姓名直接合并个人主页与Scholar，也不得把待核验成果标为已确认。**

**验收条件（需求层面的 Given/When/Then；未执行）：**

- **AC-IMPL-FR03-01**：Given 学者未认领且有已生效成果，When 访客打开门户，Then 可以浏览并看到未认领提示。

- **AC-IMPL-FR03-02**：Given 一名学者关联待核验成果，When 查看公开关系，Then 待核验不得显示成已确认合作或本人确认。

- **AC-IMPL-FR03-03**：Given 用户甲刚注册且无论文/专利/项目/获奖，When 访客凭其稳定主页地址访问，Then 能正常打开个人主页并看到“暂无公开成果”，不因零成果返回404。

- **AC-IMPL-FR03-04**：Given 普通用户资料和另一位同名Scholar档案，When 访客分别打开链接，Then 页面对象与核验状态区分显示，不自动合并或冒充已认证学者。

**参与者： 访客/登录用户/管理员。规范性要求： 注册成功时一次性创建User与唯一UserProfile，并绑定稳定公开地址及本人普通资料编辑权限；注册重试应幂等，不得产生重复或无主主页。登录、退出、账号状态与受保护接口检查均由服务端完成。UserProfile所有权不等同于Scholar档案的认领授权，隐私资料不得公开。**

**验收条件（需求层面的 Given/When/Then；未执行）：**

- **AC-IMPL-FR04-01**：Given 登录用户有门户甲授权而无门户乙授权，When 修改乙，Then 拒绝且不写入；前端隐藏入口不能取代拒绝。

- **AC-IMPL-FR04-02**：Given 账号被停用或已退出，When 发起受保护请求，Then 拒绝而不删除该用户关联的学者公开档案。

- **AC-IMPL-FR04-03**：Given 新用户注册成功且暂无学术身份，When 查询账号和个人主页，Then 恰好存在一个与该User绑定的UserProfile及稳定可分享的公开URL；重试不产生第二个主页。

- **AC-IMPL-FR04-04**：Given 未登录访问者查看个人主页，When 读取公开资料或尝试受保护写操作，Then 公开读取成功、修改被拒绝；凭据和审核材料不出现在公开响应。

**验收条件（需求层面的 Given/When/Then；未执行）：**

- **AC-IMPL-FR05-01**：Given 申请缺必要证据，When 提交，Then 不进入审核或标待补充并说明缺失。

- **AC-IMPL-FR05-02**：Given 管理员通过无冲突申请，When 事务生效，Then 新授权仅对目标门户有效，申请人可查询决定。

- **AC-IMPL-FR05-03**：Given 门户已有有效授权且他人争议申请，When 提交与处理，Then 原授权不转移，争议进入受控待办。

- **AC-IMPL-FR05-04**：Given 用户已拥有注册自动创建的个人主页，When 其成功认领一个已有Scholar档案，Then 仅新增经过批准的学者档案关联/管理授权，不创建第二个个人主页且不自动确认全部成果归属。

# 6. 业务流程与状态模型

## 6.1 数据管线与生命周期

获准来源→来源记录（保留原值）→结构校验→按稳定ID匹配/候选→学者证据和参与关系核验→发布合格实体与生效关系→检索、门户、统计和论文网络读取。不存在自动“采集过=已审核”的状态跳跃。

## 6.2 采集任务六状态与守卫

`待``执行`` → ``运行``中`` → ``成功``/``失败``/``已停止`；`失败`` → ``重试`` → ``运行中``/``失败`。每次重试保留检查点与任务历史；只有计划输入都记录到结果或异常队列后才可成功。异常待治理数量须披露，单次成功不暗示全部人工核验通过。停止后保留历史成果；不得重复计算实体。

## 6.3 认领与门户授权

`待``审核`` → ``待``补充`` → ``待``审核` 或 `待``审核`` → ``已通过``/``已驳回``/``争议`；争议交人工结论，但一期不支持原授权自动转移。Scholar认领申请状态不等于注册用户个人主页的公开状态；审核通过只授予对象级管理权，不代表任何成果真实或被本人逐条确认。门户已有授权则继续公开显示为已认领，不因竞争申请自动转未认领。

## 6.4 公开变更及成果关联

重要字段待审旧值继续公开；通过才生成生效版本。学者成果关系在自动关联、本人确认、待核验、争议、已排除中有确定有效状态；待核验/争议/已排除不得成为确定合作边。解除一人关联不删除共享成果、其来源或其他合法参与关系。历史审计保留可追踪前后值。

## 7.1 数据字段与来源

每个成果：内部稳定ID、类型、标题、来源ID、来源域/使用许可、采集/来源更新时间（不可混称）、真实/模拟/混合标识、公开生效状态。论文：DOI、作者顺序、发表年份/载体/版本证据；专利：申请号、发明人、申请/公开日期；项目：项目编号、负责人及承担单位、起止时间；获奖：年度、奖项、获奖人员/团队。不存在的专属字段标未知，不造默认值。

## 7.2 保留与一致性不变量

原始来源事实不被人工修订覆盖，公开规范值与审核记录独立；一个作者同一论文只能形成一条本人关系；重复来源不增加统计或图关系强度；公开实体存在不意味着每一个作者关联都合格；归属纠正可能改变论文合作图，但不得擦除历史证据。

# 9. 非功能要求与验收目标

### NF01 基础可用性

公开检索、门户、统计无需登录；加载、空结果、错误、越权和处理中可区分；表单有字段提示。

- **AC-IMPL-NF01-01**：分别准备空库、失败和无权请求，页面不能混淆成功零条与执行失败。（尚未执行）

### NF02 普通检索性能

NF02容量基线≥500万条去重可检索成果，≥100名同时活跃查询用户；固定环境、固定查询集、闭环负载模型，预热2分钟、测量≥5分钟，错误率≤1%，单请求超时5秒。须记录P50/P95/P99、吞吐、数据组成、硬件、索引大小、超时及失败数；未执行为NOT RUN。普通检索P95≤2秒原属另项候选，若无独立签认记录不得作为本轮已批准验收阈值。

- **AC-IMPL-NF02-01**：Given固定部署、≥500万可检索去重实体及100活跃用户查询集，When预热2分钟并以闭环负载测量≥5分钟，Then记录全部响应分位数、吞吐、错误率、硬件与索引证据，按已批准阈值判定，未执行为NOT RUN。

- **AC-IMPL-NF02-02**：Given≥500万可检索去重成果、100活跃闭环并发、2分钟预热和≥5分钟测量，When执行固定查询集，Then请求错误率≤1%，单请求超时5秒，未超容量时记录全部P50/P95/P99和资源条件；无运行证据为NOT RUN。

### NF03 安全及权限

凭据和证明受控；服务端每次校验账号、角色和对象授权；安全审计不包含秘密信息。

- **AC-IMPL-NF03-01**：跨用户写入、停用账号、未授权读取审核材料均拒绝。（尚未执行）

### NF04 可靠性与恢复

外部来源离线期间历史成果可读取；重复导入及恢复不重复创建实体或有效出处；每次备份恢复测试验证RTO≤30分钟、RPO≤24小时，记录测试起止、状态与恢复校验。（NOT RUN）

- **AC-IMPL-NF04-01**：恢复操作前后去重实体数/来源可核对，失败不删除历史。（尚未执行）

- **AC-IMPL-NF04-02**：Given一份可复核备份和故障恢复场景，When执行恢复，ThenRTO≤30分钟且RPO≤24小时，复核实体数、有效出处数、审核历史并保留日志。（NOT RUN）

### NF05 生效一致性与审计

更新生效后详情、门户、检索、统计及合格合作网络读取同一生效关系版本；待审不公开。逐项记录生效时刻与视图传播延迟；历史60秒目标不在本轮明确通过的量化清单内，须有独立签认记录才能作为硬性指标。

- **AC-IMPL-NF05-01**：Given有效归属变更正式生效，When逐视图查询，Then详情、检索、学者门户、统计和受影响的合作网络最终使用同一生效数据版本；逐视图记录传播时间，不得展示待审核关系。（NOT RUN）

- **AC-IMPL-NF05-02**：Given已审核的成果归属变更，When提交生效，Then检索、门户、统计和由论文参与关系派生的IN01/FR12网络最终一致；未运行标NOT RUN。

### NF06 隐私与数据最小化

不默认采集私人邮箱、手机号、未公开项目细节；认领证据仅本人及审核员按需可见；模拟标识可见。O02延期，因此一期不采集推荐行为画像。

- **AC-IMPL-NF06-01**：普通用户打开其他申请证明时被拒绝；公开详情无私有证明原文。（尚未执行）

### NF07 来源与配置可维护性

停用/更换来源不改变用户查询/门户操作语义；部署与任务恢复说明可复现。

- **AC-IMPL-NF07-01**：停用来源后既有公开成果仍可读，管理员可从日志定位任务错误。（尚未执行）

### NF08 代码质量和课程流程

后续实现阶段以数据清洗/去重、学者消歧、检索排序三个独立核心模块分别做行覆盖率≥80%检查；实现边界/权限/集成测试并以CodeArts留真实工程流程证据。未运行标NOT RUN。

- **AC-IMPL-NF08-01**：检查三个被选模块各自独立覆盖率，不以平均值替代；工程证据由 CodeArts 实测产生。（尚未执行）

# 12. 公开个人主页与学者档案的职责分离

现行基线：需求调研V2.0评审结果。本增补不改变FR01–FR16主编号、IN01/O01/O02或最终≥500万去重成果、≥100活跃并发等已批准规模；模型采用V2.1增补号便于追溯。

实体模型：User(账号) 1:1 UserProfile(公开个人主页)；Scholar(平台采集/核验的学者身份)可没有账号，User可不对应任何Scholar；当且仅当FR05通过审核，建立明确User—ScholarAuth/Claim授权记录；Scholar—WorkEntity通过Authorship关联，不能从普通用户资料直接推导。UserProfile 与 Scholar 不是一对一强制合并。

操作与边界：注册事务创建唯一UserProfile和稳定公开地址；User在通过会话/所有权校验后可直接修改昵称、头像、简介、兴趣领域等普通信息；匿名访客可读已允许公开字段；无成果只显示空态，不能冒充学术认证。Scholar归属、机构事实、成果确认、冲突处理严格按FR05/FR07/FR15。用户不能因注册、填个人简介或新增兴趣领域就被加入真实学者统计/论文合作网络。

对应UC及UML：UC-04“注册账号”含成功后自动建个人主页结果；UC-03“查看公开个人主页/学者档案”覆盖匿名与零成果；新增UC-22“编辑本人普通个人主页”；UC-07仍为已授权的学者档案维护；UC-05/UC-06仍仅处理Scholar认领与审核。新增独立“注册后个人主页生命周期”业务流程，不将创建UserProfile错画为独立外部参与者。原CodeArts导出图须在平台按附带UML修订说明同步；未重导出仍为NOT VERIFIED。

新增AC：AC-IMPL-FR03-03/04、FR04-03/04、FR05-04、FR06-03/04/05、FR07-03，共9条；当前唯一AC由60增至69条，全部新增项执行状态NOT RUN。原有已确认判据仍有效。
