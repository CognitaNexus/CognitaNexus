# 工程仓库文档导航

本目录保存工程实现侧的架构与规范文档。需求侧文档（基线、SRS、SPEC、UML）在需求仓库维护，此处只提供入口与追踪，不复制正文。

## 目录职责

| 路径 | 职责 |
| --- | --- |
| architecture/ | 架构设计说明书、架构决策记录（ADR） |
| standards/ | 编码规范、工程协作与 AI 协作规范 |
| ai/ | AI 辅助开发的任务证据、人工修正案例与资产清单（实现阶段建立） |
| ops/ | 部署与运维手册：拓扑、首次部署、备份恢复、升级、故障处置与已知限制 |

目录按实际授权创建，不预建空目录与占位文档。当前文档内容状态以各文档正文标注为准。

## 上位依据入口（需求仓库）

| 依据 | 用途 |
| --- | --- |
| 需求基线 V1.9 | FR / NF / IN / O 语义与优先级 |
| 双组实施候选 SRS V1.1（Implementation RC） | AC-IMPL-* 验收编号 |
| 核心 SPEC V1.0（Review Candidate） | 清洗、去重、消歧、检索排序规则 |
| UML 图源与生成图 | 用例、活动、状态、时序 |

## 维护约定

1. 架构决策变化必须新增或更新 ADR，不直接改写说明书结论；ADR 状态变更（Proposed → Accepted → Superseded）须记录日期与决定人。
2. 架构说明书中的需求编号引用必须与 SRS V1.1 的 AC-IMPL-* 一致；编号调整时同步更新全部引用。
3. 文档不写未实测的性能、覆盖率与测试结论；目标值标注为待签认或待实测。
4. 移动文档时同步检查相对链接；本目录文档对需求仓库的引用使用仓库地址而非本机绝对路径。
5. 图表使用 Mermaid 内嵌表示，与需求基线第 3.4 节的用法一致；若后续改为 PlantUML 维护源，须同步提交 .puml 与生成图并更新本节说明。
