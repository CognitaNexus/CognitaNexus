# 文档配置管理规范 V1.0（维护约定候选）

状态：Review Candidate；仅规范文档维护，不改变任何需求或授予 Frozen 状态。责任角色：模块作者维护内容，文档管理员维护导航及生成工具，两组负责人共同签认跨组业务变更。

## 阅读与效力

统一入口为 [docs/README](README.md)。需求 V1.9 决定业务语义与优先级；共同 SRS V1.1 是唯一当前工程实施候选；核心 SPEC V1.0 与 V1.1 对齐说明必须结合阅读。所有候选仍待签认。Supporting 保留详细来源，Review & Validation 保留证据，Historical 仅用于来源追踪，不作为当前开发基线，Tooling 不具有业务效力。分类不重写原文件在历史时间点的状态。

## 命名、版本和状态

1. 保留已有稳定路径、编号和名称；新评审快照使用主题及 YYYY-MM-DD；规范新版本使用 V主版本.次版本，候选可附 RC。文件名不代替正文版本。
2. 新文档写明标题、版本、日期、作者/责任模块、状态、输入版本与适用范围；未知作者或版本明确待确认，不填造事实。
3. Draft → Review Candidate → Approved → Frozen 必须有对应评审证据。两组共同文档须双方正式签认；合并 PR、自动检查通过、生成 Word 均不等于批准或冻结。
4. Historical 是导航效力分类，不抹去历史正文原来的 Draft/RC 状态。旧编号须同时带组别、来源版本和原文，不能单纯重命名为当前编号。

## 变更与评审

提交前记录来源提交、受影响需求/AC、理由和责任方。纯导航/工具变更与需求变更分开；需求语义、优先级、范围、阈值或流程变化须联合评审授权，并同步 SRS、SPEC、追踪、验收与图。依赖未决参数的验收不得标通过。历史追踪不追改为新决定，新增版本映射说明其效力。目录迁移须事先评估引用、所有者与生成命令并取得授权。

## 生成物与复现

Markdown 为 Word 内容来源，PlantUML 为 UML 唯一维护源；SVG/PNG 禁止手改。保留正式交付物，验证生成至 /tmp 或 CI artifact；经评审确认后才替换正式副本。记录输入 SHA、工具版本、命令、字体与过滤器，区分内容可重建与字节相同；DOCX ZIP 时间戳等不保证确定性。

[工具说明](../scripts/docs/README.md)列明历史工具副作用。只读检查默认不覆盖历史报告；CI 使用 contents: read、无自动提交。权限扩大、自动推送 main 或覆盖正式交付物须单独提出方案批准。

## 交付门禁

检查索引文件链接、追踪数量与目标、原文件保全、当前阅读链唯一、候选状态、图源/副本配对及 XML。Word 的 AC/媒体检查不代替完整文本及视觉核验；渲染成功不等于人工逐页检查。报告分别记录静态检查、生成、渲染、人工检查、未执行项及环境限制。软件单元/集成/性能测试不能用文档检查替代。
