# UC-12 Boundary / Control / Entity 识别

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.4.2：从用例事件流识别边界类、控制类、实体类；不从现有全局 BCE 反向填充。
**输入：** 本目录 01 规约、02 事件流。

## 1. 识别原则

1. **Boundary**：与外部参与者交互、接收请求或显示结果的对象。
2. **Control**：协调本用例内的范围过滤、统计资格、机构归属、机构规范名归并、机构维度计数与名次、披露与状态区分；不是实现层 Controller/Service，也不是聚合引擎或报表工具。
3. **Entity**：承载业务事实、状态与可追溯信息；不是数据库表、物化视图或排名快照。
4. 只有在本 UC 事件流中实际接收消息的对象才进入 VOPC。
5. 参与者“访客”“机构规范名与分类映射维护方”不是系统分析类；被拒绝的质量评分、机构评级、排名快照、DTO 与报表对象不进入本 UC。
6. 仅因“以后可能用到”而出现的类不进入本 UC；排名结果是**读时投影**，不建持久实体（05 §4；07 §5）。

## 3. 逐类选择理由

### C1 InstitutionRankingUI（Boundary）

- 发现于 E1 打开视图、E11 展示排名与声明、E12 条件变更、E14 口径解释与下钻；并承担 A1（条件非法）、A2（空结果）、A3（失败）、A4（未更新）、A13（类别维度不可用）、A16（规模超限）、A17–A19（越界与错误单位）的提示显示。
- 无持久业务属性；当前筛选条件、结果行、声明块、数据性质标识与提示类型是单次请求的展示状态。
- **命名说明：** 全局 BCE 文本与 `DGM-CLASS-01-analysis.puml` 只有 `AnalyticsUI`（`..>` `GraphCtl`），未区分“统计分布/机构排名”与“合作网络/路径”。本 UC 用 `InstitutionRankingUI` 明确“机构排名视图”语义；与 UC-11 的 `StatisticsUI`、UC-14/UC-15 的网络展示、UC-01 的 `SearchUI`、UC-02 的 `WorkDetailUI` 分离。与 `StatisticsUI` 是否合并（排名是否只是统计页内一栏）留 R5 与 B-10；合并案见 07 §2。

### C2 InstitutionRankingCoordinator（Control）

- 发现于 E2 范围判定、E3 统计资格与去重守卫、E4/E5 机构归属与证据、E6 归并、E7 机构维度计数、E8 名次、E9 覆盖率、E10 声明、E12 条件校验与重算、E13 数据性质守卫、E14 条件回显，以及 A1–A19 的分支裁决。
- 需要跨三类实体协调，并保证：①只有去重实体进入计数（来源/版本/关系/作者不放大）；②机构归属只用有证据的发生时机构，未知不进名次，且不用作者当前单位推断；③同一机构只出现一行；④机构维度合计可大于实体数且必须声明；⑤默认现实视图不混入模拟/混合；⑥结果、声明与更新时间一致；⑦空、失败、非法条件、未更新、规模超限互不冒充。
- 这些守卫都需要同时读多个实体（例如“同一成果同一规范机构只计一次”要同时看成果的归属集合与机构规范名），不能下推给单一实体。
- **命名说明：** 全局 `GraphCtl`（“+四类基础边/论文路径”）是网络与路径协调者，`SearchCtl` 是检索协调者；机构排名的守卫在全局无对应协调者。本 UC 使用 `InstitutionRankingCoordinator`；与 UC-11 的 `StatisticsCoordinator` 的边界/合并由 R5 与 B-10 决定（07 §2）。

### C3 WorkEntity（Entity）

- 发现于 E2 只读读取范围与共享字段、E4 发生时机构归属事实、E12 按条件重算；A7/A8 未纳入与版本重复、A9/A10 机构缺失与当前单位误用、A12 多机构。
- 必要性来自三个独立要求：①“按去重实体计数”（BR-IMP-02/06；`AC-IMPL-FR11-01`）；②“按成果类型、领域、时间范围筛选并说明口径”（FR11；FR11-S05）；③“默认现实视图只取真实、公开、生效、合格数据”（FR11；BR-IMP-01/07）。三者都要求一个“去重后、带共享字段与数据性质”的成果事实。
- 不能并入 `SourceRecord`：来源数是分母错误来源；重复来源不增实体数（BR-IMP-02；`AC-IMPL-FR16-02`）。
- 不能并入 `WorkVersion`：已确认版本合并仍只计一次，未确认版本按现有实体分别计数（FR11-S07 细化）。
- 不能并入 `Authorship`：见 C4。
- **本 UC 只读：** 不改共享字段、不合并/拆分实体、不改公开状态。

### C4 Authorship（Entity）

- 发现于 E4 只读读取参与者角色/顺序/多机构署名原值；A18 拒绝“按作者数或关系条数当机构计数”。
- 必要性：机构归属证据必须**逐参与者**可追溯（ID-05“多作者必须为每个作者分别形成 Authorship 候选，保留署名顺序、角色及多机构原值”），因此多机构原值不能压成 `WorkEntity` 上的单个字符串；同时 §2.2/BR-IMP-10 要求“实体统计资格与关系资格分离”，这只有把关系状态放在独立对象上才能表达。
- 不能并入 `WorkEntity`：参与关系的状态、角色与顺序是关系事实，成果共享字段不承载（§6.4；ID-05）。
- **本 UC 只读且不按关系计数：** 关系条数、作者数都不进入任何计数或分母；不写关系状态。

### C5 Institution（Entity）

- 发现于 E6 机构规范名/别名/合并链读取；A11 别名合并后不出现重复行；A9/A10 未映射与缺失标记。
- 必要性：FR11-S08 E2 要求“机构正名或别名发生合并时按合并后的规范名计数，不出现同一机构的重复行”，CL-05 要求“机构仅通过已审别名字典映射，未知则未映射”。这需要机构自身携带规范名、别名与合并链；仅靠成果上的机构原值字符串无法保证合并与去重。
- 不能并入 `WorkEntity`：机构跨成果共享，且机构合并链是机构身份的历史事实。
- 不能等同于“作者当前任职单位”：后者属学者档案的任职期事实（UC-07/UC-10），本 UC 明确**不**用它推断成果归属（BR-513；SR-06；SPEC T35）。
- **本 UC 只读：** 不新增机构、不改别名、不合并机构；机构类别维度是否作为排名维度待确认（B-02）。

## 5. 九项对象边界结论

| 边界 | 结论 | 本 UC 证据 |
|---|---|---|
| `WorkEntity`（去重成果实体） vs `SourceRecord`/`WorkVersion`（来源与版本） | 计数单位只能是成果实体；跨源重复、已确认版本合并都不增加计数；未确认版本按现有实体分别计并披露待确认数 | BR-IMP-02/06；`AC-IMPL-FR11-01`；`AC-IMPL-FR16-02`；FR11-S07 |
| `WorkEntity`（成果） vs `Authorship`（参与关系） | 一项成果可有多条参与关系，关系不是计数单位；实体资格与关系资格分离（关系待核验不使成果退出机构计数） | ID-05/ID-11；BR-IMP-06；Q-SPEC-08 |
| `Authorship`（参与者署名机构原值） vs `Institution`（机构身份） | 原值是来源侧署名事实（逐参与者、带发生时间）；机构身份提供规范名、别名与合并链；二者都只读 | ID-05；FR11-S08 E2；CL-05；BR-513 |
| `Institution`（机构身份） vs 作者当前任职（学者任职期） | 排名只用有证据的成果发生时机构，不用作者当前任职单位；两处事实分属不同对象、不同 UC，二者之间本 UC 不建关系 | BR-513；SR-06；SPEC T35；A10 |
| “成果发生时机构归属事实” vs “排名视图投影” | 前者是业务事实（可追溯证据，作为 `WorkEntity` 属性与关联表达）；后者是读时投影（条件、计数、名次、声明、更新时间），本 UC 只建前者 | 05 §4；07 §5 C-01 |
| 已知名次 vs 机构未知分组 | 未知单列、不进入已知名次、不分摊、不参与并列；合计可大于实体数且须声明 | BR-IMP-06；FR11-S05 E1 / AC-FR11-S08-03；A9/A19 |
| 机构行 vs 机构类别 | 每行是一个规范机构身份；机构类别（类型标签）体系未冻结，本 UC 不提供类别维度 | FR11-S05；Q-SPEC-03；A13 |
| 计数排名 vs 质量评价 | 只做计数与并列名次；不作质量、影响力、机构优劣、评级或个人综合学术排名 | BR-522；SRS §2.1 |
| 机构排名读侧 vs 检索读侧 | 下钻只回显同一条件与机构规范标识，检索执行与分页属 UC-01；两者须复现同一计数 | FR11-S05 步骤 5；FR01 |

## 6. 识别结论

本 UC 的候选分析类共 5 个：

- Boundary：`InstitutionRankingUI`
- Control：`InstitutionRankingCoordinator`
- Entity：`WorkEntity`（只读）、`Institution`（只读）、`Authorship`（只读）

持久排名结果/快照、口径版本、排名策略、来源记录、版本与去重候选、学者/账号/任职期、领域分类树、机构类别维度、质量评分与机构评级、独立 `InstitutionAffiliation`、排名任务/缓存/聚合引擎、DTO/展示投影、审计、会话与通知均不进入本 UC VOPC。该集合将在 04 的顺序图中接受消息检验；若某类没有消息，则删除或降为属性/职责。
