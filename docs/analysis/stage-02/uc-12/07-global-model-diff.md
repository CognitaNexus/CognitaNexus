## 4. 关系差异

### 4.1 `AnalyticsUI ..> GraphCtl`（全局图）

- 全局把统计、排名、热点、网络、路径的读侧统一指向 `GraphCtl`；本 UC 的机构排名不建边、不算路径，因此不依赖 `GraphCtl`。
- **R5 建议：** 保留 `AnalyticsUI` 作为读侧边界时可拆多条依赖（分布统计／机构排名／网络与路径），并明确“排名不调用建边/路径职责”。

### 4.2 `Work -- Source`、`Work -- Version`（全局未标多重性）

- 本 UC 沿用 `WorkEntity 1 : 0..* SourceRecord`、`WorkEntity 1 : 0..* WorkVersion`，但**不**把它们画入本 VOPC：来源数与版本数不参与机构计数（BR-IMP-02/06）。
- **R5 建议：** 保留既有边并注明“机构排名与规模核对均按实体计数，不按来源/版本计数”。

### 4.3 新增业务关联（全局无）

- `WorkEntity 0..* : 0..* Institution`（成果发生时机构归属，有证据）。两端均 `0..*` 的理由见 05 §2.2；与 UC-11 的同名关联一致，可由 R5 统一收录一次。
- **R5 建议：** 新增该关联并注明“仅含有证据的发生时归属；缺失/未映射不建边、计入机构未知或未映射披露”。

### 4.4 未画的关联（有意不画）

| 关联 | 不画理由 |
|---|---|
| `Authorship → Institution` | 参与者署名机构原值作为 `Authorship` 属性，避免与 `WorkEntity→Institution` 重复表达同一归属结果（05 §2.3） |
| `Scholar → Institution`（当前任职/任职期） | 本 UC 明确**不**用作者当前单位推断成果归属（BR-513；SR-06；T35）；画边会暗示可据此补全归属 |
| `Institution → Institution`（合并链自关联） | 合并链写成 `mergedIntoRef` 属性；顺序图无独立寻址消息（05 §2.3） |
| 排名结果/投影 → 任何实体 | 投影不是业务实体（05 §4；C-01） |

## 7. 差异结论

UC-12 分析支持以下全局模型调整建议：

1. 保留 `WorkEntity` 作为唯一计数单位，并在其职责中补“数据性质（真实/模拟/混合）”与“成果发生时机构归属事实（集合、带证据、可未知/未映射）”；
2. 新增 `Institution`（读侧最小职责：规范名/别名/合并链/未映射），否则“别名合并后不出现重复行”没有承载者；
3. 把“机构排名读数”从 `AnalyticsUI → GraphCtl` 的单一依赖中分离：机构排名 ≠ 分布统计 ≠ 合作网络与最短路径；
4. 明确机构排名口径守卫：默认仅真实、公开、生效、合格；去重实体计数；机构只取有证据的发生时归属；未知单列不进名次；同机构一行；机构维度合计可大于实体数；
5. 统一声明清单（筛选条件/时间范围/计数单位/归属/归并/未知/并列/分母与覆盖率/数据性质/更新时间）并要求条件变更后同步刷新，补下钻复核与口径解释；
6. **评审决定排名/统计结果的对象化程度（C-01）**：保留模块细化的结果版本/生效状态，或采用本包的读时投影；
7. **评审确认 C-02**：`Q-4`（跨机构归属口径）是否已被 `BR-IMP-06` 取代；在此之前本 UC 按现行 69 AC 基线执行；
8. **澄清“机构类别排名”的类别语义（B-02）** 与 UC-11/UC-12 的视图分工（B-10）；
9. 阈值、分类层级、占比分母、上限、更新时间语义与未映射处理仍需需求确认（B-01～B-12）。
