# UC-11 Boundary / Control / Entity 识别

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.4.2：从用例事件流识别边界类、控制类、实体类；不从现有全局 BCE 反向填充。
**输入：** 本目录 01 规约、02 事件流。

## 1. 识别原则

1. **Boundary**：与外部参与者交互、接收请求或显示结果的对象。
2. **Control**：协调本用例内的范围过滤、去重计数、维度聚合、机构归属、披露与状态区分；不是实现层 Controller/Service，也不是聚合引擎或报表工具。
3. **Entity**：承载业务事实、状态与可追溯信息；不是数据库表、物化视图或统计快照。
4. 只有在本 UC 事件流中实际接收消息的对象才进入 VOPC。
5. 参与者“访客”“口径与分类映射维护方”不是系统分析类；被拒绝的质量评分、统计快照、DTO 与报表对象不进入本 UC。
6. 仅因“以后可能用到”而出现的类不进入本 UC；统计结果是**读时投影**，不建持久实体（05 §4；07 §5）。

## 3. 逐类选择理由

### C1 StatisticsUI（Boundary）

- 发现于 E1 打开视图、E5/E11 展示结果与声明、E6/E12 条件与排名请求、E14 下钻复核；并承担 A1（条件非法）、A2（空结果）、A3（失败）、A4（未更新）、A14（样本不足）、A15（规模超限）、A16–A19（范围与数据性质边界）的提示显示。
- 无持久业务属性；所选条件、结果集、声明块与提示类型是单次请求的展示状态。
- **命名说明：** 全局 BCE 文本与 `DGM-CLASS-01-analysis.puml` 只有 `AnalyticsUI`（`..>` `GraphCtl`），未区分“统计分布/机构排名”与“合作网络/路径”。本 UC 用 `StatisticsUI` 明确“统计读数入口”语义；与 UC-14/UC-15 的网络展示边界及 UC-01 的 `SearchUI`、UC-02 的 `WorkDetailUI` 分离；合并入 `AnalyticsUI` 的建议留 R5（07 §2；B-10）。

### C2 StatisticsCoordinator（Control）

- 发现于 E2 范围判定、E3 去重计数、E4 声明生成、E7 条件校验、E8/E9 机构归属与归并、E10 机构计数与排名、E12 重算、E13 数据性质守卫、E14 条件回显，以及 A1–A19 的分支裁决。
- 需要跨三类实体协调，并保证：①只有去重实体进入计数（跨源/版本/作者不放大）；②机构归属只用有证据的发生时机构，未知不进名次；③默认现实视图不混入模拟/混合；④结果与声明、更新时间一致；⑤空、失败、非法条件、规模超限互不冒充。
- 这些守卫都需要同时读多个实体（例如“同一成果同一机构只计一次”要同时看成果的归属集合与机构规范名），不能下推给单一实体。
- **命名说明：** 全局 `GraphCtl`（“+四类基础边/论文路径”）是网络与路径协调者，`SearchCtl` 是检索协调者；统计分布与机构排名的守卫在全局无对应协调者。本 UC 使用 `StatisticsCoordinator`，R5 需要明确 `AnalyticsUI` 下的两个协调者边界（07 §2）。

### C3 WorkEntity（Entity）

- 发现于 E2 只读读取范围与共享字段、E8 发生时机构归属事实、E12 按条件重算；A7/A8 机构缺失与当前单位误用、A10 跨源/版本重复、A12 多领域、A13 未纳入实体。
- 必要性来自三个独立要求：①“统计按去重实体计数”（BR-IMP-02/06；`AC-IMPL-FR11-01`）；②“按类型/年份/领域统计并披露时间未知与多领域规则”（FR11；BR-IMP-06）；③“默认现实视图只取真实、公开、生效、合格数据”（FR11；BR-IMP-01/07）。三者都要求一个“去重后、带共享字段与数据性质”的成果事实。
- 不能并入 `SourceRecord`：来源数是分母错误来源；重复来源不增实体数（BR-IMP-02；`AC-IMPL-FR16-02`）。
- 不能并入 `WorkVersion`：已确认版本合并仍只计一次，未确认版本按现有实体分别计数（FR11-S07）；版本对象本身不是计数单位。
- 不能并入 `Authorship`：见 C4。
- **本 UC 只读：** 不改共享字段、不合并/拆分实体、不改公开状态。

### C4 Authorship（Entity）

- 发现于 E8 只读读取参与者角色/顺序/多机构原值；A17 拒绝“按作者数当成果数”。
- 必要性：机构归属证据必须**逐参与者**可追溯（ID-05“多作者必须为每个作者分别形成 Authorship 候选，保留署名顺序、角色及多机构原值”），因此多机构原值不能压成 `WorkEntity` 上的单个字符串；同时 BR-519 要求“实体统计资格与关系资格分离”，这只有把关系状态放在独立对象上才能表达。
- 不能并入 `WorkEntity`：参与关系的状态、角色与顺序是关系事实，成果共享字段不承载（§6.4；ID-05/ID-11）。
- **本 UC 只读且不按关系计数：** 关系条数、作者数都不进入任何分母；不写关系状态。

### C5 Institution（Entity）

- 发现于 E9 机构规范名/别名读取；A9 别名合并后不出现重复行；A7/A8 未映射与缺失标记。
- 必要性：FR11-S08 E2 要求“机构正名或别名发生合并时按合并后的规范名计数，不出现同一机构的重复行”，CL-05 要求“机构仅通过已审别名字典映射，未知则未映射”。这需要机构自身携带规范名、别名与合并链；仅靠成果上的机构原值字符串无法保证合并与去重。
- 不能并入 `WorkEntity`：机构跨成果共享，且机构合并链是机构身份的历史事实。
- 不能等同于“学者当前任职单位”：后者属 `Scholar` 的机构任职期事实（UC-07/UC-10），本 UC 明确**不**用它推断成果归属（BR-513；SR-06）。
- **本 UC 只读：** 不新增机构、不改别名、不合并机构；机构类别维度是否作为排名维度待确认（B-02/B-08）。

## 5. 四项对象边界结论

| 边界 | 结论 | 本 UC 证据 |
|---|---|---|
| `WorkEntity`（去重成果实体） vs `SourceRecord`/`WorkVersion`（来源与版本） | 计数单位只能是成果实体；跨源重复、已确认版本合并都不增加计数；未确认版本按现有实体分别计并披露待确认数 | BR-IMP-02/06；`AC-IMPL-FR11-01`；`AC-IMPL-FR16-02`；FR11-S07 |
| `WorkEntity`（成果） vs `Authorship`（参与关系） | 一项成果可有多条参与关系，关系不是计数单位；实体统计资格与关系资格分离（关系待核验不使成果退出统计） | ID-05/ID-11；BR-519（细化）；BR-IMP-06 |
| `Authorship`（参与者机构原值） vs `Institution`（机构身份） | 原值是来源侧署名事实（逐参与者、带发生时间）；机构身份提供规范名、别名与合并链；二者都只读 | ID-05；FR11-S08 E2；CL-05；BR-513 |
| `Institution`（机构身份） vs `Scholar`（学者当前任职） | 机构排名只用有证据的成果发生时机构，不用学者当前任职单位；两处事实分属不同对象、不同 UC | BR-513；SR-06；SPEC T35 |
| “成果发生时机构归属事实” vs “持久统计结果” | 前者是业务事实（可追溯证据），后者是读时投影（条件、计数、声明、更新时间）；本 UC 只建前者 | 05 §4；07 §5 C-01 |
| 默认现实视图 vs 演示模式 | 真实/模拟/混合互斥标识；默认只真实；模拟/混合只在显式演示模式展示且必须标识 | BR-IMP-07；`AC-IMPL-FR11-02`；NF06 |
| 机构未知 vs 已知名次 | 未知单列、不进入已知名次、不分摊；合计可大于实体数且须声明 | BR-IMP-06；BR-513；FR11-S08 E3 |
| 统计计数 vs 质量评价 | 只做计数与并列；不作质量、影响力、机构优劣或个人综合学术排名结论 | BR-522；SRS §2.1 |
| 统计读侧 vs 检索读侧 | 统计条目下钻只回显同一条件，检索执行与分页属 UC-01；两者须复现同一计数 | FR11-S11；FR01 |

## 6. 识别结论

本 UC 的候选分析类共 5 个：

- Boundary：`StatisticsUI`
- Control：`StatisticsCoordinator`
- Entity：`WorkEntity`（只读）、`Authorship`（只读）、`Institution`（只读）

持久统计结果/快照、口径版本、来源记录、版本与去重候选、学者/账号、领域分类树、机构类别维度、质量评分与排名策略、独立 `InstitutionAffiliation`、统计任务/缓存/聚合引擎、DTO/展示投影、审计、会话与通知均不进入本 UC VOPC。该集合将在 04 的顺序图中接受消息检验；若某类没有消息，则删除或降为属性/职责。
