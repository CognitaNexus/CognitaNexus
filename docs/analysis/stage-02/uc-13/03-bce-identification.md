# UC-13 Boundary / Control / Entity 识别

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.4.2：从用例事件流识别边界类、控制类、实体类；不从现有全局 BCE 反向填充。
**输入：** 本目录 01 规约、02 事件流。

## 1. 识别原则

1. **Boundary**：与外部参与者交互、接收请求或显示结果的对象。
2. **Control**：协调本用例内的条件校验、统计范围判定、统计资格判定、术语归并、计数、并列排序、样本与规模判定、披露与状态区分；不是实现层 Controller/Service，也不是聚合引擎、索引或报表工具。
3. **Entity**：承载业务事实、状态与可追溯信息；不是数据库表、物化视图或热点快照。
4. 只有在本 UC 事件流中实际接收消息的对象才进入 VOPC。
5. 参与者“访客”“主题登记与术语映射维护方”“领域分类映射维护方”不是系统分析类；被拒绝的语义主题模型、词向量、趋势/预测、质量评分、热点快照、DTO 与报表对象不进入本 UC。
6. 仅因“以后可能用到”而出现的类不进入本 UC；热点结果是**读时投影**，不建持久实体（05 §4；07 §5 C-01）。
7. **不从关键词反推主题**：关键词事实属 `WorkEntity`，规范词与凭证映射属 `TopicTerm`，二者不合并为一个“主题模型”类（FR13 明文“不做语义主题模型”）。

## 3. 逐类选择理由

### C1 HotspotUI（Boundary）

- 发现于 E1 打开视图、E12 展示排序与披露、E13 条件变更、E15 明细与口径解释；并承担 A1（条件非法）、A2（空结果）、A3（失败）、A4（未更新）、A15（样本有限/条数不足）、A16（映射覆盖不足）、A17–A18（越界与错误单位）、A19（规模超限）的提示显示。
- 无持久业务属性；当前条件、热点项、披露块、数据类别标识与提示类型是单次请求的展示状态。
- **命名说明：** 全局 BCE 文本与 `DGM-CLASS-01-analysis.puml` 只有 `AnalyticsUI`（`..>` `GraphCtl`），未区分“分布统计/机构排名/热点/网络与路径”。本 UC 用 `HotspotUI` 明确“领域热点视图”语义，与 UC-11 `StatisticsUI`、UC-12 `InstitutionRankingUI`、UC-14/UC-15 网络展示、UC-01 `SearchUI`、UC-02 `WorkDetailUI` 分离。是否与 `StatisticsUI` 合并（热点是否只是统计页内一栏）留 R5 与 B-12；合并案见 07 §2。

### C2 HotspotCoordinator（Control）

- 发现于 E2 条件校验、E3 范围判定、E5 统计资格、E7 术语归并、E8 计数、E9 排序、E10 样本与规模、E11 披露、E13 重算、E14 数据类别守卫、E16 版本核对，以及 A1–A19 的分支裁决。
- 需要跨两类实体协调，并保证：①只有公开真实论文关键词/已登记主题进入计数；②无凭证不合并、存疑单列标注；③同一论文同一规范词只计一次，来源/版本/作者数不放大；④计数降序＋规范词升序破并列；⑤稀疏或无关键词只显示“无数据/样本有限”与实际数量；⑥披露与结果同屏且随条件刷新；⑦空、失败、未更新、样本有限、映射覆盖不足、规模超限互不冒充。
- 这些守卫都需要同时读多个实体（例如“有凭证才合并”要同时看论文关键词原写法与 `TopicTerm` 的映射凭证，并确认未映射关键词单列规则），不能下推给单一实体。
- **命名说明：** 全局 `GraphCtl`（“+四类基础边/论文路径”）是网络与路径协调者，`SearchCtl` 是检索协调者；热点守卫在全局无对应协调者。本 UC 使用 `HotspotCoordinator`；与 `StatisticsCoordinator`/`InstitutionRankingCoordinator` 的边界/合并由 R5 与 B-12 决定（07 §2）。

### C3 WorkEntity（Entity，只读）

- 发现于 E4 只读读取成果公开状态、数据类别、时间语义、领域取值与关键词事实；E14 数据类别切换；A5–A11 的缺标识、模拟/混合、时间未知、缺关键词、未登记主题、跨源重复与列表内重复。
- 必要性来自四个独立要求：①“以**论文**关键词计数”（FR13；SPEC §4.1 把关键词列为论文可选证据字段）；②“在明确**年份窗**与**领域**下计算”（FR13；§7.1 时间语义分开）；③“公开真实数据”与数据类别标识（BR-IMP-01/07）；④“按去重实体计数，不按来源数/版本数”（`AC-IMPL-FR16-02` 边界；INV-02）。
- 不能并入 `SourceRecord`：来源数是放大错误来源，重复来源不增成果数（BR-IMP-02）。
- 不能并入 `WorkVersion`：已确认版本合并仍只计一次（A10）。
- 不能并入 `TopicTerm`：关键词是来源侧字段原值，规范词是主题登记结果；二者之间是**有凭证才成立**的映射，不是同一事实（FR13 明文；CL-05）。
- **本 UC 只读：** 不改关键词原值、不改领域取值、不改数据类别、不改公开状态。

### C4 TopicTerm（Entity，只读）

- 发现于 E6 读取规范词/原始写法/映射凭证、E15 归一明细回显；A9 未登记、A12 无凭证不合并、A13 规范化范围。
- 必要性来自三个独立要求：①“**已登记主题**”是基线允许的第二种计数源（FR13 明文）；②“同义词映射**有凭证才合并**”要求承载凭证来源与合并关系（FR13 明文；CL-05）；③“按计数降序＋**规范词升序**破并列”要求存在规范词身份（FR13 明文）。
- 不能并入 `WorkEntity`：规范词与凭证映射跨论文共享，且一个规范词可对应多项成果的多个写法（05 §2.2）；把它压进成果会丢失“凭证”这一可追溯事实，也无法解释合并明细。
- **不构造词典或模型**：本类只承载**已生效、可查询**的登记与凭证映射；没有凭证时不存在合并关系，关键词按规范化原写法单列（A12/A13；B-01/B-02）。
- **本 UC 只读：** 不新增主题登记、不新增或修改同义词映射、不改规范词。

## 5. 九项对象边界结论

| 边界 | 结论 | 本 UC 证据 |
|---|---|---|
| `WorkEntity` 的**关键词事实** vs `TopicTerm` 的**规范词** | 关键词是来源侧字段原值（可缺），规范词是已登记主题；二者只在**有凭证**的映射下等价，本 UC 不推断等价 | FR13 明文；SPEC §4.1/§4.4；CL-05 |
| `TopicTerm`（凭证映射） vs 自建词典/同义词表 | 只用已生效、可查询的凭证映射；无凭证或存疑→不合并、单列并标注；不新建词表 | FR13 明文；A12；BR-UC13-05 |
| 计数单位“论文 × 规范词” vs 来源数/版本数/作者数 | 前者是唯一计数单位；来源数、版本数、作者数与列表内重复都不放大计数 | `AC-IMPL-FR13-01`；BR-IMP-02；`AC-IMPL-FR16-02` 边界 |
| 领域取值（`WorkEntity.fieldRefs`） vs 领域分类体系 | 前者是分类结果引用（可“待分类/未映射”）；领域层级与映射由 FR14/FR16 维护，本 UC 只读并披露覆盖 | CL-05；Q-SPEC-03；B-09 |
| 关键词字段 vs 标题/摘要文本 | 只用关键词字段；标题/摘要不用于推断或补充主题（基线只允许关键词与已登记主题） | FR13 明文；SPEC §4.1；A9 |
| 稀疏数据 vs 零结果 vs 失败 | 三者可区分且不互相冒充：样本有限仍展示实际数值；无数据明确提示；失败明确失败 | `AC-IMPL-FR13-02`；NF01；A2/A3/A15 |
| 热点计数 vs 质量/趋势评价 | 只做计数与并列名次；不做趋势预测、语义主题模型、质量/影响力/学术水平评价 | FR13 明文；§2.1；A17；BR-UC13-11 |
| 真实/模拟/混合数据 | 互斥标识；默认现实视图只取真实；模拟/混合仅显式演示并固定标识 | BR-IMP-07；A5/A6 |
| 热点读侧 vs 检索读侧 | 热点项明细只回显原写法、次数与凭证来源；检索执行与分页属 UC-01，两者须同版本 | NF05；UC-01 边界 |

## 6. 识别结论

本 UC 的候选分析类共 4 个：

- Boundary：`HotspotUI`
- Control：`HotspotCoordinator`
- Entity：`WorkEntity`（只读）、`TopicTerm`（只读）

持久热点结果/快照、语义主题模型/聚类/词向量、自建词典、趋势与预测对象、质量评分与学者个人排名、来源记录、版本与去重候选、学者/账号/参与关系、领域分类树、独立 `Keyword` 实体、指标口径对象、热点任务/缓存/聚合引擎、DTO/展示投影、审计、会话与通知均不进入本 UC VOPC。该集合将在 04 的顺序图中接受消息检验；若某类没有消息，则删除或降为属性/职责。
