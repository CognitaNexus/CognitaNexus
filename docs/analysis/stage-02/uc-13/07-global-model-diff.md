## 4. 关系差异

### 4.1 `AnalyticsUI ..> GraphCtl`（全局图）

- 全局把统计、排名、热点、网络、路径的读侧统一指向 `GraphCtl`；热点不建边、不算路径，也不做图结构计算，因此不依赖 `GraphCtl`。
- **R5 建议：** 保留 `AnalyticsUI` 作为读侧边界时可拆多条依赖（分布统计／机构排名／热点／网络与路径），并明确“热点不调用建边/路径职责”。

### 4.2 `Work -- Source`、`Work -- Version`（全局未标多重性）

- 本 UC 沿用 `WorkEntity 1 : 0..* SourceRecord`、`WorkEntity 1 : 0..* WorkVersion`，但**不**把它们画入本 VOPC：来源数与版本数不参与关键词计数（BR-IMP-02；`AC-IMPL-FR16-02`）。
- **R5 建议：** 保留既有边并注明“关键词热点与规模核对均按实体计数，不按来源/版本计数”。

### 4.3 新增业务关联（全局无）

- `WorkEntity 0..* : 0..* TopicTerm`（论文关键词事实按有凭证映射归入规范词；未映射按原值单列）。两端均为 `0..*` 的理由见 05 §2.2。
- **R5 建议：** 新增该关联并注明“只含有凭证映射；无凭证/存疑不建边、写法单列并标注；该关联不表达语义相似度”。

### 4.4 未画的关联（有意不画）

| 关联 | 不画理由 |
|---|---|
| `Scholar → TopicTerm`（研究者热门主题） | 本 UC 不做按学者个人的热点排名（SRS §2.1；A17），画边会暗示个人热度画像 |
| `TopicTerm → Field`（主题属于某领域） | 领域分类层级与主题—领域映射未冻结（Q-SPEC-03；B-09）；关系图无对应消息 |
| `TopicTerm → TopicTerm`（同义合并链自关联） | 合并关系写成 `variants[]`＋`synonymEvidence[]` 属性；顺序图只有 M8/M25 两次读取，无独立寻址消息（05 §2.3） |
| `WorkEntity → Keyword` | 关键词属性化在 `keywordFacts[]`；不建独立 `Keyword` 实体（03 §4；05 §2.3） |
| 热点结果/投影 → 任何实体 | 投影不是业务实体（05 §4；C-01） |

## 7. 差异结论

UC-13 分析支持以下全局模型调整建议：

1. 保留 `WorkEntity` 作为唯一计数单位，并在其职责中补 `dataOrigin`、`fieldRefs[]` 与**论文关键词事实** `keywordFacts[]`（原写法/来源字段/证据/缺失标记）；
2. 新增 `TopicTerm`（读侧最小职责：规范词/原始写法/同义词映射凭证来源/映射状态），否则“有凭证才合并”与“规范词升序破并列”没有承载者；明确禁止把它实现为词典或语义主题模型；
3. 把“领域热点读数”从 `AnalyticsUI → GraphCtl` 的单一依赖中分离：热点 ≠ 分布统计 ≠ 机构排名 ≠ 合作网络与最短路径；
4. 明确热点口径守卫：三种条件明确（领域/年份窗/数据类别）、两种计数源（论文关键词/已登记主题）、论文×规范词去重、有凭证才合并、计数降序＋规范词升序、稀疏只显示实际数量；
5. 统一披露清单（字段来源/年份窗/领域与映射覆盖/数据类别/样本量/映射凭证来源/并列规则/更新时间）并要求条件变更后同步刷新，补“术语明细可回溯”；
6. **评审决定热点结果的对象化程度（C-01）**：保留模块细化的结果版本/状态机，或采用本包的读时投影；
7. **评审确认 C-02**：模块细化 FR13-S05（趋势展示）是否已退出本期范围；在此之前本 UC 按 69 AC 基线“不做趋势预测”执行；
8. **评审确认 C-03**：模块细化 FR13-S03 的机构/成果类型/数据集范围条件是否纳入；在此之前本 UC 只实现基线的三项条件；
9. 澄清与 UC-11/UC-12 的视图分工与边界类口径（B-12）；
10. 映射凭证来源、规范化范围、未登记关键词、默认年份窗、阈值、条数与上限、更新时间语义、覆盖率口径、关键词字段口径与计数单位仍需需求确认（B-01～B-11）。
