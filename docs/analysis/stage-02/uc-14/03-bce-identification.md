# UC-14 Boundary / Control / Entity 识别

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.4.2：从用例事件流识别边界类、控制类、实体类；不从现有全局 BCE 反向填充。
**输入：** 本目录 01 规约、02 事件流。

## 1. 识别原则

1. **Boundary**：与外部参与者交互、接收请求或显示结果的对象。
2. **Control**：协调本用例内的条件校验、数据范围与数据类别判定、成果资格判定、参与关系资格判定、节点身份守卫、建边、强度去重、证据绑定、披露与规模判定、状态区分与版本核对；不是实现层 Controller/Service，也不是图数据库、索引、缓存或图渲染引擎。
3. **Entity**：承载业务事实、状态与可追溯信息；不是数据库表、物化视图或图快照。
4. 只有在本 UC 事件流中实际接收消息的对象才进入 VOPC。
5. 参与者“访客”不是系统分析类；被拒绝的最短路径、图版本快照、机构/领域筛选、质量评分、DTO 与渲染对象不进入本 UC。
6. 仅因“以后可能用到”而出现的类不进入本 UC；网络是**本次请求内推导**的结果，持久“网络结果/图快照”是否成立见 05 §4 与 07 §5 C-01。
7. **不从旁证推出合作**：同机构、同领域、相似姓名、同一来源或账号资料都不是合作证据；只有“同一项合格共同成果上的两条合格参与关系”构成边（FR12 明文：同机构/同领域/相似姓名；§12：账号与普通主页；同一来源不建边为分析推导；AC-IMPL-FR12-04）。

## 3. 逐类选择理由

### C1 CollaborationNetworkUI（Boundary）

- 发现于 E1 打开视图、E14 展示网络与声明、E15/E16 的边与节点检视、E17 导航、E18 范围变更；并承担 A1（条件非法）、A2（无合作关系）、A3（失败）、A17（规模超限）、A20（导航不可用）的提示显示。
- 无持久业务属性；当前条件、节点/边、披露块、数据类别标识、规模信息与提示类型是单次请求的展示状态。
- **命名说明：** 全局 `01-BCE` 与 `DGM-CLASS-01` 只有 `AnalyticsUI`（`..>` `GraphCtl`；“+统计/排名/热点/基础网络/路径”）。本 UC 用 `CollaborationNetworkUI` 明确“四类共同成果基础合作网络”语义，与 UC-11 `StatisticsUI`、UC-12 `InstitutionRankingUI`、UC-13 `HotspotUI`、UC-15 的路径/筛选视图分离。是否合并回 `AnalyticsUI` 留 R5 与 B-12（07 §2）。

### C2 CollaborationNetworkCoordinator（Control）

- 发现于 E2 条件校验、E3 数据范围、E5 成果资格、E7 参与关系资格、E9 节点资格、E10 建边、E11 强度、E12 证据、E13 披露与规模、E18 重建、E19 版本核对、E20 边界拒绝，以及 A1–A19 的分支裁决。
- 需要跨四个实体协调，并保证：①四类成果同等进入候选、不裁成论文图；②同机构/同领域/相似姓名不建边；③每项去重成果对同一学者对只贡献 1，来源/版本/重复角色不放大；④强度＝证据清单条数、边可追溯；⑤待核验/争议/已排除不进入强度与证据；⑥默认只真实、模拟仅演示并标识；⑦空/失败/未更新/超限/越界互不冒充。
- **命名说明：** 全局 `GraphCtl`（“+四类基础边/论文路径”）与 `01-BCE` 的 `AnalyticsNetworkCoordinator`（“四类合格基础图、论文子图、筛选/BFS/等长规则”）把**建边**与**论文筛选/路径**放在同一个协调者上。本 UC 只承担建边部分；建议 R5 拆分“基础网络建边”与“论文子图筛选/路径（UC-15）”（07 §2）。

### C3 WorkEntity（Entity，只读）

- 发现于 E4 读取成果身份与资格字段、E10–E12 作为强度贡献单位与证据、E15 证据成果公开字段；A5/A6 数据类别、A7 时间未知、A12 版本/来源重复、A13 多成果、A16 成果类型。
- 必要性来自三个独立要求：①“实体按去重后 `canonical_id` 计算”（FR12 明文；BR-IMP-02）；②“四类成果均可用”（FR12 明文；AC-IMPL-FR12-01）；③“真实、公开、合格”与时间语义（BR-IMP-01/07；§7.1）。
- 不能并入 `Authorship`：成果是共享实体，解除一位参与者不删除成果与其他合格关系（INV-05；§6.4）。
- 不能并入 `SourceRecord`/`WorkVersion`：来源数与版本数不增加强度（AC-IMPL-FR12-02；`AC-IMPL-FR16-02` 边界）。
- **本 UC 只读：** 不改公开状态、数据类别、发生时间、字段与版本关系。

### C4 Authorship（Entity，只读）

- 发现于 E6 读取参与关系、E7 资格判定、E10 取参与者集合；A8/A9 状态排除、A11 身份歧义、A14 角色不同、A19 缺角色证据。
- 必要性来自三个独立要求：①“按合格作者/发明人/项目参与者/获奖个人成员建边”要求区分四类角色及其证据（FR12 明文；SPEC §1）；②“已核验参与关系”要求承载角色证据与关系状态（FR12 明文；FR15；§6.4）；③“待核验/争议/已排除不产生边”要求状态与证据可分离判定（AC-IMPL-FR12-04；§11.3）。
- 不能并入 `Scholar`：关系状态属于“学者—成果”关系而不是身份；同一位学者在不同成果上可处于不同状态（AC-IMPL-FR15-06 语义）。
- 不能并入 `CollaborationEdge`：Authorship 是**一对一成果**的参与事实；边是**一对学者**的聚合关系（05 §2.2）。
- **本 UC 只读：** 不改角色、顺序、状态与证据。

### C5 Scholar（Entity，只读）

- 发现于 E8 读取身份与公开状态、E9 节点资格与合并解析、E17 导航；A11 同名不合并、A15 合并后唯一节点、A20 目标不可用。
- 必要性来自两个独立要求：①“实体按 canonical_id 计算”“`stable_id`＝学者 `canonical_id`，不是姓名、ORCID 原文、来源内 ID 或账号”（FR12 明文；SPEC §2）；②合并后不得保留重复节点与自环（BR-530；FR12-S04/S08 细化）。
- 不能并入 `User`/`UserProfile`：合作网络节点是平台采集/核验的学者身份，注册用户与其普通主页不是合作证据（`01-BCE` §5；§12）。
- **本 UC 只读：** 不合并身份、不改公开范围；身份判定属 UC-10。

### C6 CollaborationEdge（Entity，派生）

- 发现于 E10 建边、E11 强度、E12 证据、E13 披露（节点/边规模）、E15 证据清单、E16 节点强度；A12–A16。
- 必要性来自两个独立要求：①“任意两名学者之间只有一条无向边，强度＝去重合格共同成果数”（FR12 明文；BR-IMP-08；AC-IMPL-FR12-03）；②“每条边可追溯至至少一项合格共同成果，强度与证据清单条数一致”（BR-IMP-08；FR12-S03 细化）。二者都要求一个**携带两端与证据集合聚合**的对象。
- **派生而非事实源：** 本 UC 的边完全由“合格成果 + 合格参与关系 + canonical 身份”推导，本次请求内即可重建，故不把它作为独立事实源持久保存；它是**只读派生对象**（05 §4；07 §5 C-01 待确认）。
- 不能并入 `WorkEntity`：一项成果可产生多对学者的边（多作者），边与成果是 `0..*`:`1..*`。
- 不能并入 `Scholar`：边是二元关系而不是节点属性；把强度写成节点属性会丢失“与哪位学者”的对应。

## 5. 九项对象边界结论

| 边界 | 结论 | 本 UC 证据 |
|---|---|---|
| `CollaborationEdge`（派生边） vs 持久网络结果/图快照 | 边是二元关系的派生聚合，请求内可重建、必须带证据；本 UC 不建持久结果对象（是否保留版本见 C-01） | BR-IMP-08；FR12 明文；05 §4 |
| `WorkEntity` vs `Authorship` | 成果是共享实体，参与关系携带角色/顺序/状态/证据；解除一位参与者不删成果与其他合格关系 | INV-05；§6.4；AC-IMPL-FR15-06 |
| `Authorship` vs `Scholar` | 关系状态属于“学者—成果”关系；身份属于学者。同名/相似姓名不得合并，身份候选交 UC-10 | BR-IMP-03；§11.3；AC-IMPL-FR15-04 |
| `Scholar` vs `User`/`UserProfile` | 节点标识只能是 `canonical_id`；账号与普通主页资料不是节点标识也不是合作证据 | SPEC §2；§12；`01-BCE` §5 |
| 四类合格共同成果 vs IN01 论文子图 | 基础网络接受四类成果；论文子图限定与路径属 IN01/UC-15，本 UC 不裁剪 | FR12 明文；AC-IMPL-FR12-01/05；IN01-R1 |
| 共同成果证据 vs 同机构/同领域/相似姓名 | 只有同一合格成果上的两条合格关系构成边；机构/领域/姓名相似不构成证据 | FR12 明文；AC-IMPL-FR12-04；BR-IMP-08 |
| 合格关系 vs 待核验/争议/已排除 | 后者不产生强度、不作证据、不暴露明细（是否可视化提示待确认）；管理员审核≠本人确认 | AC-IMPL-FR12-04；FR12-S05 细化；§11.3；B-09 |
| 关系强度 vs 质量/影响力/学术水平 | 强度＝去重合格共同成果数，仅作结构计数，固定声明不代表质量；不排序、不评级 | BR-522（细化）；FR12-S03（细化）；§2.1 |
| 网络读侧 vs 统计/检索读侧 | 网络只表达节点与边；结果计数与排名属 UC-11/UC-12，热点属 UC-13；三者须同一生效数据版本 | NF05；BR-IMP-10；BR-523（细化） |

## 6. 识别结论

本 UC 的候选分析类共 6 个：

- Boundary：`CollaborationNetworkUI`
- Control：`CollaborationNetworkCoordinator`
- Entity：`WorkEntity`（只读）、`Authorship`（只读）、`Scholar`（只读）、`CollaborationEdge`（派生、只读、证据承载）

最短路径/路径证据、持久网络结果/图快照/图版本、机构与领域实体、身份候选与合并对象、账号与普通主页、来源记录与版本、去重/清洗候选、质量与影响力评分、强度排行榜、审计证据、会话、DTO/渲染对象、图存储/索引/缓存/构建任务、强度阈值对象、推荐与行为画像、通知均不进入本 UC VOPC。该集合将在 04 的顺序图中接受消息检验；若某类没有消息，则删除或降为属性/职责。
