> **范围边界：** 本 UC 只处理“**四类共同成果基础合作网络的公开读侧**”：以 **Scholar** 为节点、以“两名不同学者共享至少一项合格共同成果且两端参与关系均合格”为**无向边**，边强度按**去重合格共同成果实体数**计，每条边可回溯到其共同成果证据，并同屏披露关系定义、强度含义、数据范围与更新时间。
> **基础网络不是论文图**：论文（合格作者）、专利（合格发明人）、项目（合格项目参与者）、获奖（合格获奖个人成员）四类同等参与建边；**论文子图限定与最短路径属 IN01/UC-15**，本 UC 不裁剪、不计算路径、不推断“同机构必合作”。
> **按机构/领域筛选网络**同样属 IN01/UC-15；本 UC 的视图条件只有数据类别（现实/演示）与已声明的时间范围（默认窗待确认）。
> 成果去重（UC-09）、身份与归属判定及纠正（UC-08/UC-10）、采集与增量（UC-18/19）、统计分布与机构排名（UC-11/12）、领域热点（UC-13）、成果详情与检索（UC-01/02）、学者门户（UC-03）、后台审计（UC-17）均不在本 UC。
> 本 UC **全程只读**：不写成果、参与关系、关系状态、学者身份与合并、来源与许可；**不建持久“网络结果/图快照”实体**（读时投影，取向差异见 07 §5 C-01）；**不做**质量、影响力、学术水平评价或个人综合排名（BR-522 语境；SRS §2.1）；**不做**实现设计（图数据库、索引、缓存、任务、接口、DTO）。

> **对象区分（本 UC 的核心边界）：**
> - `WorkEntity` 是**去重后的成果规范实体**（canonical 成果标识）：在本 UC 只提供成果身份、类型（论文/专利/项目/获奖）、公开生效状态、数据类别（真实/模拟/混合）、已核验发生时间，以及证据展示用的公开字段。它**不是**参与关系，也**不是**边的强度单位之外的东西：一项成果对同一学者对最多贡献 1 强度。
> - `Authorship` 是**学者—成果参与关系**，携带**四类角色之一**（论文合法作者／专利合法发明人／合格项目参与者／合格获奖个人成员）、角色顺序（适用时）、关系状态（自动关联／本人确认／待核验／争议／已排除）、公开性与角色证据引用。它**不是**边：同名同机构的两条 Authorship 不构成合作；待核验/争议/已排除的 Authorship 不产生强度也不作证据。
> - `Scholar` 是**平台采集/核验的学者身份**，节点标识只能取 `canonical_id`；它**不是**账号 `User`、**不是** `UserProfile`（普通主页资料不进入网络）、也**不是** 同名姓名串。
> - `CollaborationEdge` 是**派生合作关系**：由合格共同成果与两端合格参与关系在本次请求内推导，以学者对 min/max `canonical_id` 为边键，`weight`＝该对不同去重成果数，证据按成果 `canonical_id` 升序保存。它**必须携带证据**、**可回溯**，但本 UC **不把它作为独立事实源持久保存**；是否保留结果版本与状态机见 07 §5 C-01（待确认）。

## 2. 目标

让访客在**公开、可复核**的前提下看到由**真实、公开、合格的四类共同成果与已核验参与关系**构成的学者合作网络：节点只取公开学者 canonical 身份，边只由“两名不同学者共享至少一项合格共同成果”产生；每项去重合格成果对同一学者对只贡献 1 强度，跨来源、重复角色与已确认版本都不重复累计；每条边可回溯到其共同成果证据，且强度与证据清单条数一致；仅同机构、同领域或相似姓名不产生任何边；待核验/争议/已排除关系既不产生强度也不作证据；默认现实视图只含真实数据；同屏披露关系定义、强度含义、数据范围、被排除关系状态与更新时间，使任一节点、边与强度都能按同一快照复算。

## 3. 触发事件

1. 访客打开四类共同成果基础合作网络视图（默认现实视图；未显式指定时使用已声明的默认时间范围）。
2. 访客在该视图内切换数据类别（现实/演示）或调整时间范围。
3. 访客选中一条合作关系，请求其成果依据清单。
4. 访客选中一个学者节点，请求其关系强度与含义说明。
5. 访客从节点导航到学者门户，或从证据清单导航到成果详情。
6. 访客提出越界请求（最短路径、按机构/领域筛选网络、个人综合排名或质量评价）。

## 4. 前置条件

1. 平台已收录公开生效的成果实体；成果实体已由 FR09/UC-09 去重（本 UC 不判定实体唯一性）；某范围可能命中 0 条合格合作关系（A2）。
2. 每项成果具备：类型、公开生效状态、数据类别（真实/模拟/混合）、已核验发生时间（可未知）与来源/许可（§7.1；BR-IMP-01/07）。
3. 每项成果的参与者以 `Authorship` 表达：角色为四类之一，角色顺序与角色证据（论文作者顺序、专利发明人、项目成员、获奖个人成员）可查；关系状态取自动关联／本人确认／待核验／争议／已排除之一（FR15；§6.4；§11.3；SPEC FR12-IN01 §1）。
4. 参与者身份已由 FR15/UC-10 归一到公开学者 `canonical_id`；合并先解析到当前 `canonical_id`，环或失效目标按异常处理（SPEC §2；BR-IMP-03）。
5. 身份/归属明确且可公开的参与关系，其状态须为**本人确认**或**具备已批准自动规则或独立人工核验证据的自动关联**；“管理员审核”本身不等于本人确认（FR15；§11.3；SPEC §1）。
6. 合作网络是公开只读能力，无需登录，也没有对象级授权分支（NF01；§8）。
7. 合作网络与检索、门户、统计使用同一生效关系版本（NF05）；60 秒传播目标不在本轮已批准清单内（NF05 原文）。
8. 合作网络的容量/并发/超时只在 NF02 的整体验收下核对；本 UC 不主张独立性能阈值（NF02；08 §5）。

## 5. 成功与失败后置条件

### 5.1 成功（网络结果）

1. 节点集合只含**公开学者**的 canonical 身份；合并后不保留重复节点、不出现自环（SPEC §2；BR-530；M13）。
2. 边集合只由“两项参与关系在同一项**合格共同成果**上均合格且参与者为两名不同学者”产生；**仅同机构、同领域、相似姓名、同来源或许可关系不产生边**（FR12 明文；AC-IMPL-FR12-04；BR-IMP-08；M7/M10/M13）。
3. 基础网络用**四类**合格成果建边：论文按合格作者、专利按合格发明人、项目按合格项目参与者、获奖按合格获奖个人成员；不因“只有共同专利/项目/获奖”而丢边（AC-IMPL-FR12-01/05；M7）。
4. 任意两名学者之间只有**一条无向边**；作者顺序不同、角色不同、成果不同都不产生新边（FR12-S04 细化与基线一致；BR-IMP-08；M14）。
5. 强度＝**该对不同去重合格共同成果实体数**：每项成果对同一学者对只贡献 1；同成果多来源、重复角色、已确认版本不重复加权；跨来源不重复累计（AC-IMPL-FR12-01/02/03；BR-IMP-08；BR-IMP-02；`AC-IMPL-FR16-02` 边界；M16/M17）。
6. 每条边**至少一项**合格共同成果证据，且**强度必须等于证据清单条数**；不一致按缺陷处理（BR-IMP-08；FR12-S03 细化；M18/M25–M30）。
7. 证据清单每项展示标题、类型、时间、来源与归属状态；字段缺失标“未知”而不隐藏该项；可从清单进入成果详情（UC-02）（FR12-S02 细化；M27–M30）。
8. 同屏披露：数据范围（真实/演示）、时间范围、关系定义（共享至少一项合格共同成果且两端参与关系均合格）、强度含义（共同成果实体数）、被排除的关系状态与未纳入计数、节点/边规模、更新时间（AC-IMPL-FR12-01/02 语境；BR-IMP-07；FR12-S01/S03/S05 细化；M19/M21/M22）。
9. 固定声明“关系强度不代表研究质量、影响力或学术水平”，与结果同屏、可直接读到（BR-522 语境；FR12-S03 细化；M22/M35）。
10. 无合作学者不虚构连线、不作为有边节点出现；口径说明必须写出该处理方式（FR12-S07 细化；BR-IMP-08；M19/M22；处理口径待确认 B-05）。
11. 规模超过已声明展示上限时提示当前规模并引导收窄，不把未声明子集描述为完整网络（FR12-S06 细化；NF01；M20；上限待确认 B-02）。

### 5.2 成功（数据类别与一致性）

1. 默认现实视图只纳入**真实**数据；模拟与混合数据只在显式演示模式下展示，并在结果区与披露中固定标识“不得用于描述真实世界”（BR-IMP-07；M4/M45）。
2. 缺真实/模拟/混合标识的成果**不**计入真实数据，归“数据类别未知”并在披露中给出数量（BR-IMP-07 互斥标识＋分析推导；B-04；M4）。
3. 范围变更后按新范围重建并**同步刷新**披露与数据类别标识，不保留与结果不符的旧披露（FR12-S01 A1 细化；BR-IMP-07；M45/M47）。
4. 网络与检索/门户/统计使用同一生效关系版本；落后时标注“结果可能未反映最新变更”，不展示待审核关系（NF05；M46/M47）。

### 5.3 失败（无业务写入）

1. 本 UC 无写操作：失败不改变成果、参与关系、关系状态、学者身份、合并结果与来源。
2. 条件非法、范围内无合作关系、执行失败、数据未更新、规模超限五类结果可区分且不互相冒充（NF01；FR12-S01 E1/E2；M3/M49/M50）。
3. 无合作关系时明确提示并展示数据范围，**不展示空画布作为正常结果**（FR12-S01 E1 细化；M49）。
4. 结果不可用时明确失败：不展示半成品网络、不以过期结果冒充最新、不编造更新时间（NF01；FR12-S01 E2 细化；M49）。
5. 拒绝最短路径查询、按机构/领域筛选网络、个人综合排名与质量/影响力评价，并给出可用范围与交接（FR12/IN01 分工；BR-IMP-09；SRS §2.1；M51/M52）。
6. 待核验/争议/已排除关系**永不**产生强度或证据；仅依赖该关联的边不出现，仍有其他合格证据的边保留并按有效证据计数（AC-IMPL-FR12-04；FR12-S05 细化；M10）。

## 11. 待确认

1. **B-01 强度口径的展示与解释边界**：基线 `AC-IMPL-FR12-03` 已固定“强度累计为 2”，模块细化 FR12-S03 备选 A1 又允许“评审决定不展示关系强度”。本分析按基线**必须展示强度**建模，并把该备选登记为差异（07 §5 C-02），需确认 FR12-S03 A1 是否仍然有效。
2. **B-02 展示上限（节点数/边数）与收窄方式**：FR12-S06 要求上限但未给值（Q-6；待决清单 D-08）；IN01 的“≤1 万节点/≤10 万边”只针对论文子图（AC-IMPL-IN01-04）。本 UC 只要求“声明实际规模、不把子集冒充完整”，上限数值留空。
3. **B-03 时间范围条件**：基线 FR12 未规定时间范围是否为视图条件；模块细化 FR12-S01 要求披露“时间范围”。本分析按“披露时间范围＋默认窗已声明且可复算”建模，默认窗起止/滚动年数未定义；时间未知成果的排除规则为分析推导（A7）。
4. **B-04 数据类别与缺标识**：BR-IMP-07 只规定“真实/模拟/混合互斥、默认现实网络仅真实合格数据、模拟只可显式演示”。演示模式下模拟与混合是否都可展示、缺标识成果是否单列，属分析推导，需确认。
5. **B-05 无合作学者口径**：模块细化 FR12-S07 允许“不显示”或“单独标注为无合作关系”两选一并要求全站一致；基线未规定。本 UC 按“不虚构连线、不作为有边节点出现”建模并披露处理方式。
6. **B-06 四类角色的“合格证据”门槛**：论文作者（署名与身份核验）、专利发明人（登记证据）、项目参与者（成员名单与承担单位）、获奖个人成员（获奖名单中的个人）各自需要什么证据才算“已核验”；“已批准自动规则或独立人工核验证据”的判定标准未冻结（SPEC §1）。
7. **B-07 机构/领域筛选与最短路径的入口归属**：两者按 IN01 属 UC-15；但模块细化 FR12-S06 的收窄提示举例“加领域或机构条件”。本 UC 不提供筛选，只把该差异登记 07 §5 C-03。
8. **B-08 图版本与上一版结果**：AC-IMPL-IN01-02 要求 IN01 在固定图版本下给出结果，FR12 基线未要求图版本；模块细化 FR12-S08 要求“重建失败保留上一版可用网络”。本 UC 只核对“同一生效关系版本”并标注未更新；是否保留上一版网络见 C-01。
9. **B-09 已排除/待核验关系是否可在页面标注**：AC-IMPL-FR12-04 只要求“不产生边”，FR12-S05 备选 A1 提议以虚线或独立图层提示。本 UC 按“不进入强度与证据清单，只在披露中给出状态名称与数量”建模；是否可视化提示待确认（且不得影响强度）。
10. **B-10 强度是否参与排序/过滤**：基线只要求展示强度与证据；是否按强度排序边、或以“最低强度”过滤未规定。本 UC 不排序、不设强度阈值。
11. **B-11 ACE/多角色参与者的处理**：同一学者在同一成果上有重复角色记录（如既是项目负责人又是参与者）时按 `canonical_id` 去重后仍只计 1（分析推导，FR12-S04 A1 细化）；是否需要在证据清单暴露重复角色待确认。
12. **B-12 与 UC-11/UC-12/UC-13/UC-15 的边界类与协调者命名/合并**：全局只有 `AnalyticsUI ..> GraphCtl`；登记表 `AnalyticsNetworkCoordinator` 覆盖 FR12＋IN01。本 UC 用 `CollaborationNetworkUI`/`CollaborationNetworkCoordinator`，并把“基础建边”与“论文子图筛选/路径”建议在 R5 拆分（07 §2）。
