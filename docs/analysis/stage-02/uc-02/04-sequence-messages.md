## 1. 顺序图范围

本序列只实现 UC-02“查看一条成果的详情与来源”：

- 按稳定成果标识取**一条**当前公开有效成果；
- 取四类适用字段，缺失标“未知”；
- 数据性质与时间语义分开；
- 取该成果**全部可公开来源**（一条成果多条来源）；
- 取有明示证据的版本关系；
- 取作者/参与者角色与状态；
- 按公开/生效/许可过滤后组装详情，只给原站外链；
- 不可访问、执行失败、外链失败三种状态分开；
- 只读，不发出任何写操作。

检索与分页（UC-01）、主页（UC-03）、确认/纠错（UC-08）、治理核验（UC-09/10）、规模核对（UC-16）、统计与网络（UC-11～15）不进入本序列。

## 3. 关键协作说明

### 3.1 公开有效与不可访问（A1）

M3/M4 回答“是否当前公开且生效”。M7/M8 与 M5/M6 分属不同分支：**不可访问**不是**执行失败**，UI 不得用同一文案（BR-UC02-11；`AC-IMPL-NF01-01`）。M5/M6 的失败守卫覆盖 M3–M18 的任一次实体读取失败或超时，不只覆盖 M3；M19 之后不再新增读取。对外是否细分“不存在/无权/待审”属 Q-02，分析层只要求可区分且不泄露字段。

### 3.2 一条成果、多条来源（核心）

- M13/M14 面向 SourceRecord 取该成果下**全部**可公开来源；M20 明确返回“一条成果 + 多条来源”；
- 来源数不改变成果数，`AC-IMPL-FR02-01`（一条成果展示两条来源）与 `AC-IMPL-FR16-02`（按去重实体而非来源数/版本数）在分析层由**单一 WorkEntity 聚合多 SourceRecord** 保证；
- 逐条来源保留自身许可与采集时间（INV-01），协调器不改写来源原值。

### 3.3 缺失字段与时间语义

- M9/M10：类型适用字段按 §7.1 返回；缺失返回“未知”（A4），不补默认值、不推测。
- M11/M12：发生时间、采集/导入时间、更新时间三个语义分开传递；不以采集时间代替发生时间。
- 数据性质随来源与成果分别表达（Q-07 聚合口径未冻结，见 08）。

### 3.4 许可与公开过滤

M19 是分析级统一守卫：待审新值不展示（A8）、无公开许可的来源不进入公开详情（A6）、私有证明材料不公开（BR-IMP-11），并保证只输出原站地址而不输出全文。M19 不替代实体自身的公开状态判断，两者互补。

### 3.5 版本证据门槛

M15/M16 只读取**有明示证据**的版本关系；无证据时回答“无版本关系”，既不显示、也不把两个实体压成一个（A7；DD-08）。

### 3.6 参与角色与状态

M17/M18 取角色（论文作者顺序、专利发明人、项目负责人、获奖人员/团队）与状态。待核验/争议/已排除不得展示为已确认参与（A9）：`AC-IMPL-FR15-03/04`、SRS §6.4、§11.3 的约束在详情侧表现为“不冒充已确认”，本 UC 不改变关系状态。

### 3.7 外链边界与失效

- M21–M23：只提供原站地址；平台不代理、不缓存、不托管全文（FR02；SRS §2.1）。
- M24/M25：原站由外部参与者访问，平台不可控。
- M26–M28：外链失效只影响外链，不删除、不隐藏成果，元数据仍可读。平台**是否主动探测外链可用性**未冻结（Q-01），本序列只保证可观察结果。

### 3.8 只读边界

M1–M28 中没有任何创建/修改/删除业务实体的消息；M28 是“不发出写操作”的保证。确认、补录、纠错（UC-08）与治理（UC-09/10）不在本序列。

## 4. 消息完整性检查

| 检查 | 结果 |
|---|---|
| 每条消息有发送者/接收者 | 是，M1–M28 |
| 接收者有明确职责 | 是 |
| 每条消息可追溯到事件步骤 | 是：E1–E11、A1–A9；A10 并入 A1 分支（类型缺失不得成为公开有效成果），不另设消息 |
| 是否出现实现技术 | 否（无数据库/API/框架/缓存） |
| 是否把 Actor 画成系统类 | 否；访客与原站是参与者，不是系统类 |
| 空/失败/不可访问是否混用 | 否：M5/M6（失败）、M7/M8（不可访问）、M27（外链失败）分离 |
| 是否遗漏“一条成果多条来源” | 否：M13/M14/M20 覆盖 |
| 是否把全文/下载当作系统能力 | 否：只有 M23 地址跳转 |
| 是否出现写/删除消息 | 否；M28 明确不发出删除或隐藏 |
