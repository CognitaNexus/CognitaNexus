> **范围边界：** 本 UC 只处理“已获授权学者对其**已获授权 Scholar** 名下**已收录成果的一条参与关系**作出本人确认；对已收录成果补录可核验的已发表元数据；就误归属或字段错误提出纠错申请；以及有权审核的管理员对这些待审请求作出决定并使其生效”的行为。
> 认领申请与认领审核（产生授权）属 UC-05/UC-06；已授权 Scholar 档案字段维护属 UC-07；来源采集、清洗、去重属 UC-08 之外的 UC-09；身份消歧、同名合并/拆分、把关系**改派到另一位学者**属 UC-09/UC-10（FR15-S10）；合作网络建边与最短路径属 UC-14/UC-15；公开详情/门户展示属 UC-02/UC-03/UC-11；后台审计查询与待办队列属 UC-17；本人普通主页字段编辑属 UC-22。
> 本 UC **不创建** `Scholar`、**不创建/转移** `ScholarAuthorization`、**不创建** `ClaimApplication`、**不新建** `WorkEntity`（不提供论文投稿/出版）、**不删除** `WorkEntity` 或 `SourceRecord`、**不改写**原始来源事实、**不合并/拆分**学者身份、**不建任何合作边**。
>
> **对象区分（本 UC 最重要的边界）：** `WorkEntity` 是去重后的成果规范实体，承载共享字段（类型、题名、标识、载体、时间等），其存在与来源数、参与关系数无关；`Authorship` 是“一位学者 × 一项成果”的**参与关系**，携带角色、顺序、证据与独立确认状态，一位学者在同一成果上只有一条逻辑参与关系（SPEC ID-11）；`Scholar` 是平台采集/核验的学术身份档案，可无账号，同名不等于同人（是否允许多名管理者属 SPEC ID-12 待评审）；`SourceRecord` 是来源侧原始证据（原值、许可、到达时间），只读且永不因人工纠错被改写（INV-01）；`ReviewEvidence` 是提交给审核的材料与可见范围（本人＋有权审核者可见），不是公开字段；`CorrectionRequest` 是一条**待审纠错请求**（未生效内容＋状态＋理由＋证据引用），与已生效的成果字段、关系状态**并存且可区分**，也不是 `AuditEvidence`（已发生动作的留痕）。

## 1. 参与者

| 类型 | 参与者 | 说明 |
|---|---|---|
| 主要参与者 | 已获授权学者（用例图中“门户管理者”） | 已登录、账号可用，且对**目标 Scholar** 持有有效 `ScholarAuthorization`；只能确认/申请修改**自己的**参与关系，只能在该授权范围内补录成果元数据 |
| 次要参与者 | 有权审核的管理员 | 在待审纠错请求产生后参与：复核证据、作出批准/驳回决定，使请求生效或不生效（FR07 参与者“审核管理员”；§11.4“FR15处理方包括相关学者和管理人员”；FR14 边界） |
| 只读边界 | 访客/登录用户 | 只能读取**当前生效**的公开成果与参与关系状态说明；本 UC 只保证“待审不公开、已排除不入合作边”，读侧展示属 UC-02/UC-03/UC-14 |

> 不引入审核员等级、审批链、SLA、申诉或“争议仲裁庭”：基线只区分“是否具备对应审核权限”（FR14；NF03）。争议处置队列的载体属 FR14/UC-17，本 UC 只把关系置为“争议”并记录提出方与证据。

## 2. 目标

已获授权学者在服务端授权校验、状态优先级与审计约束下，对本人名下的已收录成果完成三件事：**确认**一条待确认的参与关系、**补录**可核验的已发表成果元数据、**申请纠正**误归属或错误字段；并保证：只改自己的参与关系、共享字段与他人的关系必须审核、解除后成果与来源及其他关系保留、单次确认不扩散、待核验/争议/已排除不成为确定合作边、全过程可追溯。

## 3. 触发事件

已获授权学者打开本人成果关系视图并选定目标成果与本人参与关系，提交“确认本人关系 / 补录已发表元数据 / 申请修改误归属或字段”；或（待审已存在时）查询本人请求的处理过程；或有权审核的管理员对一条待审纠错请求作出决定。

## 4. 前置条件

1. 请求者已登录且账号状态可用；身份、账号状态与权限由服务端每次校验（NF03；`AC-IMPL-NF03-01`；SRS §8）。
2. 目标 `Scholar` 是平台**已收录**的学者档案，且请求者对其持有**有效** `ScholarAuthorization`；该授权只能由 UC-06 在无冲突批准后产生（FR05；`AC-IMPL-FR05-02`；BR-IMP-05；SPEC ID-07）。
3. 目标 `WorkEntity` 是平台**已收录**成果（FR07 标题“已收录成果确认、补录与纠错”）；本 UC 不新建成果实体，不提供投稿/出版（FR07 规范性要求“不提供论文投稿或出版功能”；`AC-IMPL-FR07-03`）。
4. 目标 `Authorship` 已存在并归属该 `Scholar`（由采集/治理建立，状态为 `自动关联/本人确认/待核验/争议/已排除` 之一）；`WorkEntity` 至少保留一条可追溯来源 `SourceRecord`（FR15-S07；`DGM-STATE-05`；BR-354）。
5. 同一学者在同一成果上的参与关系是**一条逻辑关系**，重复证据归入该关系而非新建（SPEC ID-11）。
6. 待审请求的审核证据最低集合、共享字段清单与可直接确认的关系状态集合尚未冻结（B-01～B-05）；本 UC 不预设结论，只保留可观察分支。

## 5. 成功与失败后置条件

### 5.1 成功（本人确认生效）

1. 被确认的那**一条** `Authorship` 状态置为 `本人确认`，并追加“本人确认”证据事件（确认人/时间/范围）；原有来源证据保留（FR15-S08；`DGM-STATE-05`；SPEC ID-06/ID-10）。
2. 该 `Scholar` 在同一成果或其他成果上的**其余**候选署名关系状态**不变**：不因本次确认升级为本人确认（`AC-IMPL-FR15-06`；SPEC ID-06/ID-07；§11.3）。
3. 未修改 `WorkEntity` 的共享字段、未修改其他学者的 `Authorship`、未新增/删除对象。
4. 受控审计记录确认人、对象、前后状态、时间；不含凭据与材料原文（BR-IMP-10；INV-10；NF03）。
5. 该关系由 `自动关联/待核验` 进入 `本人确认`；它能否满足 FR12“经核验的合法共同参与关系”的建边资格由 UC-14 按 BR-IMP-08 与 §6.4 判定，本 UC 不建边、不计算强度。

### 5.2 成功（补录/纠错请求进入待审）

1. 生成一条 `CorrectionRequest`：目标成果、涉及的本人员关系（如有）、请求类型、字段级旧值/新值、理由、提交者、证据引用、状态 `待审核`、状态版本与提交时间。
2. 该请求的证据材料登记为 `ReviewEvidence`，可见范围为提交者本人与有权审核者（BR-IMP-11；NF06；`AC-IMPL-NF06-01`）。
3. **公开字段与关系状态保持旧值**：成果详情、检索、门户、统计与合作网络仍读取生效值，待审内容不进入公开视图（`AC-IMPL-FR07-02`；BR-IMP-01/10；§6.4）。
4. 提交者可查询本人请求的状态、决定理由与“公开未变更”事实（`AC-IMPL-FR07-02`“处理过程可查”）。
5. 原始来源事实未被改写；公开规范值与审核记录独立保留（§7.2；BR-IMP-04；INV-01）。
6. 审计留痕（待审登记）。

### 5.3 成功（审核通过并生效）

1. **字段类**：仅批准范围内的共享字段写入生效规范值；未批准字段、原始来源事实与其他字段保持原值（`AC-IMPL-FR07-02`；`AC-IMPL-FR15-02`；BR-IMP-04）。
2. **解除类**：仅该条 `Authorship` 状态置为 `已排除`；`WorkEntity` 仍存在、全部 `SourceRecord` 保留、其余合法 `Authorship` 状态不变；该学者门户不再展示该成果，其他学者门户不受影响（`AC-IMPL-FR07-01`；FR15-S11；BR-359；SPEC ID-09/INV-05）。
3. 请求状态置 `通过`，记录决定者、理由与时间；请求依据标注“来自学者申请”（FR15-S10 A3；BR-IMP-10）。
4. 生效后检索、门户、统计与合作网络采用同一生效关系/值，不展示待审关系（NF05；`AC-IMPL-NF05-01/02`；BR-IMP-10；FR15-S12）。
5. 审计保留前后值与历史证据；已排除关系不得被后续来源自动恢复（BR-IMP-04；`AC-IMPL-FR15-04`；INV-05）。

### 5.4 成功（审核驳回）

1. 请求状态置 `驳回`，记录理由、决定者与时间（FR15-S11 E4；`AC-IMPL-FR07-02`）。
2. 公开字段与关系状态**完全不变**；提交者可查询驳回原因（`AC-IMPL-FR07-02`；FR15-S11 E4）。
3. 审计留痕（驳回与“公开值不变”）。

### 5.5 失败（无业务写入）

1. 目标 `Authorship` 状态、`WorkEntity` 公开字段与任何待审请求状态保持原值。
2. 不新建 `WorkEntity`/`Authorship`/`ScholarAuthorization`/`ClaimApplication`，不删除成果与来源，不改写原始来源事实。
3. 未认证/停用、越权（他人学者关系、无有效授权）、越界（修改他人关系）被服务端拒绝并保留受控审计（`AC-IMPL-NF03-01`；BR-IMP-05；SRS §8）。
4. 状态不允许（已排除/争议）、证据不可核验、写入失败、请求已被处理或版本已变化时，不返回成功、不显示为已生效（分析推导；§6.4；INV-10）。
5. 拒绝、越权、不可核验、失败、待审、已生效六类结果可区分（NF01“加载、空结果、错误、越权和处理中可区分”；分析推导）。

## 6. 基本事件流

> 基本流把 `AC-IMPL-FR07-01/02` 锚定的“申请 → 待审 → 决定 → 生效”与 `AC-IMPL-FR15-06` 锚定的“本人确认”放在同一次分析交易中；可直接生效的只有“本人确认本人关系”一项，共享字段、误归属与解除一律经审核（B-04 未冻结“可直写字段清单”，故不把字段直写放入基本流）。

| 步骤 | 事件 | 需求/规则来源 |
|---:|---|---|
| E1 | 已获授权学者打开本人成果关系视图，选定目标成果与本人参与关系，选择操作：确认本人关系 / 补录已发表元数据 / 申请修改误归属或字段。 | FR07“本人可确认待选成果关系、录入可核验的已发表成果元数据、申请修改误归属/字段”；`DGM-USECASE-05`（门户管理者 → UC-08；有权管理员 → UC-08）；§11.4 |
| E2 | 系统在服务端校验请求者身份与账号状态，确认是可用账号发起的受保护写入。 | NF03；`AC-IMPL-NF03-01`；SRS §8 |
| E3 | 系统读取请求者对该目标 Scholar 的有效对象级授权与授权范围。 | FR05；`AC-IMPL-FR05-02`；BR-IMP-05“Scholar档案仍要求对象级认领管理授权”；SPEC ID-07 |
| E4 | 系统确认目标学者正是授权所指学者，读取所选 `Authorship`（含归属学者、归属成果、角色、顺序、状态与冲突标记），确认该关系属于本学者且只涉及这一条关系。 | FR07“只修改自己的参与关系不影响他人”；BR-353“同一成果上不同参与者不得合并为一条关系”；SPEC ID-05/ID-11 |
| E5 | 系统判定本次操作类型（确认 / 补录 / 纠错）与对象范围（本人关系字段 / 成果共享字段 / 他人参与关系）。 | FR07“共享字段和争议归属进入审核”；§7.1；BR-IMP-05 |
| E6 | [确认] 系统执行状态守卫：该关系不是 `已排除` 或 `争议`、无未决相反归属主张、确认范围覆盖本关系、且仅作用于本关系。 | §6.4“学者成果关系在自动关联、本人确认、待核验、争议、已排除中有确定有效状态”；BR-356；`DGM-STATE-05`；`AC-IMPL-FR15-04/06` |
| E7 | [确认] 系统为该关系追加“本人确认”证据（确认人/时间/范围）并把状态置为 `本人确认`；不改变其余候选关系。 | FR15-S08 主流程 1–3；`DGM-STATE-05`“自动关联／待核验 → 本人确认”；`AC-IMPL-FR15-06`；SPEC ID-06 |
| E8 | [确认] 系统记录本人确认审计并返回结果：“本条关系已确认、其余候选关系不变”。 | BR-IMP-10；SPEC ID-10/INV-10；`AC-IMPL-FR15-06` |
| E9 | [补录/纠错] 系统读取成果当前公开字段与共享字段现值，判定拟改字段属于共享字段、本人关系字段还是他人关系。 | FR07“共享字段和争议归属进入审核”；§7.1（成果字段）；BR-IMP-04（人工确认值不被静默覆盖） |
| E10 | [补录/纠错] 系统只读读取该成果的来源事实，核验补录元数据是否可追溯，并判定最低字段是否齐备（缺失不造值）。 | FR07“可核验的已发表成果元数据”；§7.1“不存在的专属字段标未知，不造默认值”；SPEC CL-01/CL-08；BR-IMP-02 |
| E11 | [补录/纠错] 系统登记一条待审纠错请求（类型/目标/前后值/理由/证据引用/提交者/状态 `待审核`/版本）；公开字段与关系状态保持旧值。 | FR07“进入审核”；`AC-IMPL-FR07-02`“审核未通过→公开旧值不变”；BR-IMP-10“待审不替代公开版本”；§6.4 |
| E12 | 系统登记该请求的证据材料与可见范围，记录待审登记审计，并返回“已提交待审、公开未变更、本人可查”。 | BR-IMP-11；NF06；`AC-IMPL-FR07-02`“处理过程可查”；BR-IMP-10 |
| E13 | [次要参与者] 有权审核的管理员打开待审请求并提交决定（批准/驳回）与理由；系统再次在服务端校验其身份、账号状态与审核权限，并读取待审内容与证据。 | FR07 参与者“审核管理员”；§11.4；FR14（关键批准/拒绝记录原因）；NF03；`AC-IMPL-NF03-01` |
| E14 | [批准] 系统应用生效：字段类仅写入批准范围内的共享字段生效规范值（来源原值保留）；解除类仅把该条关系置为 `已排除`，成果实体、全部来源与其余合法关系保留。 | `AC-IMPL-FR07-01`；`AC-IMPL-FR15-02/05`；FR15-S11/BR-359；SPEC ID-09/INV-05；§6.4 |
| E15 | 系统记录决定与生效审计，返回结果，并使检索/门户/统计/合作网络采用同一生效关系，待审内容不进入公开视图。 |
| E16 | 本人查询自己提交的补录/纠错请求的状态、决定理由与公开是否变更。 | `AC-IMPL-FR07-02`“处理过程可查”；NF06；BR-IMP-11 |

> 步骤 6–8 是“本人确认只改变一条关系且不扩散”的分析级组合；步骤 9–15 是“共享字段/解除必须先待审、通过才生效、生效后跨视图一致”的分析级组合。此处只定义业务约束，不指定事务、锁、并发或消息实现。

## 7. 备选/异常流

| 编号 | 条件 | 系统行为 | 依据 | 说明 |
|---|---|---|---|---|

## 11. 待确认

1. **B-01 待审纠错请求的状态集合**：FR07 与 §6.4 只要求“进入审核”，未定义该请求是否含 `待补充`、`争议` 或 `已撤回`；本分析按 `待审核 → 通过/驳回` 建模，并把“多发并存/并发冲突”按版本守卫处理，具体状态机待确认（亦影响 A9）。
2. **B-02 本人可直接确认的关系状态集合与“确认范围”判定**：`DGM-STATE-05` 与 FR15-S08 要求“确认范围覆盖本关系”，但“范围”如何表达、`待核验` 关系在何种冲突条件下可直接确认未冻结；本分析只保留“无冲突才可直接确认，有冲突转争议”的可观察分支。
3. **B-03 补录可覆盖的成果范围**：本分析按 FR07 标题与 `AC-IMPL-FR07-03` 判定“只对已收录成果补录、不新建 `WorkEntity`”；若评审允许学者为未收录的已发表成果补录并新建实体，则 A14 与 E9–E11 需增加“新建成果候选 + 去重/治理”分支（与 UC-09 边界重划）。
4. **B-04 共享字段清单与可直接生效字段清单**：FR07 只说“共享字段…进入审核”；哪些 `WorkEntity` 字段属共享字段（题名/标识/载体/时间/作者顺序）、哪些可由本人补录后直接生效未冻结。本分析把共享字段类请求一律纳入审核（基本流），不设字段直写分支。
5. **B-05 审核证据最低集合与“可核验”判定口径**（已登记 D-06）：影响 A5 的判定与 M36 的结论；本分析只要求“可追溯到来源记录或材料”，不定义最低集合。
6. **B-06 解除/纠错审核的责任人、SLA 与超时兜底**：§11.3 只规定“超时仅发提醒、不自动批准”，未定义责任人与时限（D-06）；本分析只保证“超时不等于通过”。
7. **B-07 生效传播口径与时限**：NF05 明确历史 60 秒目标不在本轮量化清单；本分析只要求“最终一致、不展示待审关系”。
8. **B-08 归属改派/拆分的入口分工**：FR15-S10 的关联用例同时列 UC-08 与 UC-10；本分析把“改派到另一位学者/拆分档案”判为 UC-10 处置（A11），UC-08 只保留申请与状态；若评审要求 UC-08 内完成改派，则需增加处置与传播消息。
9. **B-09 会话/凭据是否成为独立分析对象**（沿用 UC-04/UC-07 B-08）：本 UC 作为请求上下文，不建模。
10. **B-10 命名与追踪**：`AchievementCorrectionUI`/`AchievementCorrectionCoordinator` 与全局 `ScholarPortalUI`/`GovernCtl`；`CorrectionRequest` 与 UC-07 `ScholarChangeRequest`、UC-05 `ClaimApplication`；`ReviewEvidence`/`AuditEvidence`/`SourceRecord` 的统一；追踪表是否增补 `SEQ-13/VOPC-09` —— 均留 R5（D-11/D-13）。
