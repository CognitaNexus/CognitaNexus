# UC-08 分析类职责、属性、关系与分析机制

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.5.1 职责、§5.5.2 属性、§5.5.3 关系、§5.5.4 分析机制。
**范围：** 只定义 UC-08 能够证实的部分；跨用例统一关系不在此擅自补齐。

## 1. 定义原则

1. “做（Do）”型职责说明对象能执行/协调什么；“知道（Know）”型职责说明对象必须知道/提供什么。
2. 属性只写业务信息，不写数据库字段、主键类型、索引或 API 参数。
3. 关系只写有消息或正式业务约束支持的；无依据的跨用例关系留待 R5。
4. 控制类没有长期业务属性；其请求上下文是单次用例的分析状态。
5. 共享字段清单、待审请求状态集合、可直接确认的关系状态集合、审核证据最低集合等未冻结项不伪装成类定义，统一标 `待确认`（B-01～B-10）。

## 15. 与其他 UC 的边界

- **UC-05/UC-06**：认领申请与审核是授权的唯一来源；本 UC 只读授权，不创建、不转移、不撤销。
- **UC-07**：`Scholar` 档案字段（身份/机构/归属声明）维护属 UC-07，使用 `ScholarChangeRequest`；本 UC 不写档案字段、不复用该待审对象。
- **UC-02/UC-03/UC-11**：成果与门户的公开读取与展示由消费方实现；本 UC 只保证“待审不入公开、解除后成果仍存在”。
- **UC-09/UC-10**：清洗/去重（含版本与重复到达）与身份消歧、归属改派/拆分不在本 UC；A11 明确转交。
- **UC-14/UC-15**：合作边、强度与论文子图由消费方按“经核验的合法参与关系”计算；本 UC 只产出生效关系状态。
- **UC-17**：审计查询、待办队列与争议结案在 UC-17；本 UC 只写入审计与请求状态。
- **UC-22**：普通主页字段编辑属 UC-22；本 UC 不写普通资料。
