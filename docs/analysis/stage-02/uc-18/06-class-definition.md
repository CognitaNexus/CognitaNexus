# UC-18 分析类职责、属性、关系与分析机制

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.5.1 职责、§5.5.2 属性、§5.5.3 关系、§5.5.4 分析机制。
**范围：** 只定义 UC-18 能够证实的部分；跨用例统一关系不在此擅自补齐。

## 1. 定义原则

1. “做（Do）”型职责说明对象能执行/协调什么；“知道（Know）”型职责说明对象必须知道/提供什么。
2. 属性只写业务信息，不写数据库字段、主键类型、索引或 API 参数；批次、检查点、进度、计数的实现口径不在分析层定义。
3. 关系只写有消息或正式业务约束支持的；属主 UC 已定义的关系不重复画。
4. 控制类没有长期业务属性；启动守卫、完成判据、进度与计数核对都是单次用例的分析状态。
5. 重试上限、检查点间隔、批次大小、计划输入口径、计数口径与“结果”边界未冻结，一律标 `待确认`（B-01～B-09），不写成类定义里的既定规则。
