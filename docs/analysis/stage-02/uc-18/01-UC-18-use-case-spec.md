> **范围边界：** 本 UC 只处理“**配置获准来源定义**”与“**采集任务的创建、启动、进度、停止、失败恢复与重试**”两件事，并把每条计划输入**记录到结果或异常队列**。
> 来源更新与增量变更、来源停用/更换属 UC-19；成果清洗、去重、版本与字段冲突处置属 UC-09；学者身份与成果归属判定属 UC-10；认领审核属 UC-05/06；后台待办与审计查询属 UC-17；发布与公开可见性属治理与读侧（UC-01/02/03/11/14/15/16）。
> 本 UC **不判定去重/身份/归属**、**不创建或更新 `WorkEntity`/`Authorship`/`Scholar`**、**不发布任何数据**、**不改写来源原值**、**不删除历史**；也**不建立调度器、任务队列、作业运行器、重试策略或异常队列类**。

> **对象区分（本 UC 的核心边界）：**
> - `SourceDefinition` 是**来源配置事实**：来源身份、输入方式（API 或文件，二选一）、许可/使用范围、数据性质（真实/模拟/混合）、允许范围。它回答“这条来源是否获准、以什么方式、在什么范围内可采集”，**不是**已到达的记录。
> - `SourceRecord` 是**到达证据**：来源身份、逻辑出处（`source_id`＋`source_record_key`）、到达事件、原始字段值、数据性质、许可与到达时间；原值不可改写，重复到达追加到达事件（INV-01；FR09-06）。
> - `CollectionTask` 是**一次执行的状态与历史**：六状态（待执行/运行中/成功/失败/已停止/重试）、参数快照、检查点、每次尝试的任务历史与处置计数；它不是调度器、线程或队列。
> - `GovernanceException` 是**待处置异常项**：原因、对象引用、待处理状态；它**不是**成果、不是公开数据、不是审核留痕，本 UC 不为它设公开可见性。
> - `GovernanceCoordinator` 是**属主 UC-09/10 的协作控制类**：本 UC 只逐条移交并取回“处置结果/需异常移交”，不建模清洗、去重与身份归属规则。
> - `SourceAdapter` 是**与获准来源交换记录与失败信息的边界类**：只请求/接收记录与失败反馈，不决定公开、归属或去重；`AdminConsole` 接收采集管理交互，不代替服务端授权。

## 1. 参与者

| 类型 | 参与者 | 说明 |
|---|---|---|
| 主要参与者 | 管理员（具备“数据来源/采集”具体管理权限） | 配置来源定义、创建/启动/停止/重试任务、查看进度与任务历史（FR08 参与者“管理员”；§8 权限表“数据来源/采集｜管理员｜具体管理权限”；`DGM-USECASE-03` actor“管理员”） |
| 次要参与者（外部） | 获准数据来源（API 或文件形式） | 按许可与允许范围提供记录或失败反馈；一期只验证两种独立且获准的来源输入（FR08 规范性要求；`DGM-USECASE-03` actor“外部数据来源”） |
| 协作方（图外，属主 UC-09/10） | 治理处理 | 接收逐条移交并返回“已登记结果/待核验”或“需异常移交”与原因；清洗/去重/身份归属规则不属本 UC（FR09/FR15） |
| 次要参与者（负向） | 未授权请求者（未认证/停用账号/普通登录用户） | 提交采集操作一律拒绝且**无业务变更**（FR08 执行前提“权限失败不得修改任何业务实体”；§8；NF03 边界） |
| 只读被查询对象 | 来源定义、来源记录、任务、异常项、留痕 | 本 UC 只读或只按采集职责写入；不改写原值、不删除历史、不发布（见 05 §2） |

> 不把“系统”画成参与者：系统职责由 `AdminConsole`/`SourceAdapter`/`CollectionCoordinator` 实现。不引入调度器、队列、作业运行器等实现角色；`DGM-USECASE-03` 已明确“系统、调度器不作为外部参与者”。

## 2. 目标

让有“数据来源/采集”具体管理权限的管理员能够登记**已获准**的来源定义（两种独立来源，API 或文件任选其一），按该定义创建与启动采集任务，在运行中查看进度与检查点，必要时停止、失败恢复与重试；并在批次结束时以**计划输入全部记录到结果或异常队列**为唯一成功判据，**单列**待核验与异常数量，明确“任务成功 ≠ 人工治理完成 ≠ 已公开”。异常项不得直接成为公开成果；重试保留历史成功记录、可定位失败点且不产生重复实体。

## 3. 触发事件

1. 管理员打开采集管理入口，登记或确认一个已获准来源的接入定义；
2. 管理员基于来源定义创建采集任务并请求启动；
3. 管理员在运行中查询进度，或在失败/停止后请求重试、查询任务历史与失败定位；
4. 未授权请求者提交采集操作（触发拒绝路径，不改变任何业务状态）。

## 4. 前置条件

1. 请求方已认证、账号状态可用；每次请求在服务端校验“数据来源/采集”具体管理权限，入口可见不构成授权（§8；NF03；`AC-IMPL-NF03-01` 边界）。
2. 来源**已获准**且其许可/使用范围与数据性质可声明；一期只验证两种独立来源输入（API/文件任选），该来源的接入声明可定位（FR08；FR16；INV-09）。
3. 输入方式为已支持的一种（API 或文件）；具体协议、文件格式、字段映射、分页/游标未冻结（D-10；B-03）。
4. 本次**计划输入范围**可在启动时确定并保存为可核对快照；其口径（清单快照还是可枚举范围）未冻结（B-04）。
5. 任务的既有状态允许启动/重试：成功或已停止的任务不再推进，须另建关联任务；失败只能经重试恢复（§6.2；`DGM-STATE-01`）。
6. 治理处置规则（清洗/去重/身份归属）属 UC-09/10；本 UC 只移交与计数，不判定（FR09/FR15）。

## 5. 成功与失败后置条件

### 5.1 成功（任务成功）

1. **成功根因唯一**：每条计划输入都已记录到“结果”（已交治理受理并登记处置结果）或“异常队列”（`GovernanceException` 待处理）；治理交接失败、存在未记录项或异常项未建立均不得成功（§6.2；M54–M58；A5）。
2. 返回互斥处置计数，并**单列**待核验数量与异常数量（`AC-IMPL-FR08-01`；FR08 规范性要求）。
3. 结论措辞受约束：不得表述为“人工治理已完成”“全部已核验”“全部公开”（FR08；§6.2；BR-UC18-08）。
4. 任务历史追加本次尝试（起止、范围快照、检查点、处置计数、结论），受保护写入留痕含操作者/对象/时间/前后值/理由（§6.2；BR-IMP-10；INV-10）。
5. 不创建或更新 `WorkEntity`/`Authorship`/`Scholar`，不发布任何数据，不改写 `SourceRecord.rawValues`（INV-01/02；BR-IMP-01/02；A11）。

### 5.2 成功（配置、进度、停止、重试、历史）

1. 来源定义保存后可作为启动前置被读取；其可用性判定（已获准∧输入方式已支持∧许可与范围可声明∧数据性质可标识）可复核（M10–M12）。
2. 进度查询只读返回状态、检查点、已读/已登记结果/待核验/异常计数，**不推进状态、不改计数**（M46–M53；A13）。
3. 停止按“先生效”裁定：停止决定先于完成生效则运行中→已停止，保留已完成项与未完成范围（§6.2；`DGM-STATE-01`；M63–M69）。
4. 重试从失败点/检查点续跑，不重做已完成项，历史成功记录与任务历史保留，失败点可定位（`AC-IMPL-FR08-02`；INV-07；M74–M84）。
5. 任务历史查询只读返回尝试次数、起止、结果、失败点、检查点、计数与关联留痕（NF07-01；M87–M94）。

### 5.3 失败（无业务写入、无历史删除）

1. 未认证/停用/无“数据来源/采集”具体权限：拒绝，不返回来源定义与任务明细，业务实体状态不变，受控拒绝留痕不含凭据（A1；M95–M100；§8；NF03）。
2. 来源无效、输入方式未支持、许可/范围无法声明、计划输入不可确定：拒绝保存或拒绝启动，不创建运行中任务、无业务写入（A2/A8；M10/M22/M30）。
3. 读取失败、断连或来源反馈异常：任务失败，保存失败点、已成功结果与恢复范围；已收录数据仍可查询，历史成果不删除（A4；M70–M73；BR-IMP-04；NF04-01/NF07-01 边界）。
4. 异常项保持待处理，不进入公开可见状态、不被计为成功结果；异常项缺失（不可追踪移交）同样使任务失败（A5/A11；M41–M43/M56–M58）。
5. 空范围、失败、拒绝、无权限四类结果可区分，不互相冒充（NF01 类比；BR-UC18-14）。

## 6. 基本事件流

> E11–E15 按“批次×记录”循环，直到计划输入处理完、任务失败或被停止（`repeat` 语义，见图）。E16/E19 可在运行中或结束后按需触发，且只读。

| 步骤 | 事件 | 需求/规则来源 |
|---:|---|---|
| E1 | 管理员打开采集管理入口（来源与任务）。 | FR08“支持配置来源、启动、进度、停止、失败恢复和重试”；§8；`DGM-USECASE-03` |
| E2 | 系统在服务端校验账号状态与“数据来源/采集”具体管理权限，每次请求重新校验；入口可见不构成授权。 | §8 权限表“数据来源/采集｜管理员｜具体管理权限”；NF03；A1 |
| E3 | 管理员提交/确认来源定义：来源身份、输入方式（API 或文件，二选一）、许可/使用范围、数据性质（真实/模拟/混合）、允许范围。 | FR08“两种独立且获准来源输入（API/文件任选）…配置来源”；FR16“每条来源保留来源ID、采集/导入时间、许可或使用范围与数据性质”；INV-09 |

| E6 | 管理员按该来源定义创建采集任务并请求启动，声明本次计划输入范围。 | FR08“启动”；§6.2；B-04 |
| E7 | 系统只读读取来源有效性与许可/允许范围，并检查该来源是否已有未结束任务（成功/已停止后须另建关联任务）。 | §6.2；`DGM-STATE-01` 图例“成功/停止后另建关联任务”；FR10 边界（B-06） |

| E9 | 系统保存参数快照与初始检查点，创建任务（待执行），追加任务历史并记录启动决定留痕。 | §6.2“每次重试保留检查点与任务历史”；`DGM-STATE-01`；BR-IMP-10 |

| E11 | 系统按参数快照与来源定义读取本批输入（API 或文件），外部来源返回记录或失败反馈。 | FR08；B-03（格式/分页待确认）；A4 |
| E12 | 系统逐条登记 `SourceRecord`：来源身份、到达事件、原值、数据性质、许可与到达时间；重复到达追加事件而不新增第二条逻辑出处。 | INV-01；FR09-06；CL-10 类比；A12 |

| E14 | 对无法处置的记录建立 `GovernanceException`（原因、对象引用、待处理状态），不设公开可见性、不创建成果。 | `AC-IMPL-FR08-01`“异常不得直接成为已公开成果”；BR-IMP-01/02；INV-02；A5/A11 |

| E17 | 批次结束核对：每条计划输入是否都已记录到结果或异常队列；交接失败或未记录项不算完成。 | §6.2“只有计划输入都记录到结果或异常队列后才可成功”；A5 |
| E18 | 核对通过：运行中→成功，单列待核验与异常数量并声明“不代表人工治理完成”。 | `AC-IMPL-FR08-01`；FR08 规范性要求；§6.2 |
| E19 | 管理员查看任务历史与失败定位；系统只读返回状态、检查点、尝试历史、失败点与关联留痕。 | NF07-01“管理员可从日志定位任务错误”；§6.2“保留检查点与任务历史”；BR-IMP-10 |

## 7. 备选/异常流

| 编号 | 条件 | 系统行为 | 依据 | 说明 |
|---|---|---|---|---|
| A1 | 未认证、账号停用，或请求者无“数据来源/采集”具体管理权限 | 拒绝；不返回来源定义与任务明细；**无任何业务写入**；拒绝与越权尝试留痕（不含凭据）；结果与失败/空结果可区分 | FR08 执行前提；§8；NF03；`AC-IMPL-NF03-01` 边界；NF01 类比 | 本 UC 的负向权限验收；不主张替代 UC-17 对 `AC-IMPL-FR14-01` 的覆盖 |
| A2 | 来源未获准、输入方式不在已支持范围、许可/允许范围无法声明、数据性质无法标识 | 拒绝保存来源定义或拒绝启动；不创建运行中任务；说明缺失项 | FR08；FR16；§7.1；INV-09 | 不为未知许可/性质填默认值 |
| A3 | 管理员请求停止，且停止决定先于完成生效 | 运行中→已停止；保留已完成项与未完成范围；记录停止决定；已停止为终态，仅可另建关联任务 | §6.2；`DGM-STATE-01`“停止［先于完成生效］”“停止与完成按先生效裁定” | 已完成的处置不因停止回滚 |

## 11. 待确认

1. **B-01 重试上限**（D-10）：基线只要求“失败恢复和重试”，未定义次数上限与耗尽后的处置；本分析只写“未超过上限”（M79；A7），不写数值。
2. **B-02 检查点间隔与批次大小**（D-10）：§6.2 只要求“保留检查点与任务历史”，未定义检查点频率、批次规模与恢复粒度；本分析只要求“检查点可定位、可续跑”，不指定实现口径。
3. **B-03 来源接入的 API/文件格式、字段映射、分页/游标**（D-10）：属接口与实现设计；本分析只用 `inputType` 表达“API 或文件任选”，不定义协议。
4. **B-04 “计划输入”的确定口径**：一次性清单快照、可枚举范围还是一次读取窗口未冻结；本分析按“启动时保存可核对的范围快照”处理（分析推导），若评审要求必须枚举清单，只改守卫判定不改类集合。
5. **B-05 计划输入为空（零条）是否算成功**：§6.2 的完成判据对空集合未定义；本分析按“拒绝启动/明确空范围，不冒充成功”处理（A8），标 `待确认`。
6. **B-06 来源配置的停用/更换归属**：UC-17 的 B-08 已把“来源停用/更换”登记给 FR10/UC-19；本分析据此只读取来源有效性、不执行配置停用/更换；若评审决定归 UC-18，需新增配置状态与转移（本包不预建）。
7. **B-07 任务历史与检查点的保留期限、可查范围**（与 D-09 审计保留联动）：未冻结；本分析只要求“保留并可查”，不承诺时间窗。
8. **B-08 进度与计数口径**：按记录数还是按批次计数、待核验与异常是否合并展示、进度刷新时点均未定义；本分析只要求“互斥计数＋单列待核验/异常＋只读”。
9. **B-09 “结果”的边界**：§6.2 的“记录到结果”是否等价于“治理已受理并登记处置结果”未逐句定义；本分析按“移交受理并取得处置结果”处理（E13/E17），标 `待确认`。
10. **B-10 `GovernanceCoordinator` 的命名与粒度**：`01-BCE` §3 用 `GovernanceCoordinator`；UC-09 用 `DedupCoordinator`、UC-10 用 `IdentityVerificationCoordinator`。本 UC 只把它作为协作控制类引用，命名统一留 R5（D-11）。
11. **B-11 命名与追踪**：全局 `Task`/`CollectCtl`/`Evidence` 与本包 `CollectionTask`/`CollectionCoordinator`/`AuditEvidence`/`GovernanceException` 的差异；`CollectionTask`/`SourceDefinition`/`GovernanceException` 未登记于 `analysis-class-registry.md`；追踪表是否增补 `SEQ-17/VOPC-13` —— 均留 R5/父 Agent（见 07 §6）。

> 停止转移说明：`DGM-STATE-01` 还定义 `待执行→已停止`、`重试→已停止`；本 UC 的顺序图只展开运行中→已停止这一条，其他停止入口沿用冻结状态图，不新增迁移。
