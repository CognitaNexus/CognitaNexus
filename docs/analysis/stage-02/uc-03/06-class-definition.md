# UC-03 分析类职责、属性、关系与分析机制

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.5.1 职责、§5.5.2 属性、§5.5.3 关系、§5.5.4 分析机制。
**范围：** 只定义 UC-03 能够证实的部分；跨用例统一关系不在此擅自补齐。

## 1. 定义原则

1. “做（Do）”型职责说明对象能执行/协调什么；“知道（Know）”型职责说明对象必须知道/提供什么。
2. 属性只写业务信息，不写数据库字段、主键类型、索引或 API 参数。
3. 关系只写有消息或正式业务约束支持的；无依据的跨用例关系留待 R5。
4. 控制类通常没有长期业务属性；其请求上下文是单次用例的分析状态。
5. 未冻结项（公开字段集合、空态文案范围、待核验展示口径、状态标签口径）不伪装成类定义。

## 3. PublicProfileCoordinator（Control）

| 项目 | 定义 | 依据 |
|---|---|---|
| 类型 | Control | §5.4.2；M3–M5/M7/M9–M13/M15/M17/M19/M21–M24/M26 |
| Do | 按稳定标识解析目标对象类型；校验公开可访问；分支读取 `UserProfile` 或 `Scholar`；读取生效参与关系与成果展示字段；统一执行公开/生效/许可过滤与关系状态守卫；分离空态/不可访问/失败；返回单一对象公开视图 | E2–E9；A1–A8 |
| 候选分析操作（`/`） | `/解析目标对象`、`/校验公开可访问`、`/读取公开主页`、`/判断零成果`、`/读取学者档案`、`/过滤公开与关系状态`、`/返回公开视图` | M3–M26 |
| Know | 本次请求的稳定标识、已解析的对象类型、公开可访问判定、分支读取结果、状态标签与返回结果 | 分析推导 |
| 业务属性 | 无长期业务属性。分析级状态：查看请求上下文、对象类型判定、公开过滤结果、关系状态过滤结果（均为单次用例状态） | §5.5.2；不指定实现存储 |
| 关系 | 与 `PublicProfileUI`、`UserProfile`（M9/M11）、`Scholar`（M17）、`Authorship`（M19）、`WorkEntity`（M21）的单向关联（按消息方向） | 04 消息表；VOPC |
| 不能承担 | 不承载公开主页资料（`UserProfile` 的 Know）；不承载学者身份事实（`Scholar` 的 Know）；不改写关系状态；不是实现层 Controller/Service | §5.4.1；§5.5.1 |
| 分析机制 | 按稳定标识解析、禁止同名合并；公开/生效/许可过滤；关系状态不冒充；三态分离；只读 | `AC-IMPL-FR03-02/04`；BR-IMP-01/03；`AC-IMPL-NF01-01` |

**待确认：** 待核验关系是否以标签公开（Q-04）；不可访问的对外粒度（Q-05）；认领/核验状态标签口径（Q-06，R5 统一）。

## 9. 分析机制汇总

| 机制 | 作用对象 | 业务问题 | 本 UC 可证实的约束 | 未决定/后续 |
|---|---|---|---|---|
| 持久性 | UserProfile、Scholar、Authorship、WorkEntity | 主页/档案/关系/成果必须可被反复公开读取 | 对象存在即可公开读取，不要求登录 | 存储粒度/保留期 |
| 稳定标识解析 | PublicProfileCoordinator | 同名对象不得被合并或误跳 | 只按稳定标识解析单个对象，不按姓名查找 | 地址格式/失效策略属 FR04、后续设计 |
| 公开可见性过滤 | PublicProfileCoordinator、UserProfile、Scholar、WorkEntity | 只公开当前生效、许可允许的对象 | 不公开/失效对象不可访问 | 对外粒度 Q-05 |
| 公开字段最小化 | PublicProfileUI、UserProfile | 只展示允许公开的信息 | 注册邮箱/联系方式等默认不公开；无凭据/审核材料/私有证明 | 字段集合 Q-01；授权动作属 UC-22 |
| 关系状态不冒充 | PublicProfileCoordinator、Authorship | 待核验/争议不得显示成已确认合作或本人确认 | 保留独立状态并在展示侧过滤 | 待核验是否公开显示 Q-04 |
| 空态判定 | UserProfile、PublicProfileCoordinator | 零成果不得返回 404 或伪装失败 | 正常页面 + “暂无公开成果” | 文案范围 Q-02；成果来源口径 Q-03 |
| 三态分离 | PublicProfileUI、PublicProfileCoordinator | 空态/不可访问/失败不得混淆 | 三个状态使用不同消息与文案 | 提示粒度 Q-05 |
| 只读 | 全部参与类 | 查看不得产生任何业务变更 | 无写消息；不改关系状态 | — |

## 10. 与 UC-22、UC-05/06、UC-02、UC-10 的边界

- **UC-22**：`ProfileUI`/`ProfileCoordinator` 负责本人普通资料编辑与“允许展示”的授权动作；本 UC 只读取其结果，不定义编辑与授权机制（BR-IMP-05；Q-08）。
- **UC-05/06**：认领申请、证据、审核与授权由 `ClaimUI`/`ClaimCtl`/`Claim`/`Auth` 承担；本 UC 只读取 `Scholar` 的公开认领/核验状态标签，不读取申请与审核材料（FR05；`AC-IMPL-NF06-01`；Q-06）。
- **UC-02**：成果详情、来源、版本、参与角色明细与外链由 `WorkDetailUI`/`WorkDetailCoordinator` 承担；本 UC 只读取成果公开展示字段（FR02）。
- **UC-10/15**：同人/异人判定、自动关联阈值与合并由治理与身份核验承担；本 UC 明确禁止自动合并，只显示既有状态（BR-IMP-03；`AC-IMPL-FR03-04`）。
