# UC-03 查看公开个人主页/学者档案

**版本：** V1.0（2026-10-21）
**对应需求：** FR03；并受 FR04-04、FR15、NF01、NF06 与 BR-IMP-01/03/05/11 约束。
**需求基线：** [`CognitaNexus-Shared-SRS-V2.2-69AC.md`](../../../srs/CognitaNexus-Shared-SRS-V2.2-69AC.md)
**教材依据：** §5.4.1 完善用例文档；§5.4.2 识别分析类；§5.4.6 用例实现四步。

> **范围边界：** 本 UC 只处理“访客凭稳定地址读取一个公开 UserProfile 或一个公开 Scholar 档案”的只读行为。
> 本人普通主页编辑（UC-22）、Scholar 认领与审核（UC-05/06）、已授权 Scholar 档案维护（UC-07）、成果详情与来源（UC-02）、检索（UC-01）、身份核验与归属修正（UC-10/08）不属于本 UC。
> 受保护写操作只作为“本 UC 不承接”的边界出现，不展开为交互分支。

## 1. 参与者

| 类型 | 参与者 | 说明 |
|---|---|---|
| 主要参与者 | 访客 | 无需登录；可打开普通用户主页地址或 Scholar 档案链接 |
| 次要参与者 | 无 | 平台是业务执行主体；Scholar、成果、Authorship 是系统内对象，不是外部参与者；检索结果的产出来自 UC-01 |

## 2. 目标

访客凭稳定标识打开**一个**页面对象，取得其公开视图：

- 若为 `UserProfile`：显示允许公开的普通资料；没有可公开学术成果时显示“暂无公开成果”空态，页面正常打开；
- 若为 `Scholar` 档案：显示公开身份信息、认领/核验状态（未认领时给出未认领提示）与当前公开且生效的成果参与关系；
- 两类对象与各自状态分别呈现：同名不合并、不互相冒充；待核验/争议/已排除关系不显示为已确认合作或本人确认。

## 3. 触发事件

访客打开某注册用户的稳定主页地址、某 Scholar 档案链接，或 UC-01 公开检索结果中的对象链接。

## 4. 前置条件

1. 请求携带可定位**单个**对象（`UserProfile` 或 `Scholar`）的稳定标识/地址；解析不依赖姓名（FR03-04；BR-IMP-03；SPEC ID-01、SR-12）。
2. 访客无需登录，也不需要已有账号、认领 Scholar 或会话（FR03 参与者：访客；NF01“公开门户无需登录”）。
3. `UserProfile` 由注册成功时创建并具备唯一、稳定、可分享公开地址（FR04；`AC-IMPL-FR04-03`）；本 UC 只读取该结果，不创建主页。
4. `Scholar` 档案独立存在，可以没有账号、可以未被认领（FR03；SRS §12）。
5. 目标对象必须处于当前公开且可访问的状态；成果参与关系必须是当前公开且生效的合格关系（BR-IMP-01；FR15）。
6. 公开字段只包含允许公开的信息；凭据、审核材料与私有证明不在公开响应内（FR03；FR04-04；BR-IMP-11；NF06）。

## 5. 成功与失败后置条件

### 5.1 成功

1. 只呈现一个页面对象：`UserProfile` 或 `Scholar` 档案；对象类型与状态标签分别显示（`AC-IMPL-FR03-04`）。
2. `UserProfile`：显示允许公开的普通资料；零成果时显示“暂无公开成果”空态，页面正常打开、不返回 404（`AC-IMPL-FR03-03`）。
3. `Scholar` 档案：显示公开身份信息与认领/核验状态；未认领但已有生效成果时仍可公开展示，并显示未认领提示（`AC-IMPL-FR03-01`）。
4. `Scholar` 档案的成果参与关系只包含当前公开且生效的合格关系；待核验/争议/已排除关系不被显示为已确认合作或本人确认（`AC-IMPL-FR03-02`；BR-IMP-01；FR15）。
5. 不因姓名相同自动合并 `UserProfile` 与 `Scholar`，不把 `UserProfile` 呈现为已认证学者，也不为其补造 Scholar 身份（`AC-IMPL-FR03-04`；BR-IMP-03）。
6. 公开响应不含凭据、审核材料、私有证明材料原文或未允许公开的字段（`AC-IMPL-NF06-01`；BR-IMP-11；FR04-04）。
7. 只读：不创建、不修改、不删除任何业务实体、关系或状态。

### 5.2 失败/不可访问

1. 稳定标识无法定位对象，或对象当前不公开/已失效：返回不可访问状态，不展示字段，且与零成果空态、执行失败可区分（`AC-IMPL-NF01-01`；BR-IMP-01）。
2. 读取依赖失败或超时：返回可区分的执行失败，不用空态冒充成功零条（`AC-IMPL-NF01-01`）。
3. 失败不改动公开数据：不删除成果、不隐去既有公开主页/档案、不改变关系状态（BR-IMP-04 精神；分析推导）。
4. 具体对外粒度（是否区分不存在/未公开/已失效）未冻结，见 §11 Q-05。

## 6. 基本事件流

| 步骤 | 事件 | 需求/规则来源 |
|---:|---|---|
| 1 | 访客打开稳定主页地址或 Scholar 档案链接（携带稳定标识）。 | FR03；`AC-IMPL-FR03-03/04`；E1 |
| 2 | 平台按稳定标识解析目标对象，判定其为 UserProfile 还是 Scholar 档案；不按姓名匹配。 | FR03-04；BR-IMP-03；SPEC ID-01/SR-12；E2 |
| 3 | 平台校验目标对象当前是否公开且可访问。 | BR-IMP-01；FR03；E3 |
| 4 | 若目标是 UserProfile：读取该主页允许公开的普通资料（仅用户允许展示的字段）。 | FR03“公开字段只包含用户允许展示的信息”；FR04-04；BR-IMP-11；E4 |
| 5 | 若目标是 UserProfile：判断是否存在可公开学术成果；零成果时生成“暂无公开成果”空态，页面正常。 | `AC-IMPL-FR03-03`；E5 |
| 6 | 若目标是 Scholar 档案：读取公开身份信息与认领/核验状态；未认领时生成未认领提示。 | `AC-IMPL-FR03-01`；FR03；E6 |
| 7 | 若目标是 Scholar 档案：读取该档案当前公开且生效的成果参与关系及其成果展示字段。 | FR03；BR-IMP-01；FR15；E7 |
| 8 | 平台统一执行公开/生效/许可过滤：待核验/争议/已排除关系不显示为已确认合作或本人确认；屏蔽私有证明与未允许公开字段；不按姓名合并或补并同名对象。 | `AC-IMPL-FR03-02/04`；BR-IMP-01/03/11；NF06；E8 |
| 9 | 平台返回该单一对象的公开视图（对象类型 + 状态标签 + 普通资料或学者身份 + 成果列表或空态）。 | FR03；`AC-IMPL-FR03-01～04`；E9 |
| 10 | 访客阅读公开视图；本 UC 不显示编辑、认领、审核或治理入口。 | FR04-04；BR-IMP-05；E10 |

> 步骤 2–3 是全部分支的公共前置；步骤 4–5 与 6–7 互斥（二选一，同一请求只呈现一个对象）。

## 11. 待确认

1. **Q-01 公开普通字段集合**：FR03 只规定“公开字段只包含用户允许展示的信息”，注册邮箱、联系方式等默认不公开已确认；昵称、头像、简介、兴趣领域等具体字段的默认可见性与字段级开关未冻结（FR06/UC-22 细化）。本 UC 不臆造字段清单。
2. **Q-02 空态文案与范围**：“暂无公开成果”是否统用于论文/专利/项目/获奖四类全部为零；部分类型为零时是否分区展示。AC 只要求零成果非 404 且可见该空态。
3. **Q-03 UserProfile 主页“学术成果”区的来源口径**：是否仅显示经 FR05 批准关联的 Scholar 的生效成果，还是始终无成果；SRS §12 明确不得由普通资料推导学术身份或合作边。本 UC 不建立 `UserProfile—WorkEntity`/`UserProfile—Authorship` 直接关系。
4. **Q-04 待核验关系的公开展示口径**：`AC-IMPL-FR03-02` 只禁止冒充已确认合作/本人确认，BR-IMP-01 只排除待审/争议/敏感证据；待核验（候选）关系是否以“待核验”标签公开、还是完全不进入公开列表未统一。本 UC 保证“绝不显示为已确认”。
5. **Q-05 不可访问的对外粒度**：不存在/未公开/已失效是否分别提示，以及不可访问是否使用 404——只要求与零成果空态、执行失败可区分。
6. **Q-06 状态标签口径**：Scholar 的认领状态（未认领/已认领）与身份核验状态如何显示、是否合并为一个标签，SPEC 的身份/关系状态枚举映射到门户展示标签需联合评审。
7. **Q-07 登录用户查看本人主页**：是否与访客视图相同、是否显示编辑入口属 UC-22；本 UC 按同一公开视图分析，不定义差异。
8. **Q-08 “用户允许展示”的授权与撤销**：由 UC-22/FR06 定义；本 UC 只读取其结果，不定义授权机制。
9. **Q-09 账号停用后的主页可读性**：`AC-IMPL-FR04-02` 只保证停用/退出不删除关联的学者公开档案，未规定已停用账号的 UserProfile 是否仍公开；本 UC 因此不读取账号状态（见 03 第 4 节拒绝 `User`）。
