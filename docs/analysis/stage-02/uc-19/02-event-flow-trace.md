## 6. 追踪结论

- E1–E17 均有正式来源或明确标注“分析推导”；E4/E8/E10/E12/E16/E17 的读取顺序、移交语义、重检时点与返回内容为分析推导，已在 01 §11 与 08 §6 标 `待确认` 或说明。
- 两个核心 AC 的可观察点均可定位：
  - `AC-IMPL-FR10-01`：只读审核值（M40/M41）→ 冲突守卫不覆盖（M44）→ 建立待核验字段冲突待办（M45–M46）→ 保全审核值与“冲突待核验”记录（M47–M48）。
  - `AC-IMPL-FR10-02`：断连/失败→失败点＋已分类结果＋恢复范围（M83–M87）；删除/撤稿→失效事件登记＋既有成果与出处存在＋待核验待办＋不删除（M63–M69）。
- “失败不删历史”“幂等”“不覆盖人工值”“版本须有证据”四条守卫均有 SRS/SPEC 直接依据，不是本 UC 的业务创新。
- 检查点间隔/批次大小（B-01/D-10）、无版本信息的退化比较规则（B-02）、回溯范围口径（B-03）、冲突处置责任与时限（B-04）、失效三类事件对公开资格的影响（B-05）、来源停用归属（B-06）、保留期限（B-07）、计数口径（B-08）、命名与登记（B-09）标 `待确认`，未写成已批准规则。
- 本表不修改 69 条 AC，不新增第 70 条 AC；与全局模型的命名/职责差异登记于 07，由 R5 统一。
