> **范围边界：** 本 UC 只处理“**在已核验来源域内，把一轮来源输入与上次观察版本比较，分类为新增/未变/变更/失效，并在不覆盖人工审核字段、不删除历史、失败可恢复的前提下记录检查/生效时间与治理待办**”这一件事。
> 来源配置（来源身份/输入方式/许可与范围/数据性质）、初始采集任务创建与启动属 UC-18；成果清洗、去重、字段确认与版本归并规则属 UC-09；学者身份与归属判定属 UC-10；后台待办聚合与审计查询属 UC-17；发布、公开可见性与读侧展示属治理与 UC-01/02/03/11/14/15/16。
> 本 UC 按**批次复跑与安全检查点**推进，**不要求实时流式同步**（FR10）：不建模实时订阅、流式推送或逐条即时同步。
> 本 UC **不修改来源配置**、**不创建/合并/拆分 `WorkEntity`**、**不建立 `WorkVersion`**、**不改公开可见性、不发布**、**不判同学者/同成果**、**不物理删除任何历史**、**不改写来源原值**；也**不建立调度器、任务队列、作业运行器、重试策略、检查点类或增量窗口类**。

> **对象区分（本 UC 的核心边界）：**
> - `SourceDefinition` 是**来源配置事实**（来源身份、来源域、输入方式、许可/使用范围、数据性质、允许范围）。本 UC **只读**它来确认“该来源已获准、来源域已核验、允许范围可定位”，**不新增、不停用、不更换来源**（配置属 UC-18，来源停用/更换的归属见 B-06）。
> - `SourceRecord` 是**到达证据**：来源身份、逻辑出处（`source_id`＋`source_record_key`）、到达事件、原始字段值、**观察版本**（`observedRevision`）、**最近检查时间**（`lastCheckedAt`）、数据性质、许可、到达时间。原值不可改写；变更追加新的到达事件，先前原值保留（INV-01；CL-10/CL-12）。
> - `CollectionTask` 是**一次执行的状态与历史**：六状态、参数快照、安全检查点、追加式任务历史（每次尝试的起止/结果/失败点/分类计数）与失败点。本 UC 复用 UC-18 定义的任务与状态，**不新增状态、不做来源定义与初始任务配置**。
> - `IncrementalChangeSet` 是**本轮比较结果**：来源域、更新范围、基线引用、**检查时间**、**来源报告更新时间**、**生效时间**、逐条分类（新增/未变/变更/冲突/失效/异常）与前后差异引用、互斥计数、待办引用、失败状态与未完成项。它**不是**任务状态（任务状态在 `CollectionTask`），也**不是**成果。
> - `WorkEntity` 是**去重后的成果实体**：本 UC **只读**其当前生效值、已人工审核字段与公开生效状态，用于判定冲突；**不写入、不覆盖、不新建、不合并、不改变公开资格**。
> - `WorkVersion` 是**有明示证据的版本关系**（预印本/修订/正式发表等），属于一个 `WorkEntity`；本 UC **只读**既有版本关系与明示证据，**不建立版本关系**（建立规则属 UC-09 DD-08）。
> - `GovernanceException` 是**待治理待办**：原因（字段冲突/并发冲突/失效待核验/来源身份或记录键不可确认/版本证据缺失待核验）、对象引用、双方证据与待处理状态；**无公开可见性**，关闭与处置属 UC-09/10 与 FR14 权限范围。
> - `GovernanceCoordinator` 是**属主 UC-09/10 的协作控制类**：本 UC 只移交“新增记录/变更生效/版本证据”并取回结果，不建模清洗、去重与身份归属规则。

## 2. 目标

让有“数据来源/采集”具体管理权限的管理员在**已核验来源域**内发起一轮来源更新：系统按 `来源ID + 来源内记录键 + 上次观察版本` 把本轮输入分类为**新增/未变/变更/失效**，分别记录**检查时间**与**生效时间**；未变不造变更，变更新增到达事件并保留先前原值，**与已人工审核字段冲突时保留人工审核值并生成待核验字段冲突治理待办**；来源删除/撤稿只登记事件并转待核验、不物理删除历史；来源失败或断连时任务失败但保留失败点、已分类结果与恢复入口，已收录数据仍可查询；批次复跑幂等、版本只在来源明示证据时交治理处理。

## 3. 触发事件

1. 管理员在已核验来源域内选择更新范围并请求一轮来源更新（增量同步）；
2. 管理员在没有可用基线（无上次检查点/来源无版本游标）时指定回溯范围；
3. 批次复跑或来源侧重叠窗口再次到达同一逻辑出处（触发幂等与分类重算）；
4. 未授权请求者提交来源更新或变更处置操作（触发拒绝路径，不改变任何业务状态）。

## 4. 前置条件

1. 请求方已认证、账号状态可用；每次请求在服务端校验“数据来源/采集”具体管理权限，入口可见不构成授权（§8；NF03；`AC-IMPL-NF03-01` 边界）。
2. 来源**已获准**且**来源域已核验**、输入方式（API 或文件）为已支持的一种、许可/使用范围与数据性质可定位（FR10“在已核验来源域”；FR08；FR16；INV-09）——本 UC **只读**这些配置事实（配置属 UC-18）。
3. 该来源已有到达登记与逻辑出处基线（`source_id + source_record_key` + 上次观察版本）可定位；基线缺失时走 A1（回溯范围），不得把“无法比较”当“未变”。
4. 任务处于允许推进的状态：更新以 `CollectionTask` 六状态推进，运行中→成功/失败/已停止；每次尝试保留安全检查点与任务历史（§6.2；`DGM-STATE-01`）。
5. 治理处置规则（清洗/去重/字段确认/版本归并）、发布与公开资格判定属 UC-09/10 与读侧；本 UC 只移交与取回结果。
6. 检查点间隔与批次大小、无版本信息的退化比较规则、回溯范围口径**未冻结**（D-10；B-01～B-03）。

## 5. 成功与失败后置条件

### 5.1 成功（一轮更新完成）

1. **每条本轮输入都有唯一分类**：新增/未变/变更（含冲突）/失效/异常（来源身份或记录键不可确认）之一，并记录到变更集；存在未记录项不得成功（E16；§6.2 完成判据的 UC-19 对应）。
2. **三种时间分开记录**：`checkedAt`（本轮检查时间）、`sourceReportedUpdatedAt`（来源报告的更新时间）、`effectiveAt`（按治理规则生效的时间）；采集/检查时间不冒充成果发生时间（FR10“保留检查与生效时间”；CL-07；§7.1）。
3. **未变不造变更**：只更新检查时间与观察版本，不新增到达事件、不新建/不修改成果（E9；`collection-update-activity`“只更新检查时间；不重复成果或业务变更”）。
4. **变更新增到达事件并保留先前原值**：前后差异可回看，来源原值不被改写（INV-01；CL-11；E10）。
5. **人工审核字段不被覆盖**：与已人工审核值冲突的变更保留审核值为公开/生效值，并生成**待核验字段冲突**治理待办（`AC-IMPL-FR10-01`；INV-06；CL-09；M45–M48）。
6. **成功结论限定措辞**：单列未变/变更/冲突/失效/异常数量，不得表述为“人工治理完成”“已核验”“已发布”（FR08 规范性要求的同源约束；§6.2；M80–M82）。
7. **幂等**：同一逻辑出处同一观察版本不重复建立变更、不新增第二条逻辑出处、不重复建立版本关系（A7；INV-07；FR09-06）。
8. 任务历史与安全检查点追加保存；受保护写入留痕含操作者/对象/时间/前后值/理由（§6.2；BR-IMP-10；INV-10）。
9. 不创建/更新 `WorkEntity`、不建立 `WorkVersion`、不改变公开可见性（BR-IMP-01/02；NF05 只在声明层）。

### 5.2 成功（分支结果）

1. **冲突变更**：变更集记录“冲突待核验”，生效值保持人工审核值，待办可被治理按对象定位（M45–M48）。
2. **无冲突变更**：先做生效前重检（M49/M50）；重检一致才交治理按字段规则生效（M51/M52）并记录生效时间（M53）；重检发现人工/生效值已变化则放弃覆盖并转并发冲突待办（M55–M58）。
3. **版本证据**：只在来源明示版本证据成立时记录证据并交治理处理；无证据保持独立并标待核验（M59–M62；A10；DD-08）。
4. **失效报告**：登记失效事件（撤稿/删除报告分别记录），既有成果与出处不被删除、不下架；建立待核验待办（M63–M69；A2/A9/A12）。
5. **无基线**：以管理员指定的回溯范围为基线并披露局限（M16–M19；A1）。

### 5.3 失败（不删除历史、无静默覆盖）

1. 未认证/停用/无“数据来源/采集”具体权限：拒绝，业务实体状态不变，不返回来源记录与变更明细，受控拒绝留痕不含凭据（A11；M106–M111；§8；NF03）。
2. 来源未获准/来源域未核验/范围不可定位/基线不可确定：拒绝本轮更新，不建立变更集、无业务写入（A1 之前的前置守卫；M14）。
3. 来源断连、读取失败或来源反馈异常：任务失败，保存失败点、已分类结果与恢复范围；变更集记录失败状态与未完成项；**既有成果、来源记录与已收录数据不删除且仍可查询**，保留恢复入口（A4；M83–M87；`AC-IMPL-FR10-02`；BR-IMP-04；NF04-01；NF07-01）。
4. 越界请求（按删除报告物理删除、按失效记录直接下架或覆盖公开值、无版本证据建立版本关系）：拒绝且无业务写入（A9/A10/A12；M98–M105）。
5. 空范围、无变更、失败、拒绝、无权限五类结果可区分，不互相冒充（NF01 类比；BR-UC19-14）。

> E7–E14 按“本轮输入×记录”循环，直到本轮输入分类完、任务失败或被停止（`repeat` 语义，见图）。E17 为只读查询。

| E9 | **未变**：只更新检查时间与本次观察版本，不新增到达事件、不建立业务变更、不新建/不修改成果。 | FR10“未变”；`collection-update-activity`“只更新检查时间” |
