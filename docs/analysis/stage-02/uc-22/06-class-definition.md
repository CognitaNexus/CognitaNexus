# UC-22 分析类职责、属性、关系与分析机制

**版本：** V1.0（2026-10-21）
**方法：** 教材§5.5.1 职责、§5.5.2 属性、§5.5.3 关系、§5.5.4 分析机制。
**范围：** 只定义 UC-22 能够证实的部分；跨用例统一关系不在此擅自补齐。

## 1. 定义原则

1. “做（Do）”型职责说明对象能执行/协调什么；“知道（Know）”型职责说明对象必须知道/提供什么。
2. 属性只写业务信息，不写数据库字段、主键类型、索引或 API 参数。
3. 关系只写有消息或正式业务约束支持的；无依据的跨用例关系留待 R5。
4. 控制类通常没有长期业务属性；其请求上下文是单次用例的分析状态。
5. 字段清单、公共资料策略、待审版本口径等未冻结项不伪装成类定义，统一标 `待确认`。

## 3. ProfileCoordinator（Control）

| 项目 | 定义 | 依据 |
|---|---|---|
| 类型 | Control | §5.4.2；M2–M6、M8、M9、M11–M13、M15、M16、M19–M21 |
| Do | 校验请求者身份与账号状态；核验对象归属；判定字段范围；协调保存普通字段；触发公开投影；拒绝学术事实写入并转交；协调受控审计；返回结果 | E2–E6、A1–A5 |
| 候选分析操作（`/`） | `/校验请求者与归属`、`/判定可编辑字段范围`、`/保存普通公开字段`、`/协调公开投影`、`/拒绝并转交学术事实`、`/记录受控审计`、`/返回编辑结果` | M3–M5、M8、M11–M21 |
| Know | 本次请求的分析状态：请求者标识、目标主页引用、提交字段集合、判定结论（允许/越权/停用/学术字段/失败）、审计留痕结果 | 分析推导 |
| 业务属性 | 无长期业务属性。分析级状态：编辑请求上下文、归属判定结果、字段判定结果、写入/发布结果（均为单次用例状态） | §5.5.2；不指定实现存储 |
| 关系 | 与 `ProfileUI`、`User`（M3）、`UserProfile`（M4/M15/M18/M19）、`AuditEvidence`（M8/M11/M20）的单向关联（按消息方向） | 04 消息表；VOPC |
| 不能承担 | 不承载账号状态（User 的 Know）；不承载公开资料与展示设置（UserProfile 的 Know）；不承载审计留痕内容（AuditEvidence 的 Know）；不是实现层 Controller/Service | §5.4.1；§5.5.1 |
| 分析机制 | 服务端每次授权的强制校验（含直接调用场景）；写入前拒绝（无副作用）；公开/私有字段分离；待审版本不覆盖公开版；受保护写入与拒绝均留痕；不创建第二主页、不创建学术对象 | BR-IMP-05/10/11；`AC-IMPL-FR06-02/03/04/05`；FR06 |

**待确认：** 公共资料策略口径与是否需要审核（B-01）；普通字段完整清单与格式校验（B-02）；混合提交（普通 + 学术）的处置（B-03）；展示设置范围（B-04）。

## 4. User（Entity）

| 项目 | 定义 | 依据 |
|---|---|---|
| 类型 | Entity | §5.4.2；M3；E2/A1 |
| Do | 提供账号标识与账号状态，供判定“请求者是否为可用账号”；作为主页所有权的账号主体；与唯一 UserProfile 保持绑定 | FR04；`AC-IMPL-FR04-02`；BR-IMP-05 |
| 候选分析操作（`/`） | `/校验账号状态`、`/提供所有权主体` | M3；A1 |
| Know | 自己的账号标识、账号状态、绑定的唯一 UserProfile | FR04；SRS §12；UC-04 |
| 业务属性 | `accountIdentifier`：账号标识（格式/唯一性规则沿用 UC-04 B/Q-01，本 UC 不新增）；`accountStatus`：可用/停用；`profile`：与 UserProfile 的 1:1 引用 | FR04；`AC-IMPL-FR04-02` |
| 关系 | `User 1 — 1 UserProfile`（唯一拥有）；本 UC 不建立、不改变 User—Scholar/Auth 关系 | FR04；SRS §12；BR-IMP-05 |
| 不能混淆 | User 不是 Scholar；User 不承载公开主页资料；账号状态不是主页公开状态 | FR04；`AC-IMPL-FR03-04` |
| 分析机制 | 持久性；账号状态校验；对象所有权；稳定标识 | FR04；BR-IMP-05；SRS §8 |

**本 UC 不新增 User 属性：** 编辑普通主页不引入新账号字段；会话/凭据是否成为独立对象待 B-06。

## 5. UserProfile（Entity）

| 项目 | 定义 | 依据 |
|---|---|---|
| 类型 | Entity | §5.4.2；M4/M15/M18/M19；E2/E4/E5；A2–A7 |
| Do | 提供所属 User 以核验归属；保存普通公开字段与展示设置；按公共资料策略生成公开投影；保持零成果空态；**不接受**学术身份/机构/归属/来源事实写入 | FR06；`AC-IMPL-FR06-03/05`；`AC-IMPL-FR07-03`；`AC-IMPL-FR03-03` |
| 候选分析操作（`/`） | `/核验归属`、`/保存普通公开字段`、`/生成公开投影`、`/保持零成果空态`、`/登记待审版本`（待确认）、`/拒绝学术事实写入` | M4、M15、M18、M19；A3 |
| Know | 所属 User；稳定公开地址；普通公开字段（昵称/头像/简介/兴趣领域）；展示设置；公开投影白名单；是否已有公开成果（空态判断）；待审版本（仅 A5 情形） | FR03；FR06；`AC-IMPL-FR04-03` |
| 业务属性 | `stablePublicAddress`：唯一、稳定、可分享的公开地址（本 UC 只读，不改变）；`owner`：所属 User（1:1）；`ordinaryPublicFields`：昵称 `nickname`、头像 `avatar`、简介 `bio`、兴趣领域 `interests`（含字段清单待确认 B-02）；`displaySettings`：展示设置（范围待确认 B-04）；`publicProjection`：只含明确允许公开字段的对外投影（白名单待确认 B-02）；`privateExcludedData`：默认不公开的账号信息/联系方式（不进入投影）；认证材料属UC-05/06 ReviewEvidence，凭据不在UserProfile数据范围；`pendingVersion`：待审版本（仅 A5，B-01 待确认）；`zeroWorkEmptyState`：零成果空态，派生显示状态而非成果实体 | FR06；`AC-IMPL-FR06-03/05`；`AC-IMPL-FR07-03`；BR-IMP-11；UC-04 06 |
| 关系 | `UserProfile 1 — 1 User`（属于/唯一）；与 `ProfileCoordinator` 按消息协作；不建立与 Scholar/Auth/Claim/Authorship 的关系 | FR04；SRS §12；`AC-IMPL-FR03-04`；FR05 |
| 不能混淆 | 不是 Scholar 档案、不是学术认证；普通资料不能成为合作边/统计依据；零成果不是 404；编辑不产生第二主页 | FR03；FR06；A1c；`AC-IMPL-FR03-03/04` |
| 分析机制 | 持久性；公开地址稳定不变；普通字段与私有字段分离；公开投影最小化（BR-IMP-11；INV-08）；待审不覆盖公开版；零成果空态；不接受学术事实写入 | FR06；`AC-IMPL-FR06-01/05`；`AC-IMPL-FR07-03`；BR-IMP-10 |

**说明：** `pendingVersion` 只在“公共资料策略要求审核”时出现（B-01 未冻结），因此本 UC 不为 UserProfile 建立复杂状态机：只有“公开版 / 待审版本（条件性）”的区分，没有草稿—发布—删除生命周期。

## 6. AuditEvidence（Entity）

| 关系 | 角色/方向 | 多重性 | 来源 | 状态 |
|---|---|---|---|---|

| ProfileCoordinator → UserProfile | 核验归属 / 保存普通字段 / 公开投影 / 登记待审版本 | 不定义持久多重性 | M4/M15/M18/M19 | 已定义（单向关联，含应答） |

## 8. 分析机制汇总

| 机制 | 作用对象 | 业务问题 | 本 UC 可证实的约束 | 未决定/后续 |
|---|---|---|---|---|
| 对象授权（服务端强制） | ProfileCoordinator、User、UserProfile | 只有所有者可写；直接调用接口也必须被拒绝 | 写入前校验身份/账号状态/归属；拒绝无副作用；留痕 | 会话/凭据对象（B-06） |
| 字段范围隔离 | ProfileCoordinator、UserProfile | 普通字段可编辑，学术事实不可经本 UC 写入 | 学术事实不写、不改核验状态，转 UC-07/UC-08 | 普通字段清单与格式（B-02）；混合提交（B-03） |
| 有效性/公开策略 | UserProfile | 普通资料“在允许公开后生效” | 保存后按公共资料策略生成投影 | 策略口径与是否审核（B-01）；展示设置范围（B-04） |
| 最小化 | UserProfile、ProfileUI | 私有联系方式、认证材料、凭据不得公开 | 投影只含允许公开字段；不回显秘密 | 白名单（B-02） |
| 待审不覆盖公开版 | UserProfile | 待审内容不得提前公开 | 未生效内容不进入公开投影；公开版保持旧值 | 是否适用普通字段（B-01） |
| 审计留痕 | AuditEvidence | 受保护写入可追溯，拒绝与越权也可追溯 | 身份/对象/理由/前后值/时间；不含秘密 | 保留期限与查询权限（B-05，UC-17） |
| 持久性与不变量 | User、UserProfile | 反复编辑后仍是同一个唯一主页 | User—UserProfile 1:1；地址不变；不新建主页 | 存储粒度 |
| 结构性不扩张 | UserProfile | 编辑不得制造学术身份或成果 | 不创建 Scholar/Auth/Claim/Authorship/WorkEntity | — |

## 9. 与其他 UC 的边界

- **UC-04**：注册创建 User 与唯一 UserProfile 并授予本人普通资料编辑权；本 UC 消费该前置，不重新创建主页。
- **UC-03**：公开读取与展示（含零成果空态、同名分开展示、私有字段屏蔽的读侧）在 UC-03；本 UC 只保证写侧公开投影与不变量。
- **UC-05/06**：认领与对象授权在 UC-05/06；本 UC 既不创建也不读取 `ScholarAuthorization`。
- **UC-07**：已授权 Scholar 档案维护（重要机构/身份变更的待审与生效）在 UC-07；本 UC 只拒绝并转交。
- **UC-08**：成果确认/纠错在 UC-08；本 UC 只保证编辑不生成成果实体。
- **UC-17**：审计查询与保留策略在 UC-17；本 UC 只写入审计留痕。
