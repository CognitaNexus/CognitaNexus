> **范围边界：** 本 UC 只处理“一条已获准接入的来源记录从**结构校验、按类型最小字段校验、原值与时间精度保留、标识按作用域归一**，到**按稳定标识匹配、无标识候选、版本归并、重复到达幂等**，再到**管理员核验候选、合并/拆分、确认字段生效值**的治理行为”。
> 来源接入、采集任务创建/停止/重试、来源配置与日志定位属 UC-18；增量识别（新增/未变/变更/失效）与失败恢复属 UC-19；学者身份消歧、同名合并/拆分、把参与关系改派到另一位学者属 UC-10；学者本人对成果的确认/补录/纠错申请与审核属 UC-08；检索、详情、门户、统计、合作网络的展示与计算属 UC-01/02/03/11/14；后台待办队列、审计查询与争议结案属 UC-17。
> 本 UC **不创建采集任务**、**不触发采集重试**、**不新建 `Scholar` 或 `Authorship`**、**不改写 `Authorship` 关系状态**、**不承认任何学者身份判定**、**不发布/下架成果**、**不删除 `WorkEntity` 与 `SourceRecord`**、**不改写来源原值**。
>
> **对象区分（本 UC 最重要的边界）：**
> - `SourceRecord`：来源侧**原始证据**（来源 ID、来源内记录键、原始字段值、许可/使用范围、到达事件、数据性质、原站地址），只读；重复到达只追加到达事件（INV-01；CL-10/CL-11）。
> - `CleanRecord`：**规范记录**（逐字段原值＋规范值＋规则/字典版本＋时间语义与精度＋标识归一结果＋治理状态＋异常原因/字段冲突项），是“可回放、可复核”的清洗产物，不是来源原值、也不是成果实体（SPEC §4.1；CL-11）。
> - `WorkEntity`：**去重后的成果实体**，承载规范生效值、已人工确认值、公开生效状态、出处集合、合并重定向；实体数不等于来源数或版本数（INV-02；DD-11）。
> - `WorkVersion`：**有明示证据的版本关系**（预印本/修订/正式发表等），属于一个 `WorkEntity`；无明示证据不建立（DD-08）。
> - `DedupCandidate`：**待核验的匹配候选**（待判定的规范记录＋候选实体清单＋逐项证据命中/冲突＋候选规模＋匹配状态＋理由），与“已生效的成果实体”并存且可区分；标题相似只产生它，不产生合并（DD-05～DD-07/DD-12）。
> - `AuditEvidence`：**治理动作留痕**（动作类型、对象、触发依据、执行者类型与身份、前后值、时间），追加式、不可覆盖；合并链/拆分链/撤销都以它承载（FR09-S09/S12；BR-IMP-10）。
>
> 六者不得合并为“一条清洗结果”或“一个可信标签”。

## 1. 参与者

| 类型 | 参与者 | 说明 |
|---|---|---|

| 次要参与者 | 系统（治理处理） | 执行结构校验、按类型最小字段校验、规范化、标识归一、稳定标识匹配、候选生成、版本归并、幂等定位、批次计数；是**外部系统参与者**，不画成分析类 |

## 2. 目标

在“保留来源原值、按类型校验最小字段、按作用域归一标识、只在不矛盾时自动关联”的约束下，把一批来源记录确定性地归入成果实体或送入待核验/异常处理，并保证：
①同一逻辑出处重复到达不增加实体与有效出处；
②无稳定标识不自动合并、标题相似不构成合并依据；
③版本归并须明示证据且不增加实体数；
④缺字段标未知不造值、年份不补日期；
⑤已人工确认值不被来源更新静默覆盖；
⑥人工合并/拆分与字段确认全部可追溯、历史不被覆盖。

## 3. 触发事件

1. 来源采集/增量任务交付一批已获准接入、已完成到达登记的来源记录（批次标识＋到达事件＋来源记录引用）；
2. 或治理管理员打开一条待核验候选/异常记录/字段冲突处理项并提交处置（含合并、拆分、确认不同、确认新实体、确认字段生效值、修正字段后重新判定、忽略）；
3. 或同一来源逻辑记录被再次导入（重复到达/批次重跑），触发本 UC 的幂等判定。

## 4. 前置条件

1. 来源已按 FR08/FR10 获准接入并完成到达登记（`source_id`、`source_record_key`、到达事件、许可/使用范围、数据性质可定位）；本 UC 不判断来源是否应接入（UC-18/19）。
2. 该批次具备可定位的批次标识；记录带原始字段值，未经本 UC 之外的改写（§6.1；SPEC §4.1 前置）。
3. 成果类型可识别（论文/专利/项目/获奖），类型专属字段语义按 §7.1 与 FR16 解释。
4. 规范值与原值可分离保存；机构/领域映射字典与分类表可用（不可用时按 A12 部分成功）。
5. 管理员处置路径要求：账号可用、服务端校验具备治理处置权限（NF03；FR14）。
6. 类型细化必填项、字段优先级、无标识相似度阈值与候选年份窗、候选截断长度、复核比例**尚未冻结**（B-01～B-05；D-07；Q-SPEC-01），本 UC 不预设具体数值。

## 5. 成功与失败后置条件

### 5.1 成功（批次处理）

1. 每条记录得到四种结局之一且可区分：**命中既有实体**（关联出处）、**新建实体**（记录新建依据）、**候选待核验**（含全部候选与逐项证据）、**异常待处理**（含原因与原始内容）（DD 判定输出；FR09-S11）。
2. 命中/新建时：`distinct(生效 WorkEntity canonical_id)` 按预期变化（命中不加、新建加一）；`distinct(source_id, source_record_key)` 有效出处数对应加一；重复到达批次两者都不变（DD-11；`AC-IMPL-FR09-03/06`）。
3. 规范化记录保留逐字段原值与规范值、规则/字典版本、时间事件语义与精度；来源原值未被改写（INV-01；CL-11）。
4. 缺失字段标“未知”并区分空白/缺失/确认为无；仅年份的时间不补月日；采集时间未冒充发生时间（CL-06/CL-07/CL-08；`AC-IMPL-FR09-04`）。
5. 未知辖区（或授予机构未知）的专利/项目标识保留原值并标待核验，不作为可自动匹配的稳定键（CL-04；`AC-IMPL-FR09-05`）。
6. 现场形成候选时不产生自动合并；仅当存在来源明示版本指向且证据成立时归入同一实体的版本清单，实体数不增（DD-06/DD-07/DD-08）。
7. 批次结论区分“命中/新建/候选/异常”计数，并声明“批次处理完成”不等于“治理全部通过”；异常不得直接成为已公开成果（FR08；§6.2；§11.4）。
8. 受保护写入、自动关联、待核验生成、新建与异常入队均留痕（BR-IMP-10；FR09-S12）。

### 5.2 成功（管理员处置）

1. **合并**：目标实体保留全部唯一出处与版本、字段按优先级合并、旧标识可溯源重定向、合并链含依据与执行者类型；`distinct` 实体数按合并结果减少，出处数不变；禁止循环合并、禁止部分成功（DD-09；FR09-S09；M74–M79）。
2. **拆分**：还原为两个实体，来源映射与实体归属重建，任何出处/版本不删除；原合并记录保留，拆分作为新记录追加（DD-10；FR09-S12 A3；M80–M84）。
3. **确认不同 / 确认新实体 / 忽略**：候选/处理项状态置已处理并保留理由与证据；确认不同不合并、实体数不变；确认新实体新建并标注“人工判定”；忽略不进入公开检索且原始内容保留（FR09-S11 A1/A3；M64–M70、M92–M94）。
4. **确认字段生效值**：写入人工确认值作为该字段生效值，原已确认值与双方来源证据保留，来源原值不改写；此后来源更新不得静默覆盖该值（CL-09；BR-IMP-04；FR09-S05；M85–M88）。
5. **修正字段后重新判定**：修正后的规范值替代参与匹配的规范值，原值与规则版本保留；重新进入标识匹配，不新建并列处理项（FR09-S11 主流程 3；M89–M91）。
6. 全部处置追加治理留痕（动作/对象/依据/执行者/前后值/时间）并可按对象与操作者追溯；历史记录不被覆盖（FR09-S12；BR-381/BR-382）。

### 5.3 失败（无业务写入或整体回滚）

1. 记录不合规（缺名称/来源身份/类型不支持）时不形成有效公开实体，保留原始记录并提示缺项（CL-01；SPEC §4.4）。
2. 处置失败（循环合并、写入中断、并发版本冲突）时不留部分合并/部分拆分状态；处理项与公开值保持原状并报告失败、可重试（DD-09；FR09-S09 E3；FR09-S11 E1/E2）。
3. 留痕写入失败时不得报告为成功，不得出现“已生效但无记录”（FR09-S12 E1；BR-IMP-10）。
4. 拒绝（无处置权限/账号停用）不修改任何业务实体，并留受控拒绝审计（NF03；FR14）。
5. 失败、拒绝、异常、待核验、已处理五类结果可区分（NF01 的可区分原则在治理侧同样适用；分析推导）。

## 6. 基本事件流

| 步骤 | 事件 | 需求/规则来源 |
|---:|---|---|
| E1 | 来源采集/增量任务交付一批已获准接入的来源记录（批次标识、到达事件、来源记录引用、许可与数据性质）；系统受理该治理批次。 | §6.1 管线；FR08/FR10（前置，属 UC-18/19）；FR09 参与者“系统/治理管理员” |

| E9 | 无命中时以同类型＋标题比对键＋年份窗召回候选，逐项产出标题/年份/参与者/类型证据；只生成候选，不自动合并。 | DD-05/DD-06/DD-07；`AC-IMPL-FR09-02`；FR09-S07 |
| E10 | 同一稳定标识命中多个实体、命中实体类型不一致、或命中实体标识处于争议时，判为待核验并列出全部候选。 | DD-02/DD-04；FR09-S06 E1–E3 |
| E11 | 判定版本关系：有来源明示版本指向时归入同一实体的版本清单（实体数不增）；无明示证据保持独立并标疑似。 | DD-08；`AC-IMPL-FR09-05`；FR09-S08；FR16 |
| E12 | 命中既有实体时按字段优先级合并：已人工确认值优先呈现，新来源证据保留为冲突项，不静默覆盖。 | CL-09；BR-IMP-04；FR09-S05 E1/E4；`AC-IMPL-FR09-04` |
| E13 | 缺失字段记“未知”并区分空白/缺失/确认为无；不设默认值、不推断填充。 | CL-08；§7.1“不存在的专属字段标未知，不造默认值”；FR09-S01 |
| E14 | 批次结束核对计数并输出批次结论：命中/新建/候选/异常分别计数，声明“批次完成≠治理通过”。 | DD-11；BR-IMP-02/06；§6.2；§11.4；`AC-IMPL-FR09-03/06` |
| E15 | 治理管理员打开一条处理项（待核验候选/异常记录/字段冲突项），查看候选清单、逐项证据、异常原因、冲突字段与双方来源；服务端校验其处置权限。 | FR09-S11 主流程 1–2；FR14；NF03 |
| E16 | 管理员提交处置：合并至目标实体 / 拆分 / 确认不同 / 确认新实体 / 确认字段生效值 / 修正字段后重新判定 / 忽略（含理由）；系统执行并给出可区分结果。 | FR09-S09/S11/S12；CL-09；DD-09/DD-10；`AC-IMPL-FR09-04/05` |
| E17 | 系统追加治理留痕（动作/对象/依据/执行者/前后值/时间），核对计数不变量与“历史不被覆盖”，并声明治理结论生效后下游读取同一去重实体。 | FR09-S12；BR-IMP-10；INV-10；NF05（下游一致只在声明层，实测未运行） |

> 步骤 E2–E14 是“批次治理”的确定性组合；E15–E17 是“人工处置与留痕”的组合。此处只定义业务约束，不指定事务、锁、并发控制、索引或消息实现。

## 7. 备选/异常流

| 编号 | 条件 | 系统行为 | 依据 | 说明 |
