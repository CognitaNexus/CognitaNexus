> **边界**：用例只表达外部参与者可观察的业务目标；清洗、去重、消歧算法是系统内部职责，不另画成外部用例。UC-20/21为 Optional 延期，不建立 Must 依赖。UC-22是普通 UserProfile 编辑，不是 Scholar 认领或学术档案维护。

## 1. 参与者

| 参与者 | 业务边界 | 不拥有的权限 |
|---|---|---|
| 访客 | 公开检索、详情、公开 UserProfile、公开 Scholar 档案、统计与网络 | 修改主页、提交认领、审核、管理 |
| 注册用户 | 拥有唯一 UserProfile；可编辑本人普通资料；可提交本人 Scholar 认领 | 编辑他人主页；未经授权维护 Scholar；绕过审核写学术事实 |
| 门户管理者 / 已授权 Scholar 管理者 | 仅操作被授予的具体 Scholar 档案及其允许字段 | 修改其他 Scholar；把普通主页资料当学术认证 |
| 有权管理员 | 按具体权限处理认领、成果修正、治理、采集、审计 | 越权处理未授权对象；以管理员身份冒充本人确认 |
| 获准数据来源 | 提供许可范围内的元数据或文件 | 获得平台账号权限；绕过来源许可 |
| 系统（业务主体） | 执行批次、校验、去重、生效和审计 | 不是自身用例的外部 Actor，不画成“系统对自己发起” |

## 3. 关键用例规约

### UC-01 检索成果与学者

- **目标：** 访客通过关键词和筛选找到公开、有效的成果或学者。
- **对应需求：** FR01；AC-IMPL-FR01-01～03；BR-IMP-01/07。
- **主要参与者：** 访客。
- **前置条件：** 公开数据已生效；查询范围明确；无登录要求。
- **触发：** 提交关键词、范围、筛选、排序或翻页。
- **主成功场景：**
  1. 访客选择成果或学者范围，输入关键词和筛选条件。
  2. 系统校验条件，只查询当前公开有效对象。
  3. 系统按匹配层级和已批准排序规则排序，以稳定实体ID打破并列。
  4. 返回当前页、总数、完整条件回显和可进入详情/主页的稳定链接。
  5. 访客翻页时保持同一查询上下文和数据快照。
- **备选/异常：**
  - A1 无匹配：返回无结果，不放宽条件，不当作失败。
  - E1 依赖失败/超时：返回执行失败，不伪装“无结果”。
  - E2 非法字段：指出非法条件，不执行误导性查询。
- **后置：** 只读，不改变业务实体；结果仅含公开有效数据。
- **业务规则：** 公开权限先于排序/计数；模拟数据不得混入默认真实结果。
- **AC 覆盖：** FR01-01（范围不混排）、FR01-02（筛选/分页/条件保持）、FR01-03（空与失败分离）。

### UC-02 查看成果详情与来源

- **目标：** 访客读取一条成果的公共字段、适用类型字段和全部可公开来源。
- **对应需求：** FR02/FR16；AC-IMPL-FR02-01/02、FR16-01；BR-IMP-01/02。
- **主要参与者：** 访客；次要参与者：成果原站。
- **前置：** 成果存在、允许公开且当前生效。
- **主成功场景：**
  1. 从检索/主页/网络证据进入详情。
  2. 系统展示一条 WorkEntity 的规范字段、类型专属字段、参与者角色、时间语义、真实/模拟标识和来源列表。
  3. 同一成果的多条许可来源合并展示，但实体仍为一条；缺失字段标未知。
  4. 访客可跳转原站；系统不承诺全文。
- **备选/异常：**
  - E1 原站链接失效：保留元数据，明确提示外链失败，不删除成果。
  - E2 字段缺失：标未知，不补造。
  - E3 来源不许可：不展示该来源详情。
- **后置：** 只读；不改变来源或成果。
- **AC 覆盖：** FR02-01、FR02-02、FR16-01。

### UC-03 查看公开个人主页/学者档案

- **目标：** 访客读取注册用户的公开 UserProfile，或读取独立 Scholar 档案及已生效成果。
- **对应需求：** FR03；AC-IMPL-FR03-01～04；BR-IMP-01/03/11。
- **主要参与者：** 访客。
- **前置：** 主页允许公开；Scholar 成果关系已生效；不要求登录或 Scholar 认领。
- **触发：** 打开稳定主页地址、Scholar 链接或检索结果。
- **主成功场景：**
  1. 系统识别链接指向 UserProfile 还是 Scholar，分别加载对应页面。
  2. UserProfile 展示允许公开的普通资料；无成果时显示“暂无公开成果”空态。
  3. Scholar 展示姓名/别名、已核验身份状态、允许公开的成果；未认领时显示未认领提示。
  4. 访客只看到生效关系，不看到审核材料。
- **备选/异常：**
  - A1 普通用户与同名 Scholar 同时存在：分别展示并标注对象/核验状态，不自动合并。
  - E1 零成果主页：正常 200 页面，不返回 404。
  - E2 待核验/争议关系：不显示成已确认合作或本人确认。
  - E3 私有字段：不出现在公开响应。
- **后置：** 只读。
- **AC 覆盖：** FR03-01～04。

### UC-04 注册账号并生成个人主页

- **目标：** 访客成功注册 User，并自动获得唯一、公开、稳定的 UserProfile。
- **对应需求：** FR04/FR03；AC-IMPL-FR04-01～04、FR03-03/04；BR-IMP-05/10/11。
- **主要参与者：** 访客；注册后成为注册用户。
- **前置：** 注册入口可用；输入满足账号规则。
- **触发：** 提交注册。
- **主成功场景：**
  1. 访客填写账号信息并提交。
  2. 系统校验必填项、账号状态和唯一性。
  3. 系统创建 User，并在同一业务事务创建唯一 UserProfile、分配稳定公开地址。
  4. 主页发布允许公开的普通资料和零成果空态。
  5. 系统返回账号与主页地址；会话建立后本人可进入 UC-22。
- **备选/异常：**
  - A1 注册请求重试：幂等识别，不创建第二个主页。
  - E1 输入无效：字段级错误，不创建账号。
  - E2 主页/地址创建失败：回滚，不留下无主主页。
  - E3 账号停用/退出：受保护请求拒绝，已有公开 Scholar 档案不因停用删除。
- **后置：** User 1:1 UserProfile；不创建 Scholar、不建立 Authorship。
- **AC 覆盖：** FR04-03/04、FR04-01/02、FR03-03/04。

### UC-22 编辑本人普通个人主页

- **目标：** 注册用户编辑本人 UserProfile 的普通公开资料，无需 Scholar 认领。
- **对应需求：** FR06/FR07；AC-IMPL-FR06-03/04/05、FR07-03；BR-IMP-05/10/11。
- **主要参与者：** 注册用户（主页所有者）。
- **前置：** 会话有效、账号可用、操作对象为本人 UserProfile。
- **触发：** 保存昵称、头像、简介、兴趣领域或展示设置。
- **主成功场景：**
  1. 本人打开编辑页，系统校验会话、账号状态和主页所有权。
  2. 用户修改普通公开字段并保存。
  3. 系统校验字段类型和公开范围，保存 UserProfile。
  4. 按公共资料策略公开生效，保留受控审计。
- **备选/异常：**
  - E1 非本人直接调用：服务端拒绝，无写入并留受控审计。
  - E2 已退出/停用：拒绝，不删除既有公开档案。
  - E3 私有账号信息/审核材料：不进入公开响应。
  - A1 试图直接改 Scholar 身份、机构、归属或成果核验状态：普通编辑拒绝写入，转 UC-07/UC-08 的对象授权与审核流程。
  - A2 无成果：保存后仍显示空态，不创建 WorkEntity/Authorship。
- **后置：** 仅普通 UserProfile 改变；Scholar/Authorship 不因普通编辑变化。
- **AC 覆盖：** FR06-03/04/05、FR07-03。

### UC-05 提交和查询 Scholar 认领

- **目标：** 登录用户对已收录 Scholar 提交可核验证据并查询处理状态。
- **对应需求：** FR05；AC-IMPL-FR05-01/03/04；BR-IMP-03/05/10。
- **主要参与者：** 注册用户；次要参与者：有权管理员。
- **前置：** 账号有效；目标 Scholar 已存在；用户已有唯一 UserProfile（注册产生）。
- **主成功场景：**
  1. 用户选择目标 Scholar，确认与本人关系并提交必要证据。
  2. 系统校验证据完整性和当前冲突。
  3. 系统创建待审核申请；用户可查询状态。
  4. 申请进入 UC-06；认领通过只增加 Scholar 授权/关联，不创建第二主页。
- **备选/异常：**
  - A1 缺必要证据：标待补充或拒绝进入审核，并说明缺失。
  - A2 已有原授权且他人争议申请：原授权保持，争议进入受控待办。
  - E1 提交重复：不创建互相冲突的重复有效授权。
- **后置：** 申请状态独立于 UserProfile 公开状态与 Authorship 状态。
- **AC 覆盖：** FR05-01/03/04。

### UC-06 审核 Scholar 认领

- **目标：** 有权管理员依据证据批准、驳回、要求补充或标记争议，并在批准时授予对象级权限。
- **对应需求：** FR05；AC-IMPL-FR05-01～04；BR-IMP-03/05/10。
- **主要参与者：** 有权管理员；次要参与者：申请人。
- **前置：** 申请存在且处于待审核/待补充/争议；管理员具有对应对象审核权。
- **主成功场景：**
  1. 管理员查看申请、证据和当前授权冲突。
  2. 证据完整、无冲突且批准条件满足时，系统在同一业务过程中记录批准并授予目标 Scholar 的对象管理权。
  3. 系统记录决定、理由和前后值；申请人可查询结果。
- **备选/异常：**
  - A1 需补充：进入待补充，保留原授权和申请历史。
  - A2 驳回：记录理由，不授予权限。
  - A3 冲突未解决：保持争议/待核验，不自动转移原授权。
  - E1 审核过期或授权事务失败：保持先前状态，不虚报通过。
- **后置：** 只授予目标对象；不创建第二 UserProfile；不批量确认 Authorship。
- **AC 覆盖：** FR05-01～04、FR15-04。

### UC-07 维护已授权 Scholar 档案

- **目标：** 已授权 Scholar 管理者维护本人被授权的学术档案字段；重要变更按审核规则生效。
- **对应需求：** FR06；AC-IMPL-FR06-01/02/05；BR-IMP-05/10/11。
- **主要参与者：** 已授权 Scholar 管理者；次要参与者：有权管理员。
- **前置：** 目标 Scholar 的授权已生效；操作字段在授权范围内。
- **主成功场景：**
  1. 管理者查看可编辑字段并提交变更。
  2. 系统校验对象授权和字段范围。
  3. 普通允许变更保存；需审核的重要机构/身份变更进入待审，公开仍显示旧值。
  4. 审核通过后生成生效版本并传播到检索/门户/统计。
- **备选/异常：**
  - E1 未授权/越权对象：拒绝，不写业务实体。
  - E2 待审期间：不替换公开旧值。
  - E3 普通 UserProfile 字段：引导至 UC-22，不混为学术核验。
- **后置：** 只有生效版本进入公开视图。
- **AC 覆盖：** FR06-01/02/05。

### UC-08 确认、补录和纠错成果

- **目标：** 已授权学者确认参与关系、补录元数据或申请纠正误归属/字段。
- **对应需求：** FR07/FR15；AC-IMPL-FR07-01～03、FR15-02/05；BR-IMP-03/07/10。
- **主要参与者：** 已授权学者；次要参与者：管理员。
- **前置：** 学者具有目标关系/成果的合法操作权；成果已收录或可补录。
- **主成功场景：**
  1. 学者选择一条参与关系进行确认/排除，或提交补录/字段修正。
  2. 系统记录原始值、证据和变更申请。
  3. 非共享、无需审核的本人关系按规则生效；共享字段/争议归属进入审核。
  4. 生效后更新门户、统计、基础网络和受影响论文路径，保留旧版本与审计。
- **备选/异常：**
  - E1 审核未通过：公开旧值不变，过程可查。
  - E2 解除本人关系：保留共享成果、来源和其他合法参与关系。
  - E3 零成果主页：保持空态，不凭空创建 WorkEntity/Authorship。
  - E4 单次本人确认：不自动把其他候选署名升级为本人确认。
- **后置：** 关系状态与成果存在性分离；历史证据不擦除。
- **AC 覆盖：** FR07-01/02/03、FR15-02/05。

### UC-14 查看四类共同成果合作网络

- **目标：** 访客查看由论文、专利、项目、获奖四类合格共同成果形成的真实基础合作网络。
- **对应需求：** FR12；AC-IMPL-FR12-01～05；BR-IMP-01/03/07/08。
- **主要参与者：** 访客。
- **前置：** 固定图快照；成果真实、公开、生效；参与关系合法且已核验。
- **主成功场景：**
  1. 访客选择已批准筛选并请求基础网络。
  2. 系统按类型核验参与角色：论文作者、专利发明人、项目合法成员、获奖个人成员。
  3. 对每项去重合格成果，为不同学者对生成一条无向边并累计强度；同一成果跨来源/版本只计一次。
  4. 保存可追溯成果证据，返回网络/节点/边及口径。
- **备选/异常：**
  - A1 仅同机构/同领域或相似姓名：不建边。
  - A2 待核验/争议/已排除关系：相关作者对不贡献该成果。
  - A3 模拟/混合：不得混入默认真实网络，只可显式演示。
  - A4 超过节点/边上限：明确超规模，不任意截断后伪称全图。
- **后置：** 只读派生结果；不改变成果或关系。
- **AC 覆盖：** FR12-01～05。

### UC-15 筛选网络及论文最短路径

- **目标：** 访客在 IN01 合格共同论文子图上筛选并查询两名已消歧学者的最少合作边路径。
- **对应需求：** IN01；AC-IMPL-IN01-01～04；BR-IMP-08/09。
- **前置：** 固定图版本与筛选；端点属于同范围且可用；边仅来自合格共同论文。
- **主成功场景：**
  1. 访客设置机构/领域筛选并指定起止学者。
  2. 系统从 UC-14 基础图中只取合格共同论文子图，应用事件时机构/领域证据。
  3. 以 BFS 按合作边数求最短路径；等长路径按 canonical_id 序列字典序选一条。
  4. 每跳展示至少一篇合格共同论文证据；返回图版本、跳数和证据入口。
- **备选/异常：**
  - A1 端点无效/不可用：分别提示，不返回伪造路径。
  - A2 无路径：明确当前范围无路径，不放宽范围。
  - A3 共同专利/项目/获奖不能作为 IN01 论文路径边。
  - A4 超规模：明确拒绝；范围内按已确认负载测 P95，当前 `NOT RUN`。
- **后置：** 只读；路径可复核同一图版本。
- **AC 覆盖：** IN01-01～04、FR12-05。

### UC-18 管理来源及采集任务

- **目标：** 管理员配置获准来源、创建/启动/停止/重试任务，查看处置与待核验。
- **对应需求：** FR08；AC-IMPL-FR08-01/02；BR-IMP-04。
- **主要参与者：** 管理员；次要参与者：获准数据来源。
- **前置：** 管理员有来源/任务权限；来源已核验许可和范围。
- **主成功场景：**
  1. 管理员配置来源与范围，创建任务。
  2. 系统保存参数快照和检查点，启动后读取记录。
  3. 每条已读记录完成入库、异常移交或待核验处置。
  4. 任务成功后显示汇总和待核验数量，不表示全部人工核验完成。
- **备选/异常：**
  - A1 人工停止：保留历史成果和已完成项。
  - E1 读取/处理失败：任务失败，保存完成项和恢复入口。
  - E2 队列交接失败：不算成功完成。
  - E3 重试：不新增重复实体/唯一出处，能定位失败点。
- **后置：** 任务状态与 SRS §6.2 一致；不删除历史。
- **AC 覆盖：** FR08-01/02。

### UC-19 管理来源更新

- **目标：** 按来源身份/版本识别新增、未变、变更、失效，安全处理更新与恢复。
- **对应需求：** FR10；AC-IMPL-FR10-01/02；BR-IMP-04/10。
- **主要参与者：** 管理员；次要人员：来源。
- **前置：** 来源启用、更新范围明确、管理员有任务权限。
- **主成功场景：**
  1. 系统取得新一轮记录，识别来源身份和原版本。
  2. 分类为新增/未变/变更，保存检查时间和来源更新时间。
  3. 新增交治理；未变不造变更；变更显示前后差异。
  4. 无人工结果冲突的变更按规则生效；与人工结果冲突保留公开值并进入待核验。
  5. 显示汇总和轨迹；生效结果传播到相关视图。
- **备选/异常：**
  - A1 无变更游标：采用管理员指定的回溯范围并披露局限。
  - A2 来源报删除/撤稿：记录事件，不因响应缺少记录就推断删除。
  - E1 断连/失败：历史仍可查，保留恢复入口，不覆盖人工值。
  - E2 身份无法识别：转异常/候选，不凭标题相似判同版本。
  - E3 更新期间人工值变化：生效前重检，不能覆盖后来确认值。
- **后置：** 失败不回退业务结果；成功范围可追踪。
- **AC 覆盖：** FR10-01/02、FR09-03。

### UC-09 / UC-10 摘要

- **UC-09 核验和纠正成果数据：** 治理管理员依据候选/告警处理清洗、去重、版本和字段冲突；标题相似/无稳定键只形成候选转人工；保留原值和证据。AC：FR09-01/02/03/04/05/06。
- **UC-10 核验学者身份与归属：** 管理员/相关学者处理同名、别名、机构历史、外部标识与 Authorship 状态；管理员审核不等于本人确认；已排除不因重采恢复。AC：FR15-01/02/03/04/05/06。

### UC-11 / UC-12 / UC-13 摘要

- **UC-11 查看成果统计：** 按去重实体统计类型/年份/领域，披露范围、口径、时间；真实/模拟分开。AC：FR11-01/02。
- **UC-12 查看机构排名：** 采用成果发生时机构证据，同一成果单机构一次、多机构各一次，未知单列；不得用当前主页机构回填。AC：FR11-01/02。
- **UC-13 查看领域热点：** 固定领域/年份窗/数据类别，以公开真实论文关键词或登记主题计数；稀疏时提示样本有限，不做质量结论。AC：FR13-01/02。

- **UC-16 核对四类覆盖与来源：** 访客核对四类成果是否可识别、来源是否合法、跨来源/版本是否按去重实体计数。AC：FR16-01/02。
- **UC-17 后台待办与审计：** 有具体权限的管理员处理采集、治理、认领、成果变更等待办，查询操作者/对象/时间/前后值/理由；私有证明不向普通用户公开。AC：FR14-01/02。

## 4. 关系判断

- **include：** UC-04 必然包含“创建唯一 UserProfile 与稳定地址”；这是注册成功的组成部分，不是可选行为。
- **extend：** 本阶段没有为形式而新增 extend。UC-05 的争议/补充分支由状态机表达；UC-22 的学术字段越权分支引导至 UC-07/08，但不在图中画成必然 include。
- **generalization：** 不建立“注册用户继承访客”的 Actor 继承来表达状态；按业务职责分别连线，避免把登录状态当作永久角色层级。
- **不作为外部用例：** 清洗、去重、消歧算法、数据库写入、消息发送均为系统内部职责。
