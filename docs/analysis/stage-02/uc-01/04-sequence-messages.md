## 1. 顺序图范围

本序列只实现UC-01的公开检索与分页：

- 范围分为“成果”或“学者”，两者互斥；
- 成果范围应用类型/年份/领域/发生时机构筛选；
- 学者范围不套用成果专属筛选；
- 无匹配、执行失败、非法条件分别处理；
- 下一页复用同一查询上下文。

成果详情（UC-02）、主页（UC-03）、统计/网络（UC-11～15）不进入本序列。

## 3. 关键协作说明

### 3.1 范围互斥

M7与M9由M3的`范围`校验选择：

- 成果范围只向`WorkEntity`查询，不向`Scholar`查询；
- 学者范围只向`Scholar`查询，不向`WorkEntity`查询；
- 满足AC-01“成果范围不返回学者”。

### 3.2 条件交集与公开过滤

成果查询使用：

- 关键词；
- 类型；
- 年份（两端含）；
- 领域；
- 发生时机构。

上述条件取交集。M13再次复核公开/有效和条件交集，避免实体返回待审/越权/不满足条件项。M13是分析级守卫，不是对实体能力的不信任。

### 3.3 无匹配与执行失败

- M15/M16只用于“执行成功但没有匹配”；
- M11/M12只用于“依赖失败或超时”；
- 两者不共用同一个“空结果”消息，避免AC-03/NF01混淆。

### 3.4 分页一致性

M6固定查询上下文；M17返回当前页和可复用上下文；M19/M20只传同一上下文，M21不重新解释条件，使用稳定排序和稳定实体ID继续分页。A-01说明同一读取版本的具体机制未冻结，本序列不指定快照/数据库/索引实现。

### 3.5 只读边界

本UC所有消息都是查询/展示；没有创建、修改或删除消息。详情跳转属于UC-02，不在本序列。

## 4. 消息完整性检查

| 检查 | 结果 |
|---|---|
| 每条消息有发送者/接收者 | 是，M1–M23 |
| 接收者有职责 | 是 |
| 是否对应事件步骤 | 是：E1–E9、A1–A3；A4（学者范围携带成果专属筛选）并入M3/M4非法条件分支，不另设消息 |
| 是否出现实现技术 | 否 |
| 是否出现Actor作为系统类 | 否 |
| 是否把空结果与失败混用 | 否 |
| 是否有遗漏的详情/主页/网络 | 否；明确排除 |
