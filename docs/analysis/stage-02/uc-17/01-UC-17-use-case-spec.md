> **范围边界：** 本 UC 只处理“**后台统一入口的待办聚合与只读导航**”和“**受保护写入事件的审计查询与可追溯性核对**”两件事。
> 采集与增量任务（启动/停止/重试/失败恢复）属 UC-18/UC-19；成果清洗与去重处置属 UC-09；学者身份与归属判定属 UC-10；认领申请与审核决定属 UC-05/UC-06；学者档案维护属 UC-07；本人确认/补录/纠错属 UC-08；普通主页编辑属 UC-22；公开展示属 UC-01/02/03/11/14/15。
> 本 UC **不执行任何处置决定**：不批准、不驳回、不合并、不拆分、不授权、不改归属、不启动/停止/重试采集、不停用来源；**不建立通用工作流实体**（审批链/路由/指派/状态机/待办表）；**不补写、不修改、不删除**任何留痕；**不把**待办视图当作可写队列。

> **对象区分（本 UC 的核心边界）：**
> - `AdminConsole` 是**唯一后台入口的边界类**：接收入口请求、待办浏览、导航选择与审计查询条件；显示待办视图、审计结果、拒绝/越权/空/失败/遮蔽/留痕不完整。它**不是**各属主 UC 的处置界面，也不代替服务端授权。
> - `AuditCoordinator` 是**审计与待办聚合的协调者**：服务端校验账号状态与**具体管理权限**、按权限裁剪类别与范围、以只读方式聚合待办、把处置导航回属主 UC、执行审计查询守卫与五要素完整性核对、遮蔽敏感字段、记录受控拒绝/越权/查询访问留痕。
> - **待办视图不是实体**：它是由属主对象状态（任务失败/异常移交、候选待核验、认领待审核/待补充/争议、授权争议入口、关系待核验/争议）**即时派生**的只读投影，只携带类别、计数、属主 UC 与对象引用；本 UC 不为它定义状态、不推进它、不持久化“谁在处理”。
> - `AuditEvidence` 是**已发生动作的追加式留痕**（操作者/对象/时间/前后值/理由/结果），覆盖被拒绝与未写入的尝试；本 UC **只读**它做核对，仅追加“查询访问/拒绝/越权”自身的受控留痕。
> - `ReviewEvidence` 是**提交给审核的说明与佐证材料**（提交者本人＋有权审核者按需可见），不是留痕、不是公开字段；审计结果只引用它并携带可见范围，**不返回原件**（FR14-02；NF06；BR-IMP-11）。
> - `User` 提供**账号状态与具体管理权限事实**；本 UC 不新增账号属性、不把“管理员”当作全量超级权限（FR14“不同管理员仍遵守对应权限”）。
> - `CollectionTask`/`DedupCandidate`/`IdentityCandidate`/`ClaimApplication`/`ScholarAuthorization`/`Authorship` 均为**属主 UC 的业务对象**，本 UC 只读其“待处理状态/计数/引用”，不写任何状态。

## 1. 参与者

| 类型 | 参与者 | 说明 |
|---|---|---|
| 主要参与者 | 有权管理员（具备该类别具体管理权限） | 打开统一后台入口、浏览本人有权类别的待办、导航到属主 UC 处置、查询审计（FR14 参与者“管理员”；§8“具体管理权限”；DGM-USECASE-06 actor“有权管理员”） |
| 次要参与者（被服务对象） | 普通登录用户 | **不得**使用管理入口；直接访问或提交管理操作被拒绝且无业务变更（`AC-IMPL-FR14-01`；BR-IMP-05；§8） |
| 次要参与者（只读边界） | 访客 | 无后台入口；不得看到待办、审计结果或证明原件（BR-IMP-01/11；NF06） |
| 上游（图外，触发方） | 各属主 UC 的管理员动作与系统事件 | UC-18/19 采集/增量、UC-09 成果治理、UC-10 身份与归属、UC-05/06 认领与审核、UC-07/08 档案维护与本人纠错——**产生**本 UC 所读的待处理状态与留痕；本 UC 不替它们执行 |
| 只读被查询对象 | 任务、候选、申请、授权、参与关系、材料、留痕 | 本 UC 只读取状态/计数/引用与留痕；不写业务状态（见 05 §2） |

> 不引入“超级管理员／管理员等级树／审批链／工单受理人”：基线只要求“不同管理员仍遵守对应权限”，未定义角色继承与指派模型（FR14；NF03；B-01）。也不把“系统”画成参与者：系统动作由 `AuditCoordinator` 与属主 UC 的协调者实现。

## 2. 目标

在**入口统一、权限不统一**的前提下，让有权管理员在一个入口看到“本人有权处理”的六类待办（采集、异常治理、学者核验、认领审核、成果变更、账号/分类/来源维护），并能**导航**到属主 UC 处置；同时让“关键批准、拒绝、合并、拆分、授权事件”的操作者/对象/时间/前后值/理由可被审计查询定位与核对，缺要素时明确暴露而不伪造；普通用户与非授权管理员既看不到待办也看不到证明材料原件。

## 3. 触发事件

1. 管理员登录后打开统一后台入口，浏览待办与进入处置入口；
2. 管理员提交审计查询（按对象/操作者/时间范围/事件类型/结果），核对关键事件的可追溯性；
3. 普通登录用户或未授权请求者直接访问管理入口或提交管理操作（用于触发拒绝路径，不改变任何业务状态）。

## 4. 前置条件

1. 请求方已通过认证；账号状态与“具体管理权限”每次都在服务端校验，入口是否可见不构成授权（NF03；`AC-IMPL-NF03-01`；§8）。
2. 属主 UC 已产生待处理状态或留痕：采集/增量任务状态（FR08/FR10）、治理候选（FR09）、身份/归属候选与争议（FR15）、认领申请状态与对象级授权（FR05）、档案待审变更（FR06）、关系待核验/争议（§6.4）。其中档案/成果变更**申请**的状态是否成为可见待办来源未冻结（B-07），本 UC 只保留导航入口。
3. 关键事件留痕由**受保护写入方**（FR05～FR10/FR14/FR15 的属主 UC）在写入时记录；本 UC 不产生这些留痕，也不回填（BR-IMP-10；INV-10）。
4. 证明材料原件只属于提交者本人与有权审核者；审计查询不改变其可见范围（`AC-IMPL-NF06-01`；BR-IMP-11）。
5. 管理权限的类别划分粒度、审计查询权限是否独立于处置权限、留痕保留期限与遮蔽范围**未冻结**（B-01/B-03/B-04；D-09）。

## 5. 成功与失败后置条件

### 5.1 成功（待办浏览与导航）

1. 返回该管理员**有权**访问的类别与范围；无权类别不出现（或明确拒绝），且“未显示”不等于“已授权”（M5/M6；FR14；§8）。
2. 待办视图按类别给出计数、属主 UC 与对象引用，按稳定顺序排列（B-06 排序/计数口径待确认）；视图是**只读派生投影**，不是可写队列（M21/M23）。
3. 导航只携带“属主 UC＋对象引用＋只读上下文”，**不携带处置动作**；处置在属主 UC 完成（M25–M27；FR14）。
4. 不产生、不推进、不关闭任何业务状态；不改变申请/候选/关系/授权/任务的既有状态（BR-UC17-05）。
5. 若某待办项已被他人处置，视图只显示属主对象**最新状态**，不覆盖他人决定（A10；M22）。

### 5.2 成功（审计查询）

1. 返回匹配的留痕：事件类型、操作者、对象、时间、前后值、理由、结果；按时间排序并保留追加链（M35；BR-IMP-10；INV-10）。
2. 对关键事件执行五要素核对；缺任一要素时该项标“留痕不完整”，**不补写、不推断、不当作可追溯通过**（M36/M37；A6）。
3. 证明材料以“引用＋可见范围”呈现；原件仅“有权审核者按需可见”，**不进入普通用户可见范围**，也不进入安全审计字段（M38–M40；A5；`AC-IMPL-FR14-02`；NF03/NF06）。
4. 超出该管理员授权范围的查询条件被裁剪并**显式声明裁剪**，不静默返回全量（M32；A4；B-01）。
5. 查询本身作为受保护访问追加留痕（分析推导；B-05 待确认），但该留痕**不包含**凭据与秘密（NF03）。

### 5.3 失败（无业务写入、无信息泄漏）

1. 未认证/账号停用、普通用户、缺少该类别或审计查询的具体权限：拒绝，返回可区分的结果；业务实体状态与留痕均不变（A1–A3；`AC-IMPL-FR14-01`；`AC-IMPL-NF03-01`）。
2. 不返回待办明细、留痕内容或证明材料原件；拒绝原因不包含他人私人信息与凭据（BR-IMP-11；NF03）。
3. 拒绝与越权尝试追加受控留痕（M54/M57；BR-IMP-10）。
4. 空结果、执行失败、无权限、已遮蔽、留痕不完整五类结果可区分（M44/M45/M56；NF01 类比）。
5. 查询/读取失败时不返回部分结果冒充完整，不改变任何状态（A8）。

| E17 | 系统执行敏感字段遮蔽：凭据、私人联系方式、非公开科研材料与秘密不进入查询结果与安全审计。 | NF03“安全审计不包含秘密信息”；BR-IMP-11；INV-08 |
| E18 | 系统返回审计结果（五要素＋材料引用与可见范围＋留痕不完整异常项＋裁剪声明），空结果/失败/无权可区分；并追加受控查询访问留痕。 | `AC-IMPL-FR14-02`；NF01 类比；BR-IMP-10；B-05（查询访问留痕待确认） |

## 11. 待确认

1. **B-01 管理权限的类别划分粒度与“审计查询权限”独立性**：FR14/§8 只写“具体管理权限”，未定义是否按六类细分、审计查询是否属于独立权限、范围是否按对象授权。本分析按“类别级具体权限＋审计查询权限”建模（M4/M5/M31），不定义权限矩阵（07 §6 建议 R5）。
2. **B-02 待办视图的载体与刷新口径**：即时派生查询还是持久快照、计数与列表是否同一版本、是否需要缓存/刷新时限，均未定义。本分析只要求“只读派生、不推进状态、最新状态可显示”。
3. **B-03 留痕保留期限与到期处置**（D-09）：未冻结，本分析不实现到期删除/匿名化，也不承诺可查时间窗（A12）。
4. **B-04 “证明原文”与遮蔽字段清单**（D-09 部分覆盖）：哪些属于“原文”、审计结果可否含材料摘要、私人联系方式的遮蔽规则，均待确认；本分析只要求“不返回原件、不返回明文敏感字段”。
5. **B-05 审计查询自身是否必须留痕/是否可导出**：SRS 未规定“查询访问留痕”与导出权限。本分析按“受控查询访问留痕”处理并标分析推导（M47），导出范围与权限待确认。
6. **B-06 待办计数与排序口径**：按类别计数还是对象计数、跨类别稳定排序键、分页大小均未定义；本分析只要求“稳定顺序、计数与状态一致”。
7. **B-07 成果变更待办的状态来源**：本包只读 `Authorship` 的待核验/争议状态，`CorrectionRequest`（UC-08）与 `ScholarChangeRequest`（UC-07）仅作为导航入口，未读取其状态。若评审要求显示其申请状态，需增补两个只读类并重渲 VOPC。
8. **B-08 账号/分类/来源维护入口的范围**：来源停用/更换属 FR10/UC-19；机构/领域“分类”在基线与 SPEC 中只有字典/映射概念，无独立业务对象与 AC。本 UC 只保留导航入口，不定义分类实体。
9. **B-09 会话/凭据是否成为独立分析对象**（沿用 UC-04/06/07/08/09/10）：本 UC 作为请求上下文，不建模。
10. **B-10 命名与追踪**：`AdminConsole`/`AuditCoordinator`（`01-BCE`）与全局图 `AdminUI`/`AuditCtl`；`Evidence`/`AuditEvidence` 一名多义；追踪表是否增补 `SEQ-16/VOPC-12`、NF06/NF07 是否增列 UC-17 —— 均留 R5（D-11/D-13），另见 07 §2/§6。
