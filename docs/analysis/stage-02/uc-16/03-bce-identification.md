# UC-16 Boundary / Control / Entity 识别

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.4.2：从本 UC 事件流识别边界、控制、实体类；不从全局 BCE 反向填充，也不照抄全局 `DGM-CLASS-01`。
**输入：** 本目录 [01 用例规约](01-UC-16-use-case-spec.md)、[02 事件流与来源](02-event-flow-trace.md)；上游 [`uc-02/`](../uc-02/03-bce-identification.md)（`WorkEntity`/`SourceRecord`/`WorkVersion` 的字段语义）、[`uc-09/`](../uc-09/03-bce-identification.md)（去重实体计数口径）。

## 1. 识别原则

1. Boundary 承接“发起核对”与“显示覆盖/规模结论、缺项、差异、失败”，并显示数据性质分组与目标值实测状态。
2. Control 协调“固定范围与截止时间 + 读四类可识别事实 + 读合法来源事实 + 按去重实体计数 + 按数据性质分组 + 区分失败与零覆盖”，并保证核对结论只是本次请求的投影。
3. Entity 只承载可核实的持久业务事实：去重成果实体（含类型适用字段事实）、来源记录、明示版本证据。
4. 只有在本 UC 事件/消息中实际出现的对象进入 VOPC；**核对结果不是实体**（读时投影），不得建 `CoverageReport`/`ScaleResult` 类。
5. 检索、详情展示、治理写侧、采集任务、统计与网络对象不属于本 UC，不强行纳入。

## 2. 候选分析类

| ID | 候选类 | 类型 | 发现事件 | 业务行为 | 为什么不能由其他候选承担 |
|---|---|---|---|---|---|
| C1 | `CoverageCheckUI` | Boundary | E1、E10、E11；A1–A4、A8–A10 | 接收公开覆盖核对/规模核对请求与范围声明；显示四类覆盖结论、缺项、可定位差异、去重实体总量与分组计数、真实数单列与模拟/混合标注、目标值 NOT RUN、执行失败与原站外链 | Entity 不承接请求与展示；Control 不直接面对访客/核对执行者；`WorkEntity` 等只能回答自身事实，不能呈现“覆盖/不通过/差异”结论 |
| C2 | `CoverageCheckCoordinator` | Control | E2–E10；A1–A12 | 固定范围与截止时间；判定样例可读性；逐类核对三项合取；以去重实体为计数单位；按数据性质分组；披露待核验与不确定版本口径；区分缺项/差异/失败；声明只读与 NOT RUN | 守卫同时依赖 `WorkEntity`（类型、字段、公开状态、数据性质、计数单位）、`SourceRecord`（许可与来源级事实）、`WorkVersion`（明示版本证据）；任何单一实体只能自知，且必须保证“来源数/版本数不进分子”“缺失不造值”“失败≠零覆盖” |
| C3 | `WorkEntity` | Entity | E3、E4、E7、E9；A2、A4、A5、A7、A11 | 提供去重成果实体的类型、公共字段、公开生效状态、类型适用字段事实（缺失标未知）、数据性质标识；作为唯一计数单位 | `SourceRecord` 是逐条出处证据，来源数不等于成果数（INV-02）；`WorkVersion` 是版本证据不是计数单位；`Authorship` 是参与关系，本 UC 无消息 |
| C4 | `SourceRecord` | Entity | E5；A3、A12 | 提供来源 ID、采集/导入时间、许可或使用范围、数据性质、原站地址；回答“该来源是否合法可公开”“是否仍保留” | 许可与采集时间是**来源级**事实（FR16；INV-01），成果实体只说明“有哪些来源”，不能替代逐来源许可判定；也不能用成果级数据性质替代来源级性质 |
| C5 | `WorkVersion` | Entity | E8；A5、A6 | 回答该成果是否存在**明示证据**的版本关系，使“跨两来源+版本关联”仍按 1 个实体计数；无证据时回答“无版本关系” | 版本证据是“同一成果内部发布形态”的事实，与成果身份、来源出处都不同层；若并入 `WorkEntity` 或 `SourceRecord`，无法表达“无明示证据不得并入”的门槛（DD-08） |

## 3. 逐类选择理由

### C1 CoverageCheckUI（Boundary）

- 发现于 E1（发起核对、声明范围）、E10（显示结论）、A8（差异）、A9（失败）、A10（未声明范围）。
- 只做输入承接与展示：不判定合法来源、不计算去重实体数、不决定数据性质分组，也不判断“是否通过”。
- **命名说明：** 全局 `PublicPortalUI` 的 UC 列表**包含** UC-16（见 [01-BCE分析类模型.md](../01-BCE分析类模型.md) §2），但该边界职责写的是“展示公开检索、详情、主页、统计、网络与错误/空态”，没有“覆盖与规模核对”语义；`SearchUI`/`WorkDetailUI` 也不承接核对的缺项与差异。本 UC 用 `CoverageCheckUI` 表达“核对入口/结论展示”这一独立边界，合并建议留 R5（[07](07-global-model-diff.md) §2）。

### C2 CoverageCheckCoordinator（Control）

- 发现于 E2–E10 的完整核对过程与 A1–A12 的分支裁决。
- 必须同时协调三类实体，并保证：①覆盖三项合取；②计数单位是去重成果实体而非来源/版本；③真实数单列、模拟/混合显式标注；④缺项与差异可定位且不宣布通过；⑤失败与零覆盖可区分；⑥结果为读时投影、不回写。
- **不复用 `SearchCoordinator`/`StatisticsCoordinator`**：检索协调器承载查询条件、排序与分页语义，统计协调器承载分布/排名/机构归属语义；覆盖与规模核对没有查询条件与维度聚合，其守卫是“样例可辨识＋合法来源＋去重计数＋数据性质分组”。三者共享“按去重实体计数”这一口径，但口径来源在 UC-09，不在本 UC（BR-UC16-14）。

### C3 WorkEntity（Entity）

- 发现于 E3（类型/公共字段/公开状态）、E4（类型适用字段）、E7（计数单位）、E9（数据性质）。
- **类型适用字段事实的边界（本 UC 必须区分）：** 论文 DOI/发表年份/载体、专利申请号/申请日/公开日、项目编号/起止/承担单位、获奖年度/奖项/获奖团队，都是**同一成果实体在其类型范围内的字段事实**，随类型不同而适用；它们既不是来源事实（不随来源数量增加），也不是版本事实（不随版本变化），因此作为 `WorkEntity` 的类型范围属性承载（`typeFieldFacts`），**不设独立类**（见第 4 节拒绝项）。
- 不能并入 `SourceRecord`：来源数不增加成果数（INV-02）；`AC-IMPL-FR16-02` 明确要求按去重实体计数。
- 不能并入 `WorkVersion`：版本只改变“发布形态”，不改变“是否为一个实体”。

### C4 SourceRecord（Entity）

- 发现于 E5（许可来源与来源级事实）、A3（无许可）、A12（停用/失效仍保留）。
- 独立理由：FR16 明确“**每条来源**保留来源ID、采集/导入时间、许可或使用范围与数据性质”；INV-01 要求来源原值不被改写；BR-IMP-04 要求停用/失败不删除历史。
- 不能并入 `WorkEntity`：若只留成果上的聚合字段，就无法表达“同一成果两条来源许可不同、采集时间不同”，也无法支撑“合法来源”的逐条判定。

### C5 WorkVersion（Entity）

- 发现于 E8（明示版本关系）、A5（跨来源+版本仍计 1）、A6（无明示证据不并入）。
- 独立理由：`AC-IMPL-FR16-02` 的 Given 是“跨两个来源且有版本关联”，其 Then 是“按去重实体不按来源数/版本数计”；要证明这一条，必须能区分“版本证据存在/不存在”并给出“版本不增加实体数”的门槛。DD-08 规定无明示证据保持独立、只能标疑似。
- 不能并入 `SourceRecord`：版本是发布形态，来源是出处；同一版本可有多个来源，同一来源也可承载版本信息，两者不是同层事实。

## 4. 被拒绝的候选类

| 候选 | 拒绝理由 | 依据/后续 |
|---|---|---|
| `CoverageReport` / `ScaleCheckResult` / `CoverageSnapshot` / `AcceptanceReport` | 核对结论是**读时投影**；若持久化就必须同时定义范围版本、生效状态、失效与回退、留痕，V2.2 与 SPEC 均未定义。本 UC 按 BR-UC16-09 不建类，投影字段作为协调器分析态 | 分析推导；05 §4；Q-09 |
| `ScaleTarget` / `Threshold` / `AcceptanceCriteria` | 1,000,000/5,000,000 是需求中的**目标值**，不是业务实体；本 UC 在协调器分析态中作为声明常量披露并标 NOT RUN | SRS §2.1、FR16；Q-08 |
| `TypeSchema` / `FieldDictionary` / `TypeFieldCatalog` | 四类适用字段是 `WorkEntity` 的类型范围属性事实（`typeFieldFacts`），没有独立生命周期与对外行为；建类会把 §7.1 的字段表误做成可维护的元数据对象（该维护能力未在基线定义） | §7.1；分析推导 |
| `SearchUI` / `SearchCoordinator` | 覆盖核对不检索、不筛选、不分页；检索已有独立协调器（UC-01） | UC-01；07 §3 |
| `StatisticsUI` / `StatisticsCoordinator` / `Institution` | 统计按类型/年度/领域/机构维度聚合与排名，本 UC 只做覆盖判定与总量分组；维度聚合不属 FR16 | FR11；UC-11/UC-12；07 §3 |
| `WorkDetailUI` / `WorkDetailCoordinator` | 详情协调器承载“一条成果的字段/来源/版本/参与关系组装与公开过滤”，本 UC 承载“四类覆盖判定与去重规模核对”；两者可读同一实体但不共享守卫 | FR02；UC-02；07 §3 |
| `Authorship` / `Scholar` | 本 UC 无参与关系/身份消息：覆盖判定不使用作者数，规模分子不受参与关系影响（BR-UC16-05） | FR15；INV-02；05 §4 |
| `CleanRecord` / `DedupCandidate` | 清洗与候选核验是治理写侧事实；本 UC 只读治理结论与计数口径 | FR09；UC-09 |
| `CollectionTask` / `SourceDefinition` / `SourceAdapter` | 本 UC 不读任务状态，不据任务“成功”推断覆盖通过；来源接入属 UC-18/19 | §6.1/§6.2；UC-18 |
| `DataOrigin`（独立类） | 真实/模拟/混合是互斥标识属性（成果级）与来源级属性，不是有身份的实体 | BR-IMP-07；INV-09 |
| `AuditEvidence` | 本 UC 只读、无受保护写入；核对历史是否留痕未冻结（Q-09） | FR09-S12；BR-IMP-10；UC-17 |
| `Session` / `CredentialContext` | 访客公开核对无需登录；核对执行者的权限校验属发布/管理侧通用约束，不作为本 UC 业务对象 | NF01；SRS §8；Q-02 |
| 视图 DTO（`CoverageView`、`GroupedCount`、`DifferenceList`） | 交互态投影，不是业务事实 | 教材 §5.4.2/§5.5.2 |

## 5. 边界结论

| 边界 | 结论 | 证据 |
|---|---|---|
| `WorkEntity` vs `SourceRecord` | 成果是去重实体与计数单位；来源是逐条出处证据；**来源数不进入规模分子** | `AC-IMPL-FR16-02`；BR-IMP-02；INV-02 |
| `WorkEntity` vs `WorkVersion` | 版本只在有明示证据时关联；**版本数不进入分子**；无证据保持独立 | FR02；DD-08；`AC-IMPL-FR16-02` |
| `WorkEntity` vs 类型适用字段事实 | 类型适用字段是成果实体的类型范围属性，随类型适用、缺失标未知；不是独立实体 | §7.1；SPEC §3；BR-UC16-04 |
| `SourceRecord` vs 成果级数据性质 | 来源级性质逐条保留；成果级真实/模拟/混合为**互斥标识**；两者不互相替代 | FR16；BR-IMP-07；INV-09；Q-04 |
| 覆盖判定 vs 规模计数 | 覆盖是“样例可辨识＋字段可得＋合法来源”的三项判定；规模是去重实体计数；两者不可互相替代 | `AC-IMPL-FR16-01` vs `AC-IMPL-FR16-02` |
| 目标值 vs 实测结果 | 1,000,000/5,000,000 是目标；无运行证据一律 NOT RUN | SRS §2.1；NF02 |
| 核对结论 vs 持久报告 | 核对结论是本次请求的读时投影，不持久化、不成为新实体 | BR-UC16-09；分析推导 |
| 写边界 | 只读：不合并/拆分实体、不改公开状态、不建版本关系、不删来源 | FR09；BR-IMP-01/04；UC-09 |
| 治理边界 | 去重结论与计数口径由 UC-09 生效；本 UC 不重新判定去重 | FR09；BR-IMP-02；UC-09 |

## 6. 识别结论

本 UC 的参与分析类为 5 个：

- Boundary：`CoverageCheckUI`
- Control：`CoverageCheckCoordinator`
- Entity：`WorkEntity`、`SourceRecord`、`WorkVersion`

不引入核对报告/规模结果/目标阈值/字段字典/检索/统计/详情/参与关系/治理记录/采集任务/审计等类；这些要么属于其他 UC，要么是属性、投影或实现设计。
