# UC-16 分析与现有全局分析类差异

**版本：** V1.0（2026-10-21）
**比较对象：** [`DGM-CLASS-01-analysis.puml`](../../../uml/analysis/DGM-CLASS-01-analysis.puml)、[`01-BCE分析类模型.md`](../01-BCE分析类模型.md)、[`analysis-class-registry.md`](../automation/analysis-class-registry.md)、既有活动模型 [`DGM-ACTIVITY-07-search.puml`](../../../uml/analysis/DGM-ACTIVITY-07-search.puml)（追踪表中 FR16 的 ACT-07）。
**原则：** 全局图只作比对材料，不作为 UC-16 类识别的反向答案；本轮不重构全局图，只登记 R5（第 6 阶段）建议。

## 1. 已存在且一致

| UC-16 概念 | 全局图对应 | 一致点 | 证据 |
|---|---|---|---|
| `WorkEntity` | `Work`（Entity，`+去重规范值/成果类型/生效状态`） | 都是去重后的四类成果实体，承载类型与生效状态；都不是来源记录 | FR16；BR-IMP-02；`AC-IMPL-FR16-02` |
| `SourceRecord` | `Source`（Entity，`+原值/来源/许可`、`+逻辑出处`） | 都表达逐条出处、许可与原始值；来源数不等于成果数 | FR16；INV-01/02 |
| `WorkVersion` | `Version`（Entity，`+版本证据`） | 都表达“有证据的版本关系”，无证据不合并 | FR02；DD-08 |
| 成果—来源—版本分离 | 全局 `Source -- Work`、`Work -- Version` | 全局无“成果+来源”合并类，方向一致 | FR16；INV-02 |
| 覆盖核对只读 | 全局无“核对写”职责（写职责在 `GovernCtl`/`CollectCtl`/`AuditCtl`） | 覆盖与规模核对不写实体 | FR09 属 UC-09；分析推导 |

## 2. 命名/别名差异

| 本 UC 名称 | 全局名称 | 差异 | R5 建议 |
|---|---|---|---|
| `CoverageCheckUI` | 无直接对应；相关：`PublicUI`（图）/`PublicPortalUI`（表，UC 列表含 UC-16）、`AdminUI`（图）/`AdminConsole`（表） | 全局把“覆盖与规模核对”并入公开门户或管理入口，无独立核对语义；01 表把 UC-16 列在 `PublicPortalUI` 下，但其职责只写“展示公开检索、详情、主页、统计、网络与错误/空态” | 明确“覆盖与规模核对”是否有独立边界正式名；可并入 Public 系（对外部分）或 Admin 系（受控部分），或保留 `CoverageCheckUI` |
| `CoverageCheckCoordinator` | 无对应；最近的是 `SearchCtl`（`+公开过滤/稳定排序`）、`GovernCtl`（`+清洗/去重/候选`）、`GraphCtl`（`+四类基础边/论文路径`） | “覆盖判定＋去重实体计数＋数据性质分组＋目标值披露”在全局无协调者：`SearchCtl` 无核对语义，`GovernCtl` 是写侧，`GraphCtl` 是网络 | 建议新增或明确“核对/披露”协调者归属（不得并入 `GovernCtl`，否则把只读核对与写侧治理混为一类） |
| `WorkEntity` | `Work` | 实体名不一致 | 以全局 `Work` 为正式名，`WorkEntity` 作为本 UC 别名（与 UC-01/UC-02 处理一致；登记表已注明） |
| `SourceRecord` | `Source` | 实体名不一致 | 统一为 `SourceRecord` 或登记别名表（D-11） |
| `WorkVersion` | `Version` | 实体名不一致；`Version` 易与“版本号/图版本”混淆 | 统一为 `WorkVersion`（与 UC-02/UC-09 一致） |

> 全局边界名自身存在两套写法（图内 `PublicUI`/`AdminUI`/`SourceUI` 与 01 文档表的 `PublicPortalUI`/`AdminConsole`/`SourceAdapter`）。这是既有不一致，本 UC 只登记，不改。

## 3. 职责/关系缺口

| 项目 | 本 UC 证据 | 全局现状 | 差异/影响 | R5 处理 |
|---|---|---|---|---|
| 覆盖判定（四类可识别＋类型字段＋合法来源） | `AC-IMPL-FR16-01`；E3–E6；M5–M13 | 全局无覆盖判定职责；`Work` 只有“去重规范值/成果类型/生效状态”，无“类型适用字段可得性/未知标注” | “四类可识别且显示合法来源”缺静态职责支撑 | 在核对协调者职责中补“覆盖三项合取”，并在 `Work` 职责中补“类型适用字段（缺失标未知）” |
| 去重实体计数与“不按来源数/版本数” | `AC-IMPL-FR16-02`；M14–M18 | 全局 `Source -- Work`、`Work -- Version` 未标多重性；无计数职责 | 计数口径可能被实现成“按来源/版本计” | 标 `Work 1 — 0..* Source`、`Work 1 — 0..* Version`，并注明“计数单位为 Work 实体” |
| 版本证据门槛 | FR02；DD-08；M16/M17 | 全局 `Work -- Version : 明示版本` 无门槛说明 | 门槛可能被忽略 | 在边上注明“无明示证据不建立/不并入” |
| 数据性质互斥分组与真实数单列 | BR-IMP-07；INV-09；`AC-IMPL-FR16-02`；M19–M21 | 全局 `Work` 无数据性质字段；`Source` 只有“原值/来源/许可” | 真实/模拟/混合分组无模型支撑 | 在 `Work` 属性中补 `dataOrigin`（互斥标识），在 `Source` 中注明来源级性质，并明确聚合口径（Q-04） |
| 来源级四要素（ID/采集时间/许可/性质） | FR16；E5；M11/M12 | 全局 `Source` 写“原值/来源/许可”，未列采集/导入时间与数据性质 | 来源可追溯要素可能缺项 | 在 `Source` 职责/属性中补 `arrivalAt`、`dataOrigin`（沿用 UC-02 06 §5） |
| 目标值 vs 实测状态（1,000,000/5,000,000；NOT RUN） | SRS §2.1、FR16、NF02；M22/M25 | 全局无目标值/实测披露职责 | 可能把目标当已达标宣称 | 在核对职责或项目级声明中补“目标值必须标未运行”；不建目标值实体 |
| 缺项/差异披露与“不宣布通过” | FR16-S03 E1/E2；M23/M24 | 全局边界只写“展示…错误/空态” | 缺项与“零覆盖/失败”易被合并 | 在核对边界职责中显式区分“缺项/差异/执行失败” |
| 核对结果不持久化 | E10；M25/M28；Q-09 | 全局无该类，也无“读时投影”说明 | 可能被实现为持久核对报告 | 在协调者职责中注明“结果为读时投影，不新建持久报告类” |

## 5. 与既有活动模型（ACT-07）的差异

追踪表把 FR16 的既有分析模型记为 `DGM-USECASE-04 / ACT-07`；`DGM-ACTIVITY-07-search.puml` 是“公开检索、筛选与稳定分页”的活动图，其末尾仅有“打开成果详情或公开主页”一步，注释提到 `AC-IMPL-FR02-01/02`。

| 项目 | ACT-07 现状 | 本 UC 需要 | 差异结论 |
|---|---|---|---|
| 四类覆盖核对 | 无该活动（检索流程图不判定四类样例/类型字段/合法来源） | 覆盖三项合取与缺项 | ACT-07 不能作为 UC-16 的活动证据；本 UC 只交顺序图与 VOPC，不新增活动图 |
| 去重实体计数与数据性质分组 | 无 | 去重实体计数、真实数单列 | 同上 |
| 目标值披露 | 无 | 1,000,000/5,000,000 标 NOT RUN | 同上 |

因此本包**不**把 ACT-07 当作 UC-16 的实现证据，只在追踪层面沿用其作为“公开读取侧”的上游模型（见 [08](08-self-check.md) §2）。

## 6. 差异结论（R5 输入）

建议 R5 统一分析类时：

1. 明确“覆盖与规模核对”的边界归属与正式名，解决 `PublicUI`/`PublicPortalUI`/`AdminUI` 与 `CoverageCheckUI` 的归属冲突（并与 UC-01 `SearchUI`、UC-02 `WorkDetailUI`、UC-11 `StatisticsUI` 并列考虑）；
2. 决定“覆盖/规模核对”协调者是否独立存在；**不得**并入 `GovernCtl`（写侧治理）或 `SearchCtl`（检索条件语义）；
3. 统一 `Work`/`WorkEntity`、`Source`/`SourceRecord`、`Version`/`WorkVersion` 命名并登记别名（D-11）；
4. 为 `Work—Source`、`Work—Version` 补 `1 : 0..*` 多重性，并在边上注明“计数单位为 `Work` 实体，来源数/版本数不进入分子”与“无明示证据不建立版本关系”；
5. 在 `Work`/`Source` 职责中补：类型适用字段（缺失标未知）、来源 ID/采集时间/许可/数据性质四要素、数据性质互斥标识与分组口径；
6. 在核对职责中补：范围与截止时间声明、缺项/差异/执行失败三分、目标值必须标未运行、结果为读时投影不持久化；
7. 决定核对结论是否留痕（若留痕则需与 `Evidence`/`AuditEvidence` 统一，D-13）。

本轮**不直接修改** `DGM-CLASS-01-analysis.puml`、`01-BCE分析类模型.md`、`analysis-class-registry.md` 或 AC/UC 追踪表；登记表增量与追踪表补充（`SEQ-24`/`VOPC-20`）由父 Agent 在批次收口时统一写入。
