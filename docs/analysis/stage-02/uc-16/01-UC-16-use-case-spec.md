## 1. 参与者

| 类型 | 参与者 | 说明 |
|---|---|---|
| 主要参与者 | 访客 | 未登录即可核对公开可读的四类样例：四类是否可识别、类型适用字段是否可得、是否有合法来源（`AC-IMPL-FR16-01`；NF01；SRS §8“公开检索/详情/门户/统计/网络 = 读”） |
| 次要参与者 | 核对执行者（管理员） | 以去重成果实体为单位核对规模与真实/模拟/混合分组，并声明本次核对的数据范围与截止时间（`AC-IMPL-FR16-02`；FR16 参与者“系统/管理员/访客”；FR16-S03 参与者“管理员”） |

> 参与者口径说明：FR16 原文把参与者写为“系统/管理员/访客”。其中“系统”是执行主体，不是外部参与者，不画成分析类。stage-02 [`02-用例模型与规约.md`](../02-用例模型与规约.md) 的 UC-16 行写“访客、原站”，与 FR16 不完全一致；原站（外部来源）在本 UC **不参与**——外链跳转与其失效表达属 UC-02，本 UC 只读来源记录上的许可与数据性质（见 [08](08-self-check.md) §5 Q-02）。

## 2. 目标

让核对者用**可复核、可追溯**的最小证据回答三个问题，并且只用当前生效数据、不制造新事实：

1. **四类是否覆盖且可识别**：论文/专利/项目/获奖各至少有一条公开可读样例，样例的类型适用字段可得（缺失标“未知”），且至少有一条**合法来源**；
2. **来源是否可追溯**：每条来源保留来源 ID、采集/导入时间、许可或使用范围、数据性质；
3. **规模是否按去重实体计**：一条跨两个来源且有版本关联的成果在规模核对中计为**一个**去重实体；真实/模拟/混合分组互斥并分别计数，真实数单列；1,000,000 与 5,000,000 作为目标值如实标为**未运行**。

## 3. 触发事件

1. 访客发起公开覆盖核对（可按类型或全类型），目的为确认四类样例、适用字段与合法来源是否可读；
2. 核对执行者发起规模核对，并声明本次核对的数据范围与截止时间（FR16-S03 前置条件 2）；
3. 在已声明范围与截止时间内重新核对（同一范围口径的复核）。

## 4. 前置条件

1. 成果已经 FR09 治理形成去重成果实体并具备生效/公开状态；未通过治理的输入不得进入公开覆盖计数（§6.1“不存在自动‘采集过=已审核’的状态跳跃”；`AC-IMPL-FR08-01` 边界）。
2. 记录类型可识别为论文/专利/项目/获奖之一；缺类型或不属于四类的记录不得算作覆盖（SPEC §3“缺类型或名称不得生成公开有效成果”）。
3. 规模核对须先声明数据范围与截止时间，并声明待核验口径；未声明时不给通过结论（FR16-S03 前置条件 2；分析推导）。
4. 1,000,000（功能联调）与 5,000,000（最终容量）是**目标值**，本期无运行证据（SRS §2.1、FR16、NF02；`AC-IMPL-NF02-01/02` = NOT RUN）。
5. 本 UC 不要求任何外部来源当前可用：来源停用/外链失效不减少历史覆盖证据（`AC-IMPL-FR02-02`、BR-IMP-04；`AC-IMPL-NF07-01` 边界）。

## 5. 成功与失败后置条件

### 5.1 成功

1. 四类逐类给出**覆盖结论**：类型可识别、类型适用字段可得（缺失已标“未知”）、至少一条许可来源；四类均有可公开样例时覆盖成立（`AC-IMPL-FR16-01`；§7.1）。
2. 每条被引用的来源保留来源 ID、采集/导入时间、许可或使用范围、数据性质（FR16 原文；§7.1；BR-IMP-07）。
3. 规模核对以 `distinct(生效 WorkEntity canonical_id)` 计数；一条成果有两条来源且存在明示版本关联时仍计 **1**；来源数、版本数、参与关系数都不进入分子（`AC-IMPL-FR16-02`；BR-IMP-02；INV-02；DD-11）。
4. 真实/模拟/混合按互斥标识分组计数，**真实数单列**；模拟与混合显式标注，不以模拟容量冒充真实采集（BR-IMP-07；INV-09；SRS §2.1）。
5. 结果同时披露：本次数据范围与截止时间、待核验/异常输入口径与数量、不确定版本关联口径、结果生成时间（FR16-S03 主成功流程 1–3；分析推导）。
6. 1,000,000 与 5,000,000 的实测状态如实标为 **NOT RUN**，不声称已达规模（SRS §2.1、FR16、NF02）。
7. 核对结果是**读时投影**：不持久化为核对报告实体，不改变任何业务实体与公开状态（分析推导；BR-IMP-01）。

### 5.2 失败/异常后置条件

1. 某类型无可公开样例、类型不可识别或来源不合法：该类/该项覆盖**不通过**并列缺项，不用默认值或虚假样例补齐（FR16-S03 E1/E4；SPEC §3）。
2. 计数不一致（实体数、来源数、分类计数对不上）：显示可定位差异，**不宣布**覆盖或规模通过（FR16-S03 E2）。
3. 读取依赖失败或超时：返回**执行失败**，不伪装成“覆盖为零”（NF01；`AC-IMPL-NF01-01` 同类约束；NF02 5 秒超时为约束引用，未实测）。
4. 未声明数据范围/截止时间：不给出规模通过结论，先要求声明（FR16-S03 前置条件 2）。
5. 任何失败分支均不删除、不隐藏、不改写成实体或来源记录（BR-IMP-04；`AC-IMPL-FR02-02`）。

## 11. 待确认

1. **Q-01 核对范围的声明方式**：FR16-S03 要求“验收数据范围、截止时间和待核验处理口径已声明”，但未规定默认值、谁能声明、声明是否可复用；本 UC 只要求“未声明不给通过结论”（A10）。
2. **Q-02 参与者口径**：FR16 写作“系统/管理员/访客”，stage-02 `02-用例模型与规约.md` 的 UC-16 行写“访客、原站”。本分析按 FR16 纳入“核对执行者（管理员）”、并把原站排除（外链属 UC-02）；需联合评审确认最终参与者集合。
3. **Q-03 模拟样例是否可以补齐类型覆盖**：FR16-S01 A1 允许“某类缺真实来源时采用明确标识的模拟样例，不取消该类功能”，而 `AC-IMPL-FR16-01` 的 Given 是“四类各有一条可公开样例”。本 UC 按“模拟可覆盖功能、真实覆盖项单列不通过”处理（A1），聚合口径未冻结。
4. **Q-04 数据性质分组口径**：BR-IMP-07 只定义真实/模拟/混合互斥；性质“未确认”是否成为第四分组（单列）或并入待核验数量未冻结（A7；与 UC-02 Q-07 同源；模块侧 Q-204 类事项）。
5. **Q-05 待核验输入是否进入规模分子/分母**：本 UC 按“不进入分子、数量单列”处理（A11）；FR16-S03 只要求披露待核验数量。
6. **Q-06 差异定位粒度**：FR16-S03 E2 要求“显示可定位差异”，未规定差异维度（按类型/按来源/按分组）；本 UC 只要求可定位到差异项。
7. **Q-07 类型适用字段与人员角色的归属**：§7.1 把作者顺序/发明人/负责人/获奖人员列为类型字段；本 UC 沿用 UC-02 结论（角色/顺序归 `Authorship`，机构/团队留 `WorkEntity` 类型字段），需 R5 统一。
8. **Q-08 规模目标与模块细化的数值冲突**：模块 FR16-S03 正文仍写“清洗去重后实体总量不少于 10,000 条”（历史 V1.9 口径，Review Candidate），与 SRS V2.2 §2.1/FR16 的 1,000,000（功能联调）/5,000,000（最终容量）冲突。本 UC 以 SRS V2.2 为唯一基线，10,000 只作历史来源；模块需修订，登记待负责人决定。
9. **Q-09 核对结论是否需要留痕**：本 UC 按“读时投影、不留痕”处理；若要求可复核的核对历史，则涉及 `AuditEvidence`/治理留痕（FR09-S12、BR-IMP-10）与 UC-17 审计查询，需明确归属。
10. **Q-10 真实公开演示链是否硬门槛**：FR16-S03 E1 与 `AC-FR16-S03-01` 标注“一条真实公开来源演示链”是否作为本期硬性通过门槛**待 Q-207 确认**；本 UC 只如实披露真实/模拟分组，不据此判定总体验收。
11. **Q-11 “可检索”口径**：NF02 的“≥5,000,000 可检索去重实体”与 FR16 的“去重后可检索成果实体”是否等同按 `publicState` 过滤后的实体集，未冻结；本 UC 按“当前公开、生效、可检索的去重实体”读取。
