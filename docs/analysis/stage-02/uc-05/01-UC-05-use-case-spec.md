# UC-05 提交和查询 Scholar 认领

**版本：** V1.0（2026-10-21）
**对应需求：** FR05；AC-IMPL-FR05-01/02/03/04；AC-IMPL-NF03-01；AC-IMPL-NF06-01。
**需求基线：** [`CognitaNexus-Shared-SRS-V2.2-69AC.md`](../../../srs/CognitaNexus-Shared-SRS-V2.2-69AC.md)
**教材依据：** §5.4.1 完善用例文档；§5.4.2 识别分析类；§5.4.3 分析交互；§5.4.4 构造 VOPC。

> **范围：** 本 UC 只处理“已登录的注册用户选择平台已收录 Scholar 档案、提交可核验证据、查询本人申请状态与决定”。审核决定（批准/驳回/争议处理）、授权生效与回滚属 UC-06；已授权 Scholar 档案维护属 UC-07；普通 UserProfile 编辑属 UC-22；成果归属确认/纠错属 UC-08/UC-10。本 UC **不创建** Scholar、**不创建第二个 UserProfile**、**不创建 ScholarAuthorization**、**不创建 Authorship**，也不编辑任何学术/研究成果事实。

## 1. 参与者

| 类型 | 参与者 | 说明 |
|---|---|---|
| 主要参与者 | 注册用户（登录用户） | 本人提交认领申请并查询本人申请结果；不得代他人提交或查询 |
| 次要参与者 | 无 | 审核管理员属 UC-06；本 UC 不出现管理员操作 |

> SRS §2.2 说明“登录用户提交本人的认领申请”，§8 权限表对应行为“本人认领申请/查看私有结果：本人提交/读”。“注册用户”与“登录用户”在本 UC 指同一账号主体，不引入新角色。

## 2. 目标

注册用户就**平台已收录的 Scholar 档案**发起身份认领申请，提交可核验证据；系统在不改变任何既有授权、不新建主页/学者/成果关系的前提下，把申请登记为可审核的申请（或按缺证情形处理），并保证申请人此后能查询本人申请的状态与决定。

## 3. 触发事件

注册用户在认领入口选择一个已收录 Scholar 档案并提交认领材料；或注册用户查询本人已提交的认领申请。

## 4. 前置条件

1. 请求者已登录且账号可用；身份、账号状态与对象归属在服务端校验（FR04“登录、退出、账号状态与受保护接口检查均由服务端完成”；NF03）。
2. 目标对象是平台**已收录**的 Scholar 档案（可没有账号）；认领前该档案仍可公开读（SRS §8）。
3. 申请人可能已拥有注册自动创建的 UserProfile；认领不要求先拥有论文，也不要求 UserProfile 与 Scholar 对应（FR05；SRS §12）。
4. 目标 Scholar 是否已有他人有效授权**不影响**本 UC 提交，但必须原样保留（AC-IMPL-FR05-03）。
5. 必要证据的最低集合未冻结（见 08 B-02），本 UC 只要求“可核验证据”并按齐备性分支。

## 5. 成功与失败后置条件

### 5.1 提交成功（证据齐备）

1. 存在一条该用户对该 Scholar 的 `ClaimApplication`，状态为**待审核**；申请人恰为一个 User，目标恰为一个 Scholar。
2. 提交的私有材料登记为 `ReviewEvidence` 并关联该申请；仅本人与有权审核者可见（BR-IMP-11；AC-IMPL-NF06-01）。
3. **没有任何** `ScholarAuthorization` 被创建、修改、撤销或转移；若目标已有他人有效授权，该授权保持原状（AC-IMPL-FR05-03；BR-IMP-05）。
4. 没有创建 Scholar、UserProfile、Authorship、WorkEntity；不自动确认任何成果归属（FR05；AC-IMPL-FR05-04；BR-IMP-10）。
5. 申请人可查询本人申请的状态、理由与（UC-06 产生的）决定。

### 5.2 缺必要证据（A1）

1. 申请**不进入审核**：要么本次提交被拒绝且不创建申请（A1a），要么申请被标为**待补充**并说明缺失项（A1b）；基线允许两者，具体策略未冻结（B-01）。
2. 已提交的材料若被保存，仍只对本人与有权审核者可见。
3. 不产生任何授权、主页、学者或成果关系变化。

### 5.3 拒绝/失败

1. 未登录、账号停用、无权：拒绝，无写入（NF03；AC-IMPL-NF03-01）。
2. 目标不是平台已收录 Scholar 档案：拒绝；不新建 Scholar、不以 UserProfile 代替、不合并主页（FR05；SRS §12）。
3. 申请或证据保存失败：返回失败，不虚报“已提交”，不留下可进入审核的半成品。
4. 拒绝、失败与“待审核/待补充”三种结果在界面上可区分。

### 5.4 查询

1. 本人可读：当前状态（待审核/待补充/通过/驳回/争议）、状态理由与缺失项。
2. 他人申请或他人证据材料：拒绝（AC-IMPL-NF03-01；AC-IMPL-NF06-01）。
3. 查询执行失败与“无该申请”可区分，失败不伪装为空结果。
4. 查询只读：不改变申请状态，不产生授权。

## 6. 基本事件流

| 步骤 | 事件 | 需求来源 |
|---:|---|---|
| E1 | 申请人选择一个平台已收录的 Scholar 档案，提交认领意图与可核验证据。 | FR05；SRS §2.2、§8 |
| E2 | 系统在服务端校验请求者身份与账号状态。 | FR04（服务端校验）；NF03；AC-IMPL-NF03-01 |
| E3 | 系统确认该目标是平台已收录 Scholar 档案；不新建 Scholar、不改档案、不以 UserProfile 代替。 | FR05；SRS §12；AC-IMPL-FR05-04 |
| E4 | 系统校验必要证据是否齐备（最低集合待 B-02 确认）。 | AC-IMPL-FR05-01 |
| E5 | 系统读取目标 Scholar 当前有效授权，仅用于识别是否为竞争认领；不修改授权。 | AC-IMPL-FR05-03；BR-IMP-05 |
| E6 | 系统创建认领申请：申请人=该 User，目标=该 Scholar，状态=待审核，并记录竞争事实。 | FR05；AC-IMPL-FR05-03 |
| E7 | 系统登记提交的私有证据材料并关联申请（仅本人与有权审核者可见）。 | BR-IMP-11；NF06；AC-IMPL-NF06-01 |
| E8 | 系统返回申请标识、状态（待审核）与查询入口，并确认原授权未变更。 | FR05；AC-IMPL-FR05-02/03 |
| E9 | 申请人查询本人认领申请的状态与决定。 | AC-IMPL-FR05-02“申请人可查询决定”；SRS §8 |
| E10 | 系统核验请求者身份与申请归属：本人可读，他人申请或他人证据拒绝。 | AC-IMPL-NF03-01；AC-IMPL-NF06-01；SRS §8 |
| E11 | 系统返回本人可读的状态（待审核/待补充/通过/驳回/争议）与理由/缺失项，不回显他人证据原文。 | AC-IMPL-FR05-02；AC-IMPL-NF06-01；FR05 状态集 |

## 9. 关联状态

> 状态集按 FR05/SPEC §3/`DGM-STATE-02` 使用 `待审核/待补充/通过/驳回/争议`。SRS §11.3 另列 `待提交` 草稿态，但 `DGM-STATE-02`/SPEC §3 无该状态、UC-05 也不产生它；差异登记为 B-12，交由 R5/状态模型统一。

本 UC 引用 [`DGM-STATE-02-claim-request.puml`](../../../uml/claim/DGM-STATE-02-claim-request.puml) 的申请状态，不新建状态机：

| 迁移 | 触发者 | 归属 |
|---|---|---|
| `[*] → 待审核` | 本人提交且证据齐备 | 本 UC（E6） |
| `[*] → 待补充`（提交侧直接标待补充） | 提交时缺必要证据且采用 A1b | 本 UC（A1b，待确认 B-01） |
| `待审核 → 待补充`（要求补证） | 有权审核者 | UC-06 |
| `待补充 → 待审核`（本人重提且校验通过） | 本人 + 审核 | 重提属 UC-05 的再次提交，校验与放行属 UC-06（B-04） |
| `待审核 → 通过/驳回/争议` 及争议后续 | 有权审核者 | UC-06 |
| 查询（任意状态） | 本人 | 本 UC 只读（E9–E11） |

本 UC **不覆盖** `通过/驳回/争议` 的产生，也不覆盖授权失败回滚；查询只把 UC-06 已产生的状态读出来。

## 11. 待确认

1. **B-01**：缺必要证据时采用“直接拒绝”还是“标待补充”（AC-IMPL-FR05-01 允许两者）——待负责人定（对应 D-06）。
2. **B-02**：必要证据的最低集合与“可核验”判定标准（材料类型、是否必须含外部稳定标识）——D-06。
3. **B-03**：同一用户对同一 Scholar 重复提交、撤回、申诉的处理（幂等/合并/拒绝）——基线未定义。
4. **B-04**：补证后材料版本与重提条件（`待补充 → 待审核` 的校验口径）——`DGM-STATE-02` 仅写“本人重提[校验通过]”。
5. **B-05**：提交/查询是否另需独立审计留痕类（与 UC-22 的 `AuditEvidence`、全局 `Evidence` 命名统一，D-13）。
6. **B-06**：竞争认领的受控待办载体与标记方式；授权转移/申诉程序待评审（SPEC ID-12）。
7. **B-07**：待补充/决定的通知渠道与内容未在 SRS 出现，本 UC 只保证“可查询”，不写通知机制。
8. **B-08**：审核 SLA 未冻结（D-06）。
