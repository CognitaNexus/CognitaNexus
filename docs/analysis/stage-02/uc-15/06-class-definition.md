# UC-15 分析类职责、属性、关系与分析机制

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.5.1 职责、§5.5.2 属性、§5.5.3 关系、§5.5.4 分析机制。
**范围：** 只定义 UC-15 能够证实的部分；跨用例统一关系不在此擅自补齐。

## 1. 定义原则

1. “做（Do）”型职责说明对象能执行/协调什么；“知道（Know）”型职责说明对象必须知道/提供什么。
2. 属性只写业务信息，不写数据库字段、图数据库实现、主键类型、索引、邻接表、物化视图或 API 参数；BFS 实现、缓存与部署不在此定义。
3. 关系只写有消息或正式业务约束支持的；无依据的跨用例关系留待 R5。
4. 控制类与边界类没有长期业务属性；筛选条件、端点、图版本、边集、路径、披露与规模是**单次查询的分析状态**。
5. `CollaborationEdge`（论文子图投影）与 `PathResult`（读时投影）都是**派生对象**：有业务身份与可观察值，但本 UC 不把它们作为独立事实源持久保存；结果对象化程度见 07 §5 C-01（待确认 B-08）。
6. 筛选维度/取值语义、机构与领域口径、规模上限口径、作者证据门槛、k 展示口径、图版本对象化、等长总条数、超时阈值、视图归属、端点选择等未冻结项不伪装成类定义，统一标 `待确认`（B-01～B-12）。
7. 本 UC 不定义任何“四类基础网络建边/强度/证据清单”（UC-14）、“统计/排名/热点”（UC-11/12/13）、“质量评分/推荐”（基线排除）职责。
8. **论文子图是唯一图范围**：所有 Do 都以“只使用合格共同论文证据的边”为前置，不把专利/项目/获奖当作路径证据（IN01-R1；`AC-IMPL-FR12-05`；BR-IMP-09）。

## 12. 与其他 UC 的边界

- **UC-14（四类共同成果基础网络）**：本 UC 的直接上游。UC-14 产出四类基础网络与强度 `weight`，并保证边保留成果类型与证据；本 UC 只取论文投影，不裁剪、不改写基础网络，不回写任何内容（BR-UC15-06/20；04 §6）。
- **UC-09（去重清洗）**：论文去重与版本确认不在本 UC；本 UC 只消费“已去重论文 + 已确认/未确认版本”状态（BR-IMP-02）。
- **UC-08/UC-10（归属与身份）**：身份消歧、合并、归属判定与排除不在本 UC；本 UC 只解析生效 `canonicalId` 与关系状态，并把身份歧义交回（BR-IMP-03；`AC-IMPL-FR15-04/05`）。
- **UC-11/UC-12/UC-13**：统计分布、机构排名与领域热点不在本 UC；四者共用“默认只真实、披露与结果同屏、空/失败可区分、同一生效数据版本”的口径，但对象不同（成果/机构/关键词/学者对与路径）。
- **UC-01/UC-02/UC-03**：检索、成果详情与学者门户不在本 UC；本 UC 只提供详情与门户入口，并在目标不可用时给原因（M44）。
- **UC-16**：规模核对（≥100 万/≥500 万去重实体、真实数单列）不在本 UC；本 UC 只保证 k 按去重论文计算（`AC-IMPL-FR16-02` 边界）。
- **UC-17/FR14**：路径查询失败明细、图结果运营与审计查询不在本 UC；本 UC 无受保护写入。
