# UC-15 Boundary / Control / Entity 识别

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.4.2：从用例事件流识别边界类、控制类、实体类；不从现有全局 BCE 反向填充。
**输入：** 本目录 01 规约、02 事件流；直接上游 [UC-14 03-BCE](../uc-14/03-bce-identification.md)（只用于确认“基础网络”与“论文子图”的分工，不复制其参与类集合）。

## 1. 识别原则

1. **Boundary**：与外部参与者交互、接收请求或显示结果的对象。
2. **Control**：协调本用例内的条件校验、图版本固定、论文子图范围与资格判定、筛选、规模判定、端点校验、BFS 与等长裁决、逐跳证据绑定、披露与状态区分、版本一致性；不是实现层 Controller/Service，也不是图数据库、索引、缓存或图渲染引擎。
3. **Entity**：承载业务事实、状态与可追溯信息；不是数据库表、物化视图或图快照。
4. 只有在本 UC 事件流中实际接收消息的对象才进入 VOPC。
5. 参与者“访客”不是系统分析类；BFS 队列、距离数组、图快照、DTO 与渲染对象不进入本 UC。
6. 仅因“以后可能用到”而出现的类不进入本 UC；路径结果是**本次查询内推导**的投影，是否保留结果版本见 05 §4 与 07 §5 C-01。
7. **不从旁证推出合作**：同机构、同领域、相似姓名、非论文共同成果都不是路径证据；只有“同一篇合格共同论文上的两条合格作者关系”才构成论文子图的边（IN01-R1/R3；`AC-IMPL-FR12-04/05`；BR-IMP-08/09）。
8. **不把 FR12 基础网络搬进本 UC**：`CollaborationEdge` 在本 UC 只承担**论文子图投影**；四类成果强度、证据清单与披露由 UC-14 负责（BR-UC15-20）。

## 3. 逐类选择理由

### C1 CollaborationNetworkUI（Boundary）

- 发现于 E1 打开筛选/路径入口、E17 披露同屏、E18 展示结果与状态、E19 导航、以及 A1–A7、A13、A18、A19、A20 的提示显示。
- 无持久业务属性；当前筛选条件、路径结果、逐跳证据、披露块、规模信息与提示类型是单次请求的展示状态。
- **命名说明：** 本 UC 沿用上游 [UC-14](../uc-14/05-vopc.md) 已登记的 `CollaborationNetworkUI`（候选类登记表已注“后续参与 UC-15”）：IN01 的筛选与路径是**同一网络视图内的增强操作**（`DGM-USECASE-02` 中 `UC15` 以 `<<extend>>` 扩展 `UC14`，`INCL_Filter`/`INCL_Path` 又以有触发条件的 `<<extend>>` 扩展 `UC15`），且两者都不要求每次一起执行。全局 `AnalyticsUI`/`PublicPortalUI` 的合并与命名留 R5 与 D-11（07 §2；B-11）。
- 不能承担：不能判定论文资格或作者关系资格、不能筛选或计算路径、不能决定等长裁决与规模上限；“页面有入口”不构成公开性证明（BR-IMP-01）。

### C2 CollaborationPathCoordinator（Control）

- 发现于 E2 条件校验、E3 图版本固定、E4 范围、E6 论文资格、E8 关系资格、E10 节点与端点资格、E11 建边投影、E12 筛选、E13 规模、E14 端点校验、E15 BFS 与等长、E16 逐跳证据、E17 披露、E20 版本一致性，以及 A1–A20 的分支裁决。
- 需要跨五个对象协调，并保证：①只用论文证据边（专利/项目/获奖不进）；②长度＝边数、强度不作距离；③等长按字典序唯一并说明规则；④每跳至少一篇论文证据且同图版本；⑤筛选用发生时机构/领域证据、未知不命中、先筛后建边；⑥无路径/无效端点/超规模/失败/超时可区分；⑦不跨范围推断；⑧只读、不建持久结果。
- **为何与 `CollaborationNetworkCoordinator` 分开：** 上游 UC-14 只负责四类基础网络的建边、强度与证据披露，并明确建议 R5 拆分“基础建边”与“论文子图筛选/路径”（UC-14 07 §2/§7）。若合并，路径规则（图版本、1 万/10 万上限、论文限定、等长裁决）会反渗进四类基础网络，导致“基础网络被裁成论文图”或“基础网络被施加上限与版本语义”。本 UC 因此新建 `CollaborationPathCoordinator`，并只通过 `CollaborationEdge` 的论文投影读取基础网络结果。全局 `GraphCtl`/`AnalyticsNetworkCoordinator` 把两者合写，差异登记 07 §3。
- 不能承担：不承载论文资格字段（`WorkEntity`）、作者角色与状态（`Authorship`）、学者身份与合并（`Scholar`）、论文边与 k（`CollaborationEdge`）、路径与逐跳证据（`PathResult`）；不是检索协调者（UC-01）、不是统计/排名/热点协调者（UC-11/12/13）、不是基础网络协调者（UC-14）、不是身份治理协调者（UC-10）、不是图存储/索引/缓存/渲染服务；不得执行质量评分或推荐。

### C3 Scholar（Entity，只读）

- 发现于 E9 读取身份、E10 节点与端点守卫、E14 端点确认、E19 导航；A3–A6 端点不可用、A15 合并后重定。
- 必要性来自两个独立要求：①“两名**已消歧**学者”与“stable_id＝学者 `canonical_id`，不是姓名、ORCID 原文、来源内 ID 或账号 ID”（IN01-R1；SPEC §2）；②合并后不得保留重复节点、不得出现自环（BR-530；`AC-IMPL-NF05-02`）。
- 不能并入 `User`/`UserProfile`：节点是平台采集/核验的学者身份，注册用户与其普通主页不是端点标识，也不是合作证据（§12；`01-BCE` §5）。
- **本 UC 只读：** 不合并身份、不改公开范围；身份判定属 UC-10。

### C4 WorkEntity（Entity，只读）

- 发现于 E5 读取论文范围字段、E6 论文资格、E11 作为证据单位、E12 领域筛选、E16 证据公开字段；A8 非论文类型、A14 未知领域/机构、A16 多来源/版本、A17 同跳多篇论文。
- 必要性来自三个独立要求：①“仅在 FR12 中经筛选合格的**共同论文**子图上”（IN01-R1；`AC-IMPL-FR12-05`）；②“年份/领域使用成果已核验发生时间与发生时分类及映射版本”（SPEC §3）；③证据展示需要公开字段（标题/类型/时间/来源/归属状态）且缺失标未知（IN01-S04 细化）。
- 不能并入 `Authorship`：成果是共享实体，解除一位作者的合格关系不删除论文与其他合格作者关系（INV-05；§7.2）。
- 不能并入 `SourceRecord`/`WorkVersion`：来源数与版本数不增加 k（`AC-IMPL-FR12-02`；`AC-IMPL-FR16-02` 边界）。
- **本 UC 只读：** 不改公开状态、数据类别、发生时间、领域分类与版本关系。

### C5 Authorship（Entity，只读）

- 发现于 E7 读取参与关系、E8 资格判定、E11 取合格作者集合、E12 机构筛选的“发生时机构证据”；A9/A10 状态与角色排除、A16 重复来源。
- 必要性来自三个独立要求：①“仅由公开、真实、经确认可用于论文合作的作者关系建边”（IN01-R1）要求区分论文作者角色与角色证据；②“待核验/争议/已排除不产生边，也不进入 IN01 论文子图”（`AC-IMPL-FR12-04`；§6.4；§11.3）；③机构筛选用“成果对应学者在成果发生时的机构证据”（SPEC §3；BR-513 细化），该证据挂在“学者—成果”关系上而非成果或学者单方。
- 不能并入 `Scholar`：关系状态属于“学者—成果”关系，同一学者在不同论文上可处于不同状态（`AC-IMPL-FR15-06` 语义）。
- 不能并入 `CollaborationEdge`：Authorship 是**一对一论文**的参与事实；边是**一对学者**在本次范围内的聚合投影（05 §2.3）。
- **本 UC 只读：** 不改角色、顺序、状态与证据。

### C6 CollaborationEdge（Entity，派生／论文子图投影，只读）

- 发现于 E11 建投影、E12 筛选后重建、E15 BFS 读邻接、E16 逐跳读证据；A8/A10 非论文边与空证据、A16/A17 计数口径。
- 必要性来自两个独立要求：①“每一跳展示至少一篇可点击的共同去重论文证据”（IN01-R3）要求边可被逐跳寻址并携带论文证据集合；②“FR12 共同成果数与 IN01 路径论文证据数分别声明”（BR-518 细化）要求有一个只含论文证据的聚合载体，其计数 k 与基础网络强度 `weight` 明确分离。
- **与上游同名类的关系：** UC-14 的 `CollaborationEdge` 是四类共同成果的派生边（`weight` 含论文/专利/项目/获奖）；本 UC 只使用其**论文子图投影**：证据集合只含论文，计数为 k。二者不是两个不同业务概念，而是同一派生关系在不同图范围上的投影；本包不重新定义 UC-14 的强度规则（BR-UC15-06；07 §4.3）。
- **派生而非事实源：** 边的每一项事实都可由“合格论文 + 合格作者关系 + canonical 身份 + 筛选条件”重建；本 UC 全程无写消息，不持久保存边或图版本（06 §8/§11；C-01）。
- 不能并入 `WorkEntity`：一篇论文可产生多对学者的边（多作者），边与论文是 `0..*`:`1..*`。
- 不能并入 `Scholar`：边是二元关系而不是节点属性。

### C7 PathResult（Entity，读时投影）

- 发现于 E14–E17；A6 0 跳、A7 无路径、A11 等长、A12 版本失效、A13 超规模、A18 失败、A19 超时。
- 必要性来自两个独立要求：①“以 BFS 的边数计算最短路径；等长路径按学者稳定标识序列字典序选择一条”（IN01-R2；`AC-IMPL-IN01-02`）要求结果能携带**节点序列与裁决规则**，并被逐跳校验；②“每一跳展示至少一篇可点击的共同去重论文证据”（IN01-R3；`AC-IMPL-IN01-01`）要求结果能按跳寻址其边与证据。二者都要求一个“有序、逐跳、可复现”的载体，而不仅是协调者内部的距离数组。
- **读时投影：** 结果在本次查询内由固定图版本与筛选条件推导，随查询结束而失效；同一图版本同条件的重复查询返回同一条是**规则保证**，不是“保存了上一版结果”。是否保留结果版本/状态机见 B-08 与 C-01（07 §5）。
- 不能并入 `CollaborationEdge`：路径是边的有序序列（0 跳时无边），一条边可属于多条路径；也不能并入 `Scholar`：路径是多个节点的有序组合，不是单个学者属性。

## 5. 十项对象边界结论

| 边界 | 结论 | 本 UC 证据 |
|---|---|---|
| `CollaborationEdge`（论文子图投影）vs 基础网络 `CollaborationEdge`（四类强度） | 同一派生关系在不同图范围上的投影：本 UC 的证据集合只含论文，计数为 k；基础网络的 `weight`（四类共同成果数）由 UC-14 负责，二者分别声明 | BR-518 细化；`AC-IMPL-FR12-02/05`；UC-14 05 §2；BR-UC15-06 |
| `PathResult`（读时投影）vs 持久路径结果/图快照 | 结果是查询内推导并随查询失效；同版本同条件返回同一条是规则保证，不是保存上一版结果 | `AC-IMPL-IN01-02`；06 §8；C-01 |
| `WorkEntity`（论文证据）vs `Authorship`（参与资格） | 论文是共享证据单位；参与关系携带角色/状态/发生时机构证据；解除一位作者不删论文与其他合格关系 | INV-05；§7.2；`AC-IMPL-FR12-04` |
| `Scholar`（端点身份）vs `User`/`UserProfile` | 端点只用 `canonical_id`；账号与普通主页不是端点标识也不是合作证据 | IN01-R1；SPEC §2；§12 |
| 论文子图筛选 vs FR12 基础网络（四类成果） | 筛选只作用于论文子图；基础网络仍含四类成果，本 UC 不裁剪 | IN01-R1；`AC-IMPL-FR12-05`；C-03 |
| k（路径论文证据数）vs `weight`（FR12 共同成果强度） | k 只计本范围内去重合格共同论文；`weight` 含四类成果；路径长度用边数，不用 k 或 `weight` | BR-518 细化；IN01-R2；SPEC §4 |
| 最短路径（边数）vs 强度排序/加权距离 | 图为无向非加权，最短＝最少边数；强度与 k 不参与距离 | IN01-R2；BR-IMP-09 |
| 无路径 vs 无效端点 vs 超规模 vs 失败/超时 | 四类可观察结果互不冒充；失效图版本为第五类提示 | `AC-IMPL-IN01-03/04`；NF01；BR-UC15-14 |
| 筛选条件（领域/机构取值）vs 机构/领域实体 | 条件来自请求，证据来自 `Authorship`/`WorkEntity`；不为机构/领域建实体类，避免暗示可建边 | IN01-R3；`AC-IMPL-FR12-04`；07 §4.4 |
| IN01 读侧 vs 统计/排名/热点读侧 | 本 UC 只表达筛选网络与路径；计数排名属 UC-11/UC-12，热点属 UC-13；三者须同一生效数据版本 | NF05；BR-523 细化 |

## 6. 识别结论

本 UC 的候选分析类共 7 个：

- Boundary：`CollaborationNetworkUI`（沿用上游网络视图入口）
- Control：`CollaborationPathCoordinator`
- Entity：`Scholar`（只读）、`WorkEntity`（只读）、`Authorship`（只读）、`CollaborationEdge`（派生、论文子图投影、只读）、`PathResult`（读时投影）

机构与领域实体、图快照/图版本对象、结果对象与状态机、BFS 数据结构、逐跳对象、查询参数对象、账号与普通主页、来源记录与版本、去重/清洗候选、身份候选与合并对象、质量与影响力评分、路径排行、强度/证据阈值对象、审计证据、会话、DTO/渲染对象、图存储/索引/缓存/任务、推荐与行为画像、通知与时限均不进入本 UC VOPC。该集合将在 04 的顺序图中接受消息检验；若某类没有消息，则删除或降为属性/职责。
