# UC-04 账号注册并自动生成公开个人主页

**版本：** V1.0（2026-10-21）
**对应需求：** FR04；并覆盖A1c引入的FR03-03/04结果。
**需求基线：** [`CognitaNexus-Shared-SRS-V2.2-69AC.md`](../../../srs/CognitaNexus-Shared-SRS-V2.2-69AC.md)
**教材依据：** §5.4.1 完善用例文档；§5.4.2 识别分析类；§5.4.6 用例实现四步。

> **范围边界：** 本UC只处理“访客提交注册→创建账号和唯一公开个人主页”的行为。登录、退出、本人普通主页编辑（UC-22）、Scholar认领（UC-05/06）、Scholar档案维护（UC-07）不在本UC内。注册成功后的访问权限只作为后置条件和守卫，不扩张为其他UC的完整规约。

## 1. 参与者

| 类型 | 参与者 | 说明 |
|---|---|---|
| 主要参与者 | 访客 | 尚未拥有可用账号；提交注册信息 |
| 次要参与者 | 无 | 系统是业务执行主体，不作为外部Actor；Scholar不是本UC参与者 |

## 2. 目标

访客成功注册后，系统创建**一个User**和**与该User 1:1绑定的唯一UserProfile**，为该主页分配唯一、稳定、可分享的公开地址，并使注册用户获得本人普通资料的编辑权；不创建Scholar、Scholar授权或Authorship。

## 3. 触发事件

访客提交注册信息。

## 4. 前置条件

1. 注册入口可用。
2. 提交信息包含现有SRS/模块规则要求的注册内容；本分析不新增强制字段。具体字段集合和格式规则未在正式基线冻结（见08 Q-01）。
3. 注册不要求访客已有账号、已有Scholar档案或已有学术成果。
4. 本次操作不以登录会话为前提；已有会话是否复用不属于本UC。

## 5. 成功与失败后置条件

### 5.1 成功

1. 恰好存在一个User。
2. 恰好存在一个与该User绑定的UserProfile；User与UserProfile为1:1。
3. UserProfile有唯一、稳定、可分享的公开地址。
4. 该UserProfile可由访客公开读取；没有公开成果时显示“暂无公开成果”空态，不是404。
5. 注册用户获得本人普通资料的编辑权；该权利不是Scholar档案管理授权。
6. 没有因注册创建Scholar、ScholarAuthorization、Claim、Authorship或WorkEntity。
7. 公开响应不包含凭据、审核材料或非公开字段；注册邮箱、联系方式等非必要个人信息默认不公开。

### 5.2 失败

1. 不留下新的User/UserProfile组合。
2. 不留下无主UserProfile，也不留下没有主页的注册成功结果。
3. 不产生第二个主页；重复请求不增加UserProfile数量。
4. 既有的其他公开主页、Scholar档案和授权不因本次失败被删除或改写。
5. 系统返回可区分的失败原因；具体错误码/文案不在本UC确定。

## 6. 基本事件流

| 步骤 | 事件 | 需求/规则来源 |
|---:|---|---|
| 1 | 访客打开注册入口，提交注册信息。 | FR04；UC-04；E1 |
| 2 | 系统校验注册信息是否满足注册规则，并检查本次请求是否可继续。 | FR04注册成功条件；E2；具体规则见Q-01 |
| 3 | 系统创建一个User，记录账号标识和账号状态。 | FR04；E3；SRS §12 |
| 4 | 系统创建与该User绑定的唯一UserProfile。 | FR04；AC-IMPL-FR04-03；E4 |
| 5 | 系统为UserProfile分配唯一、稳定、可分享的公开地址。 | FR04；AC-IMPL-FR04-03；E5 |
| 6 | 系统使注册用户获得本人普通资料的编辑权；不授予Scholar档案管理权。 | FR04；BR-IMP-05；E6 |
| 7 | 系统发布UserProfile的公开视图；零成果时显示“暂无公开成果”空态。 | FR03；AC-IMPL-FR03-03；A1c；E7 |
| 8 | 系统向访客返回注册成功结果和公开主页地址。 | FR04；AC-IMPL-FR04-03；E8 |
| 9 | 访客可公开读取该主页；未登录访客的受保护写操作被拒绝，凭据和审核材料不公开。 | FR04-04；BR-IMP-01/05/11；E9 |

> 步骤3–7是同一个注册成功结果的分析级原子性要求：不能只留下User而没有UserProfile，也不能只留下UserProfile而没有User。此处不指定数据库事务、锁或消息实现。

## 7. 备选/异常流

| 编号 | 条件 | 系统行为 | 依据 | 说明 |
|---|---|---|---|---|
| A1 | 注册信息不满足注册规则 | 拒绝本次注册；不创建User/UserProfile；指出不满足的规则。 | FR04成功条件；分析推导 | 字段级规则和文案待J02/后续决议，见Q-01 |
| A2 | 同一注册请求被重复提交/重试 | 识别为重复请求；不得创建第二个UserProfile；不产生重复或无主主页。 | FR04；AC-IMPL-FR04-03 | 业务幂等已确认；识别键/令牌和保留时长未冻结，见Q-02；返回“已有结果”的具体形式待定 |
| A3 | User创建、UserProfile创建或稳定地址分配失败 | 本次注册整体不生效；不得留下无主主页或半完成账号；可重试。 | FR04；AC-IMPL-FR04-03；SRS §12 | “整体不生效”是分析级业务原子性，不是数据库实现 |
| A4 | 注册成功但用户无论文/专利/项目/获奖 | 公开主页正常打开，显示“暂无公开成果”，不返回404。 | AC-IMPL-FR03-03；A1c | 零成果不是失败 |
| A5 | 存在同名Scholar档案 | UserProfile和Scholar分别展示；不自动合并、不把UserProfile标成已认证学者。 | AC-IMPL-FR03-04；BR-IMP-03；SRS §12 | 注册流程不创建Scholar，也不建立认领授权 |
| A6 | 账号已停用或已退出后发起受保护请求 | 拒绝该受保护请求；不删除已有的公开Scholar档案。 | AC-IMPL-FR04-02；BR-IMP-05/10 | 账号状态是守卫，不是注册成功的替代结果 |
| A7 | 未登录访客读取公开主页或尝试写操作 | 公开读取允许；受保护写拒绝；公开响应不含凭据、审核材料，注册邮箱/联系方式等默认不公开。 | AC-IMPL-FR04-04；BR-IMP-01/11 | 前端隐藏入口不能代替拒绝；字段集合见Q-06 |

## 8. 业务规则

| 规则 | 内容 | 来源 |
|---|---|---|
| BR-UC04-01 | 注册成功时一次性创建User与唯一UserProfile；两者1:1绑定。 | FR04；SRS §12 |
| BR-UC04-02 | UserProfile必须有唯一、稳定、可分享的公开地址；所有注册用户（包括非学者、零成果用户）均有公开主页。 | FR04；FR03；A1c；AC-IMPL-FR04-03 |
| BR-UC04-03 | 注册重试不得产生第二个主页、重复UserProfile或无主UserProfile。 | FR04；AC-IMPL-FR04-03 |
| BR-UC04-04 | UserProfile所有权只授予本人普通资料编辑权；不等同于Scholar档案认领授权。 | FR04；BR-IMP-05 |
| BR-UC04-05 | 注册不得创建Scholar、ScholarAuthorization、Claim或Authorship；普通资料不能推导学术身份或合作边。 | FR04；FR03-04；SRS §12；A1c |
| BR-UC04-06 | 公开读取与受保护写分离；未登录/停用账号的受保护写被拒绝；公开响应最小化。 | FR04-02/04；BR-IMP-01/11 |
| BR-UC04-07 | 零成果主页显示空态，不以404或虚假成果填充。 | AC-IMPL-FR03-03；A1c |
