**版本：** V1.0（2026-10-21）
**对应需求：** FR06（FR06-01～05）；直接前置 FR05（FR05-02/04）；相关 FR15（FR15-03/06）、NF03（NF03-01）、NF06（NF06-01）；BR-IMP-01/03/04/05/10/11、§6.4、§7.2、§8、§11.3/§11.4、§12。
**需求基线：** [`CognitaNexus-Shared-SRS-V2.2-69AC.md`](../../../srs/CognitaNexus-Shared-SRS-V2.2-69AC.md)
**核心 SPEC：** [`CognitaNexus-Core-SPEC-V1.0.md`](../../../spec/CognitaNexus-Core-SPEC-V1.0.md) §3（INV-08/INV-10）、§6.2（ID-06/ID-07/ID-10/ID-12）
**既有模型：** [`DGM-USECASE-07-profile.puml`](../../../uml/profile/DGM-USECASE-07-profile.puml)、[`DGM-ACTIVITY-06-edit-profile.puml`](../../../uml/profile/DGM-ACTIVITY-06-edit-profile.puml)（学术字段分支）、[`DGM-STATE-02-claim-request.puml`](../../../uml/claim/DGM-STATE-02-claim-request.puml)（授权来源状态）

> **范围边界：** 本 UC 只处理“已获授权 Scholar 管理者（或具备对应管理权限的管理员）对**其被授权的那一个 Scholar 档案**提交学术事实变更、按其性质直接生效或进入待审、审核通过后才改变公开版本”的行为。公开浏览与展示属 UC-03；认领申请与认领审核（产生授权）属 UC-05/UC-06；成果参与关系的确认与纠错属 UC-08；本人普通主页字段编辑属 UC-22；后台审计查询与待办列表属 UC-17。本 UC **不创建** Scholar、**不创建/转移** `ScholarAuthorization`、**不创建** `ClaimApplication`、**不创建第二个** `UserProfile`、**不确认或解除任何** `Authorship`。
>
> **对象区分（本 UC 最重要的边界）：** `User` 是账号、会话与对象授权的主体；`UserProfile` 是注册自动生成的唯一公开普通主页，承载昵称/头像/简介/兴趣领域/展示设置，**不是本 UC 的写对象**；`Scholar` 是平台采集/核验的独立学术身份档案，承载已核验学术身份、机构、归属与来源事实，即使管理员批准认领也不等于本人逐条确认成果；`ScholarAuthorization` 是“某个 User 对某个 Scholar 的对象级管理权”，由 UC-06 在无冲突批准时产生，本 UC **只读**、**不转移**；待审的字段变更与审核材料是**另一个**可追溯对象（`ScholarChangeRequest`），既不是 `ClaimApplication`（认领申请），也不是 `AuditEvidence`（审计留痕）。

## 1. 参与者

| 类型 | 参与者 | 说明 |
|---|---|---|
| 主要参与者 | 已获授权 Scholar 管理者 | 已登录、账号可用，且对**当前目标 Scholar** 持有有效 `ScholarAuthorization`；只能维护该目标档案、且只能在授权范围内维护 |
| 次要参与者 | 有权审核的管理员 | 仅在“重要变更进入待审”后参与：复核待审变更并作出批准/驳回决定，使变更生成生效版本或不生效。SRS FR06 明确参与者含“审核管理员”，§11.4 明确“FR06 管理者包括获授权门户管理者以及具备相应审核权限的管理员” |
| 次要参与者（只读边界） | 访客/登录用户 | 只能读取**当前生效版本**的公开档案字段；本 UC 只保证“待审不入公开”，读侧展示属 UC-03 |

> 不引入审核员等级、审批链、SLA、申诉或授权转移动线程序：基线未定义（沿用 UC-06 C-01/C-03/C-05）。

## 2. 目标

持有有效对象级授权的管理者，在服务端授权校验与审计约束下维护其被授权 Scholar 档案的**学术事实**（已核验学术身份、机构、归属、来源事实），并保证：重要变更先待审、公开旧值在批准前继续公开、申请人对本人待审状态可查、批准后才生成生效版本；同时不越权写他人档案或普通 `UserProfile`，不扩张身份结构（第二主页/新 Scholar/新认领/新授权/成果确认）。

## 3. 触发事件

已获授权的 Scholar 管理者打开其被授权档案的维护入口，提交该档案学术事实（身份/机构/归属/来源事实）的变更；或（待审已存在时）查询本人待审状态；或有权审核的管理员对一条待审变更作出决定。

## 4. 前置条件

1. 请求者为已登录且账号状态可用的注册用户（NF03；`AC-IMPL-NF03-01`；FR04-02；SRS §8）。
2. 目标对象是平台**已收录**的 `Scholar` 档案（可能尚未被任何人认领，但必须已存在）；本 UC 不创建 Scholar（FR05；SRS §12）。
3. 请求者对该**确切** `Scholar` 持有**有效**的 `ScholarAuthorization`，范围覆盖本次提交的字段与门户；该授权只能由 UC-06 在无冲突批准后产生（FR05；`AC-IMPL-FR05-02`；BR-IMP-05；SPEC ID-07）。
4. 目标档案当前生效公开版本已存在（可为未认领但已公开的档案，FR03/§8）；本 UC 只在其上形成新版本或待审变更。
5. 提交内容为 Scholar 学术事实，不是普通 `UserProfile` 字段；普通资料维护属 UC-22（FR06；SRS §12）。
6. 竞争的认领/争议不改变本 UC 的授权判定口径：既有授权在争议期间**保留**，本 UC 不能因争议自行撤销或转移（BR-IMP-05；`AC-IMPL-FR05-03`；SPEC ID-12）。
7. “哪些字段需审核、哪些可直接生效”的字段级清单与“重要变更”判定口径尚未冻结（见 08 B-01/B-02）；本 UC 不预设结论，只在模型中保留两条可观察分支。

## 5. 成功与失败后置条件

### 5.1 成功（变更经审核后生效）

1. 目标 `Scholar` 的生效公开版本**只**在本 UC 提交且审核通过的字段范围内更新；公开视图（门户/检索/统计）使用该生效版本（FR06；`AC-IMPL-FR06-01`；NF05；BR-IMP-10；§6.4）。
2. 待审变更状态=通过，记录决定理由、决定时间与操作者；提交者可读到本人待审结果（`AC-IMPL-FR06-01`）。
3. 原始来源事实未被人工修订覆盖；公开规范值与审核记录独立保留（§7.2；BR-IMP-04；SPEC INV-01）。
4. 未创建第二个 `UserProfile`、未创建 `Scholar`、未创建 `ClaimApplication`、未创建/转移/撤销 `ScholarAuthorization`、未自动确认或解除任何 `Authorship`、未改变成果归属关系状态（FR05；`AC-IMPL-FR05-04`；`AC-IMPL-FR15-06`；BR-IMP-05）。
5. 受保护写入与审核决定均留可追溯审计：操作者身份、对象（档案/待审变更）、理由/结果、前后值、时间；审计不含凭据与认证材料原文（BR-IMP-10；`AC-IMPL-FR06-02`；NF03；SPEC INV-10）。
6. 同名其他 Scholar 与各注册用户的普通 `UserProfile` 不受影响、不被合并（BR-IMP-03；`AC-IMPL-FR03-04`）。

### 5.2 成功（授权范围内可直接生效的变更）

1. 该变更范围内的公开字段与生效版本被更新，公开视图按生效版本读取（FR06；BR-IMP-10）。
2. 不产生待审变更，或待审变更直接置为已生效；不出现“已改待审但公开已变”的中间态（分析推导，见 A5）。
3. 第 5.1 的 3–6 项同样成立。

### 5.3 成功（重要变更进入待审，尚未批准）

1. 待审变更状态=待审核，记录提交者、旧值、新值、理由/证据引用、提交时间与版本。
2. **公开版保持旧值**：门户/检索/统计仍读取旧值，待审内容不进入公开视图（`AC-IMPL-FR06-01`；BR-IMP-01/10；§6.4）。
3. 提交者本人可查到本人待审状态与“公开未变更”事实；他人不可读该待审内容（`AC-IMPL-FR06-01`；NF06；BR-IMP-11）。
4. 审计留痕（受保护写入）。
5. 第 5.1 的 4–6 项同样成立。

### 5.4 失败（无业务写入）

1. 目标档案的公开字段与生效版本保持原值；待审变更状态不变（若存在）。
2. 不产生第二主页、不产生 Scholar/Claim/Authorization、不产生 Authorship，也不删除既有公开档案（FR04-02；FR05；FR06）。
3. 越权（无有效授权/他人档案/超范围）与账号不可用的请求被服务端拒绝并保留受控审计（`AC-IMPL-FR06-02`；`AC-IMPL-NF03-01`；BR-IMP-10）。
4. 写入或生成生效版本失败时不虚报生效；审核决定无权限、理由缺失或待审版本已变化时不改变状态（分析推导；SRS §6.4；BR-IMP-10）。
5. 拒绝/失败/待审/已生效四类结果可区分（NF01“加载、空结果、错误、越权和处理中可区分”；分析推导）。

## 6. 基本事件流

> 基本流按 `AC-IMPL-FR06-01` 锚定的“重要变更 → 待审 → 审批 → 生效”路径展开；可直接生效的分支见 A5（其字段分类口径未冻结，故不放入基本流）。

| 步骤 | 事件 | 需求/规则来源 |
|---:|---|---|
| E1 | 已获授权的管理者打开被授权 Scholar 档案维护入口，提交该档案学术事实（已核验学术身份、机构、归属、来源事实）的变更。 | FR06“更改已核验学术身份、机构、归属、来源事实等仍需按Scholar对象授权和审核规则办理”；`DGM-USECASE-07`（已授权 Scholar 管理者 → UC-07）；E1 |
| E2 | 系统在服务端校验请求者身份与账号状态，确认是可用账号发起的受保护写入。 | NF03；`AC-IMPL-NF03-01`；SRS §8“每次操作的权限判断在服务端执行”；E2 |
| E3 | 系统读取请求者对该目标 Scholar 的有效对象级授权与授权范围，并确认目标档案正是该授权所指的同一 Scholar。 | FR05；`AC-IMPL-FR05-02`“新授权仅对目标门户有效”；BR-IMP-05“Scholar档案仍要求对象级认领管理授权”；SPEC ID-07 |
| E4 | 系统判定提交字段是否既在授权范围之内、又属于 Scholar 学术事实（普通 UserProfile 字段与他人档案不在本 UC）。 | FR06；SRS §12；`AC-IMPL-FR06-02`；E4 |
| E5 | 系统判定本次变更的性质（需审核的重要变更 / 按审核规则可直接生效），并记录判定结论。 | FR06“按Scholar对象授权和审核规则办理”；`AC-IMPL-FR06-01`“重要机构变更…尚未审批”；口径待确认（B-01） |
| E6 | [需审核] 系统登记待审变更（旧值、新值、提交者、理由/证据引用、提交时间、版本），**当前公开版保持旧值**。 | FR06“待审版本不覆盖公开版”；`AC-IMPL-FR06-01`；BR-IMP-10“待审不替代公开版本”；§6.4“重要字段待审旧值继续公开” |
| E7 | 系统写入受控审计，并向管理者返回“已提交待审、公开未变更、可查本人待审状态”。 | `AC-IMPL-FR06-01`“申请人可查待审状态”；BR-IMP-10；`AC-IMPL-FR06-02`（审计）；INV-10 |
| E8 | [次要参与者] 有权审核的管理员打开该待审变更，提交决定（批准/驳回）与理由；系统再次在服务端校验其身份、账号状态与审核权限。 | FR06 参与者含“审核管理员”；§11.4；FR14“关键批准、拒绝…记录…原因”（边界）；`AC-IMPL-FR06-01`；E8 |
| E9 | [批准] 系统以该待审变更为范围生成生效版本并更新公开字段；[驳回] 公开版保持旧值，待审变更置为驳回。 | `AC-IMPL-FR06-01`“尚未审批→公开仍为旧机构”（批准后才变）；§6.4“通过才生成生效版本”；BR-IMP-10 |
| E10 | 系统写入决定与生效的受控审计（操作者/对象/前后值/时间/理由），返回结果：已生效，或已驳回且公开未变更。 | BR-IMP-10；SPEC INV-10；NF05（生效后跨视图同一版本）；`AC-IMPL-FR06-02` |

> 步骤 2–10 是同一“授权范围内的档案变更按审核规则产生唯一生效版本”的分析级组合：不出现“公开值已变但未经审核”“审核通过但公开值未变”“写入成功却无审计”的中间态。此处只定义业务约束，不指定事务、锁、并发或消息实现。

## 7. 备选/异常流

| 编号 | 条件 | 系统行为 | 依据 | 说明 |
|---|---|---|---|---|
| A1 | 请求未认证，或账号已停用/已退出 | 服务端拒绝，无任何写入；不删除该 Scholar 档案与其公开版本；记录受控拒绝审计；返回与“越权”“失败”可区分的拒绝原因。 | NF03；`AC-IMPL-NF03-01`；FR04-02；BR-IMP-10；SRS §8 | 前端隐藏入口不能代替拒绝；会话对象是否建模见 B-08 |
| A2 | 请求者对该目标 Scholar 无有效对象授权：他人档案、同名另一位 Scholar、授权从未产生/已失效/已撤销 | 拒绝越权维护，目标档案无任何变化；保留受控越权审计；返回越权结果。 | `AC-IMPL-FR06-02`“未授权用户试图修改…无变更并有越权结果”；BR-IMP-05；FR05；SRS §8 | 直接调用接口同样落此分支；争议期间既有授权保留，不由本 UC 撤销（`AC-IMPL-FR05-03`；SPEC ID-12） |
| A3 | 授权有效，但目标字段/对象超出授权范围（stale scope）：范围仅覆盖部分字段或门户，或目标已不是同一 Scholar 对象 | 拒绝写入，说明授权范围；不写业务实体；留受控审计。 | `AC-IMPL-FR05-02`（仅目标门户有效）；`AC-IMPL-FR06-02`；BR-IMP-05 | 授权范围粒度（字段级/门户级）未冻结（B-05） |
| A4 | 提交内容含普通 `UserProfile` 字段（昵称/头像/简介/兴趣领域/展示设置），或试图借档案维护入口改普通资料 | 本 UC 不写这些字段；说明普通资料维护须走本人主页编辑（UC-22）；不改变 Scholar 档案、不创建第二个 `UserProfile`。 | FR06（两类字段分属不同授权）；SRS §12；UC-22 | 混合提交（同时含 Scholar 事实与普通字段）的处置未冻结（B-06） |
| A5 | 该变更按审核规则属可直接生效的公开字段（无需先行审批） | 授权校验通过后写入该字段并生成生效版本，公开按新版本读取；写审计；不产生待审。 | FR06“按…审核规则办理”；BR-IMP-10；`AC-IMPL-FR06-03`（普通资料无需学术审核，仅作对照） | 该分类口径未冻结（B-01/B-02）；若规则要求一律审核，则本分支不触发 |
| A6 | 写入或生成生效版本失败 | 公开版保持旧值；不返回成功、不显示为已生效；可重试；不产生半完成写入。 | `AC-IMPL-FR06-01`（未生效不得公开新值）；BR-IMP-10；SPEC INV-10；分析推导 | 失败与“成功零变更”必须可区分；具体失败分类未冻结 |
| A7 | 待审变更已被处理，或其版本已变化（含并发提交/重复决定的冲突） | 拒绝本次决定或本次提交，返回当前状态；不覆盖已有决定、不覆盖公开值。 | §6.4“待审不替代公开版本”；BR-IMP-04/10；分析推导；`DGM-STATE-02` 的过期守卫类比 | 是否允许多条待审并存与冲突处置未冻结（B-09） |
| A8 | 审核者无审核权限、账号停用，或决定理由缺失 | 拒绝该决定，待审变更状态不变，公开版不变；返回“无权限/理由必填”。 | FR14“关键批准、拒绝…记录…原因”（边界）；NF03；`AC-IMPL-NF03-01`；分析推导 | 与 A1/A7 的结果分开显示 |
| A9 | 审计留痕失败 | 不得报告为“已批准/已生效”；不留下无审计的生效决定；明确失败。 | BR-IMP-10；SPEC INV-10；`AC-IMPL-FR06-02`“保留受控审计” | 回滚机制属实现阶段，本 UC 只约束“不报告生效” |
| A10 | 待审期间访客/其他用户读取公开档案 | 公开视图仍只取当前生效版本，待审内容不进入；待审状态与审核材料仅提交者本人与有权审核者可见。 | BR-IMP-01“待审/争议/敏感证据不公开”；BR-IMP-11；NF06；`AC-IMPL-FR06-05` | 本 UC 保证写侧与可见范围；读侧展示由 UC-03 验证 |

## 8. 业务规则

| 规则 | 内容 | 来源 |
|---|---|---|
| BR-UC07-01 | 只有持有对**目标 Scholar** 有效对象级管理授权的账号可以维护该档案；每次受保护写入都在服务端校验账号状态＋授权主体＋授权范围，不以入口是否可见作为授权。 | BR-IMP-05；FR05；`AC-IMPL-FR05-02`；`AC-IMPL-FR06-02`；NF03；SRS §8 |
