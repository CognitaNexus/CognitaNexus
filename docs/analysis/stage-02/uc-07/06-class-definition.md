# UC-07 分析类职责、属性、关系与分析机制

**版本：** V1.0（2026-10-21）
**方法：** 教材 §5.5.1 职责、§5.5.2 属性、§5.5.3 关系、§5.5.4 分析机制。
**范围：** 只定义 UC-07 能够证实的部分；跨用例统一关系不在此擅自补齐。

## 1. 定义原则

1. “做（Do）”型职责说明对象能执行/协调什么；“知道（Know）”型职责说明对象必须知道/提供什么。
2. 属性只写业务信息，不写数据库字段、主键类型、索引或 API 参数。
3. 关系只写有消息或正式业务约束支持的；无依据的跨用例关系留待 R5。
4. 控制类没有长期业务属性；其请求上下文是单次用例的分析状态。
5. 需审核字段清单、可直接生效字段清单、授权范围粒度、并列管理者、传播时限等未冻结项不伪装成类定义，统一标 `待确认`（B-01～B-11）。

## 10. 分析机制汇总

| 机制 | 作用对象 | 业务问题 | 本 UC 可证实的约束 | 未决定/后续 |
|---|---|---|---|---|
| 对象授权（服务端强制） | Coordinator、User、ScholarAuthorization | 无授权者/他人员/同名另一档案/超范围直接调用接口 | 每次受保护写入与每次审核决定都重新校验；拒绝无副作用并留痕 | 授权范围粒度（B-05）；并列管理者（B-04） |
| 目标一致性守卫 | Coordinator、Scholar、ScholarAuthorization | 授权目标与写入目标不一致 | 授权所指 Scholar 必须就是被写档案 | 对象改名/合并后的引用稳定性留 R5 |
| 字段范围隔离 | Coordinator、Scholar | Scholar 事实与普通主页字段混写 | 普通 `UserProfile` 字段不写、转 UC-22；只写授权范围内 Scholar 事实 | 字段清单（B-02）；混合提交（B-06） |
| 审核后生效 | Coordinator、ScholarChangeRequest、Scholar | 待审内容提前公开 | 待审登记时公开版保持旧值；只有通过才生成生效版本 | 需审核字段口径（B-01）；并存/并发（B-09） |
| 待审可见性 | ScholarChangeRequest、UI | 待审状态与审核材料泄漏 | 提交者本人可查本人待审状态；他人不可读 | 材料最低集合（B-07）；保留/脱敏（D-09） |
| 原值与规范值分离 | Scholar | 人工维护覆盖来源原值 | 原始来源事实不被覆盖，公开规范值与之独立 | 来源侧更新规则属 FR09/FR10 |

## 11. 与其他 UC 的边界

- **UC-05/UC-06**：认领申请与认领审核是授权的唯一来源；本 UC 只读授权（有效性与范围），不创建、不转移、不撤销。
- **UC-22**：普通 `UserProfile` 字段由本人编辑；本 UC 不写普通字段（A4 只转交）。
- **UC-03**：公开读取与展示（含“待审不展示”的读侧）在 UC-03；本 UC 只保证写侧与可见范围。
- **UC-08**：成果归属确认/纠错、Authorship 状态变化在 UC-08；本 UC 不确认、不解除、不提升任何参与关系。
- **UC-09/UC-10**：身份消歧与归并治理不在本 UC；本 UC 不改别名与合并状态。
- **UC-17**：审计查询、待办队列与争议结案在 UC-17；本 UC 只写入审计与待审状态。
- **UC-01/02/03/11**：检索/详情/门户/统计读取生效版本的路径由消费方实现；本 UC 只产出生效版本并声明一致性要求。
