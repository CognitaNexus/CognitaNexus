# ADR-004：引用文本由服务端生成

- 状态：**Accepted（2026-10-18，产品负责人授权「按专业学术平台标准补齐功能」直接实施；实现记录见 §7）**
- 日期：2026-10-18
- 触发来源：详情页原有的引用面板在**前端**渲染四种格式（`frontend/src/composables/useCitation.ts`），
  上线可用但在真实数据上被查出四个缺陷（§1.1）；同时后端已握有前端看不到的三类事实
- 影响面：`core-service` 新增 `catalog/domain/CitationFormat|CitationAuthor|CitationSubject|Citation`
  `Formatter`、`catalog/application/CatalogCitationService|CitationBundle`、
  `catalog/api/PublicCitationController`；`catalog/application/PublicCatalogQueryService` 抽出
  `requirePublicTarget`；前端引用面板改为纯展示

## 1. 问题

引用是这个平台的核心出口。读者来是为了「找到文献、拿去用」，而一段引用只要错一个作者顺序、
一个年份或一个 DOI，引用就作废，且错误会被带出平台、再也看不到本平台的任何标注。

原实现在前端拼接文本，看起来是「不依赖后端的独立能力」，实际暴露出四个只有真实数据才会触发的缺陷：

### 1.1 被修掉的四个缺陷（均为实测复现，不是推测）

| # | 缺陷 | 后果 | 复现条件 |
| --- | --- | --- | --- |
| 1 | BibTeX 只转义 `\` 与 `{}`，未转义 `%` | `%` 在 BibTeX 里是**注释起始符**，题名或刊名里出现一个 `%`，其后的整段（含 `}`）被吃掉，编译时条目字段残缺 | 题名含 `%`（中文期刊摘要题名里并不罕见） |
| 2 | 无作者时 `note` 字段被写两次（先写「作者不详」，末尾再写出处） | 同一 entry 出现重复键，BibTeX 取最后一个且不报错，占位说明被静默丢弃 | 成果未登记任何署名者 |
| 3 | 引用键取「第一作者名的最后一个空格段」 | 中文名取到的是「三」、`Zhang San` 取到的是 `San`；同一作者可能得到不同键，不同作者可能撞成同键 | 中文姓名，或姓在前的英文名 |
| 4 | 作者列表只取「关系合格」的学者（`qualifiedForGraph()`） | 待核验／争议的署名者被**从引用里删掉**。署名是元数据事实，关系状态回答的是「这位学者是否被正确匹配」，两件事被混成一件 | 成果有 `PENDING_VERIFY` 参与关系 |

第 3 条当时还被写进了前端测试（`assert.ok(text.startsWith('@article{Shiping202434ef56,'))`），
注释写着「按实现的实际行为断言，防止未来静默改变格式」——测试把缺陷固化成了预期。这是本轮最值得
记录的一点：**测试只证明「代码没变」，不证明「行为是对的」**。

### 1.2 前端结构上看不到的三类事实

即便把上面四条逐一修好，前端仍然做不对，因为它手里没有这些数据：

1. **被治理排除的参与关系**（`relation_state = EXCLUDED`）：前端拿到的 contributors 已经过一遍
   过滤，不知道自己少了几个人，也就无法告警。
2. **署名顺序缺失**（`author_order IS NULL`）：前端看到的顺序是列表顺序，无法区分「这是真实署名序」
   与「这是数据库返回顺序」。
3. **当前生效的诚信声明**（撤稿／更正／关注）：详情接口会返回，但引用文本要在**同一时刻**与它一致；
   前端两次请求之间成果被撤稿，就会出现「文本说没事、面板说已撤稿」。

## 2. 决策

**引用文本、告警、引用键全部由 `core-service` 生成；前端只展示、复制、下载。**

具体约束：

1. **格式化器是纯函数**（`CitationFormatter`）：给定同一份事实，输出字节必须一致，不读时间、
   不读环境、不查库。引用文本会被贴进论文、被脚本解析、被别的平台转载，它随环境漂移就是无法复现的问题。
2. **四种格式一次给全**（`GET /api/v1/public/achievements/{id}/citations`）。按标签页逐次请求会让
   每个标签页闪一次加载态，且两次请求之间成果状态可能变化，读者会在同一屏看到两种结论。
3. **告警分两层**：`warnings`（元数据层面：缺年份、署名顺序未知、已被撤稿、模拟数据）与
   `formats[].warnings`（格式层面：APA 要求拆姓名而平台不拆）。分开是因为把「APA 的简化」提到顶层，
   会让人误以为国标与 BibTeX 也不可靠。
4. **撤稿不下架在此处同样成立**：撤稿成果仍给出引用文本（它确实发表过，引用过它的人需要能查回去），
   但文本与告警都带上撤稿事实。
5. **出处与生成时刻不进文本**：作为 `provenance` / `exportedOn` 字段单独返回。引用文本会被粘进
   参考文献表，任何非书目信息都会跟着进那张表。
6. **公开资格判定复用** `PublicCatalogQueryService#requirePublicTarget`，不另写一份。这套判定里有两个
   出过问题的点——重定向必须跳到链终点、资格必须作用在终点实体上；两处各写一份，修好一处漏掉另一处
   就是一条公开读的旁路。
7. **下载入口手工写响应**（`void` + `response.getWriter()`），不返回 `ResponseEntity`。理由与
   C-10 同源：一旦让 Spring 按 `Accept` 选转换器，业务拒绝时错误处理会命中「无可用转换器」→ 406 →
   ERROR 派发 → 认证过滤器不处理 ERROR 派发 → 客户端看到与真实原因无关的状态码。

### 2.8 集合文件：同一文件内引用键必须唯一

单条下载不存在这个问题，批量导出一定遇到：BibTeX 遇到两个同名条目**不报错**，而是让后一条静默
覆盖前一条——文件能编译、参考文献表少一条。因此：

- 键的分配是**纯函数**（`CitationCollectionFormatter#uniqueCiteKeys`）：第一次出现的键保持原样，
  之后的重复键依次追加 `a`、`b`……（超过 26 个用 `aa`、`ab`）。不改第一个键，是因为读者可能已经在
  自己的 .bib 里用过它，改它等于让引用悬空。
- 后缀只由出现顺序决定，不掺随机数或时间戳：同一批输入必须得到同一份文件，否则同一检索结果导两次，
  两次的键不同，读者库里会积出重复条目。
- 改过键就回一条**文件级告警** `CITE_KEY_DISAMBIGUATED`，并真的把新键写进条目。悄悄改键比撞键更糟：
  读者按旧键去 .bib 里找会找不到。
- 编号（国标的 `[1]`）不算进条目文本：编号属于「这份文件里的第几条」，由装配时统一加，条目本身
  与单条导出逐字一致。这条约束是可验证的——自检脚本逐条比对批量条目与单条端点。

### 2.9 批量入口的两处「少给」都必须说出来

- **单条不可公开不拖垮整批**：选中列表来自检索结果，从看到结果到点导出之间，其中一条可能刚好被下架
  或并入别处。整批 500 会让读者丢掉其余 19 条；悄悄少给一条等于平台无声地改动读者的选择。因此逐条
  判定、跳过并报数。
- **跳过原因只写一个码** `NOT_AVAILABLE`：区分「不存在」与「不可公开」就是给受限内容留一条探测通道，
  与单条端点统一返回 404 的口径一致。自检脚本断言两条被跳过项的说明文本完全相同。
- **一条都导不出来时 404**，不交空文件：一份空 .bib 更容易被误当成「导出成功」。
- 上限 100 条**显式拒绝**（422）而不是截断。截断的失败是静默的；而这个规模更可能是想把整个检索结果
  倒成一份文件，那件事应当走 CSV 导出。


## 3. 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 保留前端渲染，把三类事实一起塞进详情接口 | 每个新格式字段都要改详情契约；且「渲染规则」与「展示」仍混在一处，下一次加格式还要动前端构建。更关键的是测试仍只能测前端那份实现，无法用真实库夹具验证。 |
| 前端渲染 + 服务端只给「告警」 | 告警与文本由两处生成，必然漂移：例如服务端说「署名顺序未知」，前端却已按姓名排好序，读者会以为那个顺序是真的。 |
| 只提供 BibTeX/RIS，砍掉国标与 APA | 中文投稿与学位论文用的是国标。只给机读格式等于告诉占多数的读者「你自己拼」。 |
| 引用文本里嵌入平台标识与导出日期（原前端做法） | 会随每篇引用进入参考文献表；同一篇文献被两个人在不同日期引用会得到两段不同的 .bib。可追溯性应通过 API 字段与界面说明实现，不通过污染书目数据实现。 |

## 4. 后果

- 引用规则只有一处实现，`CitationFormatter` 17 项单元测试可以逐字断言标点、分隔符与转义结果——
  这是前端实现拿不到的可测性（前端测试跑在 node:test 里，没有真实库夹具）。
- 前端 `useCitation.ts` 从「四种格式的渲染器」缩成「状态装配」，`citationView.ts` 只剩三个纯函数
  （下载前缀、告警严重度、格式回退），6 项测试覆盖。
- 代价：引用面板多一次请求，且这个请求失败时面板独立降级（页面其余部分不受影响）。
- 新增能力：告警。此前读者拿到一段缺年份、缺刊名、已撤稿的引用，界面上没有任何提示。

## 5. 未做的事

1. 卷、期、页码不采集，因此四种格式里都不会出现这三项。这是「不知道」，不是「没有」，导出文本中
   也不填占位值。
2. 没有浏览器级 E2E：标签页切换、剪贴板复制、下载三件事只有接口与纯函数据验证；`navigator.clipboard`
   在非 HTTPS 页面的降级文案未实测。
3. 引用键对纯中文名回退为 `anon`，不生成拼音。拼音需要一份词典，猜错会把两位作者折叠成同一个键。
4. ~~批量导出（检索结果集 → 一个 .bib 文件）未做~~：已在第八批实现，决策见 §2.8 与 §2.9。

## 6. 替代关系说明

本 ADR 与 ADR-003（站内通知）无关，不改变任何已有口径。它只把「引用文本」这一件事的归属从
前端移到服务端，属于实现分工调整，不改变 FR02 的承诺范围。
