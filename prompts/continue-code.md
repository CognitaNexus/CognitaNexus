# 模板：代码续写

| 项目 | 内容 |
| --- | --- |
| 版本 | V0.2，2026-10-17 |
| 任务类型 | 代码续写（在既有文件、既有约定内补全一段逻辑） |
| 适用 | 已有明确的相邻实现与命名约定，只差把这一段按同样形状写出来 |

## 模板正文

```text
任务：在 <文件路径:行号> 之后续写 <方法/分支/字段>。
必须遵守的既有约定（从相邻代码读出来的，不是推测的）：
  - 命名：<示例，含相邻的同类标识>
  - 注释口径：<本仓库注释写「为什么」，不写「做了什么」；关键判断要写出踩过的坑>
  - 错误处理：<抛业务异常还是返回 Optional；错误码取哪一个>
  - 事务/幂等：<该方法是否在事务内；重复调用返回什么>
输入输出：<签名、返回类型、判空约定>
验收：<应当出现的行为；至少一个反例>
禁止：顺手改相邻代码、重排无关 import、改动接口签名。
```

## 硬性要求

1. **只续写，不重构**。续写任务里改到范围外的代码，评审时无法区分「必要修改」与「顺手改」，会让整段改动失去可核对性。
2. **约定来自相邻代码，不来自想象**。空白文件没有约定可循时，停下来问，不要自造一套。
3. **注释写「为什么」**。本仓库的注释密度高，是因为每个不显然的判断背后都有一次真实踩坑；只重复代码内容的注释会被要求删掉。
4. 续写完成后必须能通过 `spotless:check`（缩进、折行由格式化工具裁决，不手写对齐）。

## 禁止项

- 引入新的依赖或工具类来「顺便优化」。
- 把相邻的 if/for 一并改写。
- 复制粘贴一段相似逻辑而不抽出其实已经重复的部分（本仓库对重复代码的容忍度低于对长方法的容忍度）。
