# 模板：代码解释

| 项目 | 内容 |
| --- | --- |
| 版本 | V0.1，2026-10-16 |
| 任务类型 | 代码解释（读懂既有实现，供人工判断与文档引用） |
| 适用 | 接手一段不是自己写的实现；或需要把实现口徑与文档对照 |

## 模板正文

```text
请解释 <文件路径:行号范围> 在做什么，按下面的顺序回答：
1. 这段代码解决的是什么问题（一句话），以及不这么做会怎样；
2. 输入与输出：参数取值从哪来、返回给谁用；
3. 关键分支与它们的判据（逐条列出条件与结果）；
4. 事务/幂等/并发上的保证与不保证；
5. 依赖：调用了哪些其他模块或表；
6. 明确说出你不确定的部分，不要猜。

约束：只解释给定范围，不做改进建议，不改代码。引用行号以便核对。
```

## 硬性要求

1. **不确定必须说不确定**。解释出错不会报错，只会让后续判断建立在错的模型上。宁可写「这一段我没看明白，需要看 X」。
2. **引用行号**，让人能一键核对。
3. **区分「它做了什么」与「它想做什么」**。注释里写的意图与代码实际行为不一致时，以代码为准并指出来。
4. 不把解释当作验收证据：解释得清楚不代表代码正确。

## 为什么需要这条模板

本仓库若干次真实偏差都发生在「读错了字段含义」上，而不是「写错了逻辑」：例如把「参与关系条数」读成「学者人数」，页面上不会报错，只会把「有 3 条参与关系」画成「暂无参与关系记录」。因此解释任务要求逐条给出判据与取值来源。
