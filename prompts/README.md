# 提示词资产（prompt 即源码）

本目录把用于开发的提示词与规范模板纳入版本管理。它们与代码同等对待：有版本号、有明确的用途与输入输出、改动要有理由。

## 为什么放在仓库里

1. 提示词决定了产出的形状。只把代码纳入版本管理，等于把「一半的实现依据」放在仓库之外——换个人、换台机器，得到的东西就不一样。
2. 提示词会被迭代。哪一版好用、改了哪一句之后失效，只有存下来才说得清。
3. 评审要能看到「当初是怎么让 AI 干的」。评审的对象不只是最终代码，还有产生代码的过程。

## 修改约定

1. 模板的结构性改动（增删章节）必须升版本号；只改措辞、例子不改结构的，在原版本内更新并记入「修订」小节。
2. 每条模板都必须写明**验收判据**与**禁止项**。没有这两项时，AI 会把「写完」当成「做完」。
3. 模板中出现的路径、命令、编号必须是本仓库真实存在的；模板不复制需求正文（需求在需求仓库维护）。
4. 模板给出的上下文清单是上限而不是下限：单次任务只喂与本任务相关的部分，喂多了会分心（见[工程协作与 AI 协作规范](../docs/standards/工程协作与AI协作规范.md) §1）。
