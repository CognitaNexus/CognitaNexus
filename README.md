# CognitaNexus 学术成果分享平台（工程实现仓库）

以学者为中心的学术成果聚合、共享与管理平台，覆盖论文、专利、科研项目、获奖四类成果。

本仓库是**工程实现仓库**，承载架构设计、编码规范与后续的应用代码。需求基线、SRS、核心 SPEC 与 UML 图源仍维护在独立的**需求仓库**中，本仓库不复制、不改写需求语义。

## 规划中的仓库结构

下列结构由架构设计确定，随各阶段授权逐步填充；**未获授权的目录不预建、不占位**。

```text
academicplatform/
├── README.md
├── AGENTS.md
├── compose.yaml            # 本地一键起全栈（PostgreSQL + 后端 + 前端）
├── .env.example            # 配置样例，仅变量名，不含真实密钥
├── backend/                # Spring Boot 单体工程，按业务模块分包
├── frontend/               # Vue 3 + TypeScript + Vite
├── db/migration/           # Flyway 版本化迁移脚本
├── ops/                    # 本地运维脚本：备份恢复、健康检查
├── tests/perf/             # 性能测试脚本与固定查询集
└── docs/
    ├── README.md
    ├── architecture/       # 架构设计说明书与 ADR
    └── standards/          # 编码规范、协作规范
```

## 环境前置

本机需具备 JDK 17 或以上、Node.js 20+、Docker 及 Compose 插件。当前仓库尚未提供构建脚本与镜像定义，构件设计阶段补齐；在补齐之前无法通过本仓库启动任何服务。

## 贡献流程

1. 从 main 切出分支，命名与提交信息遵循 docs/standards 下的协作规范。
2. 变更必须关联 FR / AC-IMPL 编号，并在 PR 描述中说明验证方式与未验证项。
3. 禁止直接向 main 推送、禁止强制推送、禁止提交密钥与本地数据文件。
4. 文档类变更至少 1 人评审；涉及业务语义的变更须回到需求仓库走联合评审。
